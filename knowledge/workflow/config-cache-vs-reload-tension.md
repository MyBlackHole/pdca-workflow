# 上下文缓存与热重载的张力：配置系统失效模式

## 根因链模式

「解析一次存字段」的进程上下文化优化（性能动机）与「配置热重载」（运维动机）存在**根性张力**：缓存即快照、快照即过时。失效的典型三层断裂：

```
constructor 隐式单次加载（无刷新入口）
    → 进程上下文字段缓存定格启动快照
        → 热重载只修"可见面"（ini 直连字段），缓存字段与其数据源双双遗漏
            → 裁定意图与实现行为分离，且无测试覆盖 reload 断言
```

实证：rpc RELOAD_CONFIG_CMD 三层断裂 + auth_enabled 死字段（T3977）。

## 检查清单（评审配置系统时逐项过）

1. store/缓存有无**显式 refresh 入口**？constructor 初始化 = 结构性只读一次
2. 缓存字段的**数据源**是否与缓存同步刷新？（本案例：字段重算了，store 却是旧的）
3. 发布顺序：双缓冲切换是否**先写完再发布**？（先发布后回写=数据竞争 UB）
4. 双缓冲槽位数 ≥2 时读者宽限如何保证？（慢读者跨两次写即撕裂）
5. 配置键是否有**单一注册表**？（键名散落宏/MATCH 字符串/调用实参三处 = 不可发现、不可维护）
6. show/查询接口覆盖度 vs 实际键集差距？
7. 安全开关的热切换方向限制（fail-closed：允许升级 0→1，降级 1→0 应受限或需重启）
