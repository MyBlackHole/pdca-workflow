# Git 提交分析：指纹锁定与确定性统计口径

## 洞察

对"最后一个提交"这类 git 历史分析任务，存在两个导致结论漂移的陷阱：

1. **目标漂移**：分析执行期间提交可能被 amend 重写（本例 T0386 中 `0e2d8c35` → `dbc20b5e`，标题/父链不变但文件数 4121→4123）。症状是同一命令多次运行结果不一致——先怀疑工具非确定性，实际应先核对 `git rev-parse HEAD` 指纹。
2. **口径波动**：`git show --numstat` 默认 rename 检测受资源预算影响，大 diff 下可能产生不稳定计数。统一使用 `--no-renames` 可获得完全确定性的统计。

## 复用规则

- 分析类任务的 PRD 应声明**目标指纹锁定**验收前提（如"结论仅适用于 commit <hash>；若 HEAD 变化需按参考资料重跑复核"）。
- 规模统计一律 `git show <ref> --numstat --no-renames`，报告注明口径。
- 报告参考资料节附 HEAD 指纹预检命令，使读者可自检结论是否仍适用。
