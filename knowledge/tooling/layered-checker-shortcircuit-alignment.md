# 顺序短路型检查器的失配分层与全量对齐法

来源：T0343 检查基建对齐（2026-08-22，26 limit + 25 锚点 + 克隆提取）

## 1. 洋葱式失配：首条规则掩盖全部深层问题

`set -e` + 遇错即停的检查脚本，若**第一条规则自仓库初始提交就失配**，则其后所有规则从未被执行过——包括那些本身写错的规则。症状：某次"小修复"后突然冒出成批新失败。

**正确预估方法**：先做跳过模式全量探测——临时把所有 `exit 1` 替换为继续执行，收集完整违规清单再评估工作量。逐条修逐条撞会严重低估。

## 2. grep 锚点错位的三种形态与严格校验

以"函数签名首行"为锚点的行数规则，format 化后锚点断裂。自动重锚必须双校验：
1. **同名**：从旧 pattern 提取的函数名必须与新行完全一致（防相近名误锚，如 reg_on_frame ≠ native_on_frame）
2. **顶格定义**：候选行列首无缩进且非分号结尾（排除前向声明 `static void f(...);` 与调用点）

反例教训：宽松匹配曾把锚点改到前向声明（start=324）导致段长算出 1889 行、limit 被抬到 1990 的荒谬值。

## 3. 条件行与消息行数字漂移是历史失配信号

`if (( x > 40 ))` 与消息 `(limit 50)` 数字不一致 = 该规则曾被单独手改过。统一校正时两处一起归一。

## 4. 禁令型 grep 不是失配

校验脚本批量验证锚点时，区分正向存在性断言（命中>0 才过）与禁令断言（命中=0 才过）。把禁令的"零命中"当失配去"修"会破坏治理。

## 5. 构建系统版本注入必须显式进依赖图

`CXXFLAGS += -DVERSION=\"$(shell cat VERSION)\"` 不使 .o 依赖 VERSION 文件——增量构建下版本宏静默过期，二进制版本不一致。修复：全部对象规则追加 VERSION 前置 + CMake `CMAKE_CONFIGURE_DEPENDS`。注意 dry-run 类测试脚本在非 repo 根 cwd 执行时相对路径 VERSION 会失效，需 `cd $ROOT` 包裹。

## 适用边界
适用于任何"遇错即停"的多规则检查体系（lint 脚本、CI gate）；不适用于可并行报告全部违规的聚合型 linter。
