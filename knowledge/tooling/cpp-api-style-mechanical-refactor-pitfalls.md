# C/C++ 大规模 API 风格迁移的机械重构陷阱

来源：T0341 移除异常处理 + C 风格化调用（2026-08-22，198 文件 +1289/−1876）

## 1. 批量正则替换的三个经典陷阱（Python re 实战）

### 陷阱 A：捕获组包含待删除文本 → "替换成功"但内容未变
```python
pat = re.compile(r'(^|[^:a-zA-Z0-9_>])(::[a-zA-Z_]\w*\()')
t2 = pat.subn(r"\1\2", t)   # 错：\2 含完整 "::xxx("，替换等于原文
```
- 症状：subn 报告替换了 N 处、文件写回成功，但 grep 残留不变；若外层套 `while` 循环会**死循环超时**
- 正解：把待删除的 `::` 留在捕获组外——`r'(^|[^:a-zA-Z0-9_>])::([a-zA-Z_]\w*\()'` → `r"\1\2"`
- 防御：批量替换后必须用独立工具（rg/grep）复核残留，不能只信脚本计数

### 陷阱 B：POSIX 字符类在 Python 不支持
- `[[:alnum:]]` 在 Python re 中被解析为嵌套字符集（触发 FutureWarning 且语义错误）
- Python 侧用 `[a-zA-Z0-9_]` 显式展开；grep/rg 侧可继续用 POSIX 类

### 陷阱 C：负向前缀字符集必须含 `>`
- 去除 `::func(` 的全局限定符时，`std::numeric_limits<size_t>::max()` 的 `>::max(` 会被命中并破坏为 `>max()`
- 正确前缀排除集：`[^:a-zA-Z0-9_>]`（冒号防 `std::`、字母数字下划线防成员访问、`>` 防模板闭合）

## 2. 去 `::` 前缀必然暴露同名遮蔽变量

显式全局限定 `::open(...)` 常被用于绕过局部变量遮蔽。批量去前缀后这些调用点会解析到**同名的局部变量/参数**，报出费解的错误（如 `(bs::BinWriter)(const char*, int) 无匹配`——变量名 open 被当函数式转换）。

处置：
1. 先编译，从第一个错误定位遮蔽模式
2. 全量扫描声明形态：`\b(type)\s+(open|read|...)\s*(;|=|\))`
3. 仅重命名声明行与成员调用引用，字符串字面量与真正的 libc 调用不动

## 3. 存量失败甄别法：git stash 对照

大规模重构后测试失败时，先判定"存量还是引入"再动手修：
```bash
git stash && <复跑失败测试>; git stash pop && <重建>
```
- HEAD 也失败 → 存量问题，记录到结论的"下一轮建议"，不扩当前范围
- 仅工作区失败 → 本任务引入，必须修复
- 本次实践：120 项 ctest 中 3 项失败经此法全部甄别为存量，避免范围蔓延

## 4. 重构任务的 TDD 变体：规则先行

纯机械重构没有行为测试可写，红→绿循环映射为：先在静态检查脚本写入目标风格禁令（此刻必红）→ 实施迁移至绿 → 规则留作永久防回归。检查规则本身就是本次的"测试产物"。

## 适用边界

- 适用于 C/C++ 源码树的 API 风格统一、命名空间拆除等机械迁移
- 不适用于改变运行时行为的重构（那需要行为测试先行）
- 符号全局化后的撞名安全性依赖模块前缀命名惯例，需 nm 抽查 + 全量链接验证兜底
