# 证书布局切换以"套"为单位，禁止单文件混搭

## 洞察

T0388 中 ED25519 证书名回退最初沿用历史实现的**逐文件独立判定**（CA/证书/私钥各自检查存在性各自回退），用户纠正为**整套语义**：默认整套使用 `ed25519_` 前缀名；当前缀 CA 缺失时，整套下沉到同目录无前缀名（ca.crt/host.crt/host.key）。

逐文件回退的隐患是产生**混搭布局**（如信任前缀 CA 却加载无前缀主机证书）——文件都存在时静默成功，但与部署目录的真实意图背离；且混搭状态下"哪套是权威布局"无从审计。

## 复用规则

1. 同一组件的多文件组（CA/证书/私钥、数据/索引/日志）做格式或命名切换时，回退/迁移决策必须以**组为单位**单点判定，禁止逐文件独立选择。
2. 整套判定的锚点选**必选且唯一**的成员（本例为 CA 文件存在性）；锚缺失且备选套也不完整时保持原路径 fail-closed。
3. 判定点收敛为一个函数（`tls_cert_pick_ed25519_set`），消费方一次调用拿到整套路径，杜绝调用方自行拼装。
4. 客户端布局语义（SM2 仅前缀子目录 / ED25519 整套二选一 / Go oss 根+前缀）已在 rdb-config.h 注释留痕，新增消费方先读注释对齐。

## 追加（T0390）：多 profile 加载的降级粒度

服务端多算法 profile（SM4+AES）初始化必须"尽力收集"：单算法失败跳过并记日志，仅当全部失败才整体降级（plain only）。全有或全无会让一个次要算法的数据问题连坐主用算法——T0390 中无效的 ED25519 链曾禁用国密。实现注意：失败槽位需 memset 回滚（保持直接写目标槽的调用形态，勿引入中转缓冲改变行为）。

## 追加（T0391）：现网部署规范基线

服务端 cert_dir 根：`sm2_ca.{crt,key} + sm2_host.{crt,key} + ed25519_ca.{crt,key} + ed25519_host.{crt,key}`；客户端信任子目录 `<ca_cn>/` 三件套由 `tls-keygen sign -n <ca_cn>` 自动生成（含 CA 拷贝）。CA 命名建议 My_SM2_Root_CA / My_ED25519_Root_CA（无空格，符合 cn_name_valid）。混合算法 CA 内容互拷会导致协商下发错误 ca_cn（T0388 遗留②根因）。
