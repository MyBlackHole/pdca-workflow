# 服务启动期致命错误必须显式输出到控制台

## 适用场景
任何长驻进程（CLI server / daemon）启动期的致命失败：证书缺失 fail-closed、特权端口绑定被拒、配置解析失败等。

## 结论
- 启动期致命错误**不能只写日志文件**：日志一旦被重定向到文件，运维在终端只看到"启动异常"或进程静默退出/挂起，无法诊断。
- 应在返回 error / 退出前，把错误同时写到 **stderr（控制台）** 与日志（双写），并附**可操作提示**（缺哪个文件、怎么生成、改用哪个端口）。
- 监听错误若发生在 goroutine 内，主流程不能只 `log` 后继续阻塞等待信号——否则进程**永久挂起**；应明确非零退出。
- 用户可见文案（控制台/help）与现有工具风格一致：本仓库 CLI 报错用英文（与 tls-keygen 一致），不用中文。

## 限制
- 仅针对"启动期致命错误"的可见性；不改变 fail-closed 策略、算法/密码套件选择等业务语义。
- 不引入自动生成证书之类的功能增量。
