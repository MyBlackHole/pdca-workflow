# 原生派发契约 v4

TASK/CAP/CONFIRM/SCHED 是正式 PDCA 任务的依据。父 Agent 不监控生命周期、不指挥阶段、不代答；
宿主原生机制维持消息和资源。每阶段启动仍由用户决定。

## 适用范围

本契约只适用于**正式工作节点/场景任务的 Agent**。
当前 Do 内的 Do-only Work Unit 不是正式任务；即使 Work Unit 被委派给隔离执行者，
也遵循 [CONTRACT-01](../concept/pdca-execution-contract.md)，不创建 task/attempt，
不要求该执行者运行 Plan/Check/Act。

如果 Work Unit 暴露了新的独立职责、可独立拒收成果或新的授权边界，
当前 Do 停止扩张，按 [DECOMP-01](../concept/task-decomposition.md)生成正式节点候选；
只有用户批准创建后才进入本契约。

独立验证包只检查有限记录关系，不创建 Agent、不认证宿主、不证明隔离。
现场验收状态 NOT_RUN；不要把离线合成控制通过称运行验收通过。

## 用户显式启动的独立任务派发

### 职责

用户决定创建哪些具名节点/场景任务；就绪性只是可启动条件，不是派发指令。
入口/宿主提供原生创建和无损消息路由，父 Agent **不轮询监工、不推进阶段、不代写结果**。
一次明确操作可创建若干已经定义的任务；各自仍需先展示 Plan 目标，并等待自己的 Plan
`phase_start`。

### 新建

固定 task_id、work/node/scene/attempt、项目与规则版本、父 seed/输入、输出目录、
任务书和唯一 dispatch_request_id。使用真实新 Agent/会话，不用同一主上下文换角色；
只传明确任务材料和公共规则，不导入父/兄弟完整活动历史。

派发前集中登记并取得本任务记录区/控制区实际写权。创建结果 unknown 时继续保留可能占用，
只对账原请求，不能新建另一个任务绕过。取得原生创建回执及实际身份，关联
[dispatch](record-shapes/dispatch.md)。

正式任务必须可与用户交互、等待后继续原实例、写自己的记录区。派发消息明确：
**先向用户说明本任务 Plan 目标，等待阶段启动；不要直接跑完四阶段。**

没有可交互/可恢复能力，保持 blocked_unexecuted；可输出非正式分析，
但不能冒称正式节点已执行。

### 四条路径

| 路径 | 处理 |
|---|---|
| 新建获准 | 原生创建一次，固定回执、身份与输入；新 Agent 展示 Plan 目标后等待 |
| 继续原任务 | 定位原实例，投递真实用户消息；核对身份、状态与权限连续性 |
| 创建结果 unknown | 保留原请求与可能占用；只对账，不重新创建、不分配新 attempt 绕过 |
| 恢复失败/返回新实例 | 阻断；新实例不接管，停止未获权动作并记录副作用 |

父 Agent 不保持等待循环或后台监控。任务完成/请求确认由宿主事件或用户主动打开会话呈现；
没有事件推送时明确限制，不伪造后台持续运行。一个任务等待不阻塞其他已获准任务。

### 结果消费

只从固定交付、原生消息与事件读取结果。task_id/会话/attempt 不匹配的迟到返回
不覆盖当前任务。停止和资源结清由真实拥有者处理；文字 completed 不自动释放写权。
全中心 records/resources 仍按实际对象判断跨项目冲突。

按需看[原生能力说明](../concept/capability-protocol.md)；它不是运行兼容保证。
