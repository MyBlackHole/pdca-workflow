# 原生派发契约 v4

TASK/CAP/CONFIRM/SCHED是本版依据；按本契约新建、继续、处理未知和恢复失败。父Agent不监控生命周期、不指挥阶段、不代答，宿主原生机制维持消息和资源。

任务开始前真实新Agent、独立输入、用户双向交互和原会话继续均可用，才具备正式资格。每阶段启动仍由用户决定。引用原生回执，不认证自述或同名角色。

独立验证包只检查有限记录关系，不创建Agent、不认证宿主、不证明隔离。现场验收状态NOT_RUN；不要把离线合成控制通过称运行验收通过。

## 用户显式启动的独立任务派发

### 职责

用户决定创建哪些具名节点／场景任务；就绪性只是可启动条件，不是派发指令。入口／宿主提供原生创建和无损消息路由，父 Agent 不轮询监工、不推进阶段、不代写子任务结果。一次明确操作可创建若干已定义任务；各自仍需 Plan 目标确认。

### 新建

固定 task_id、work/node/scene/attempt、项目与规则版本、父 seed／输入、输出目录、任务书和唯一 dispatch_request_id。观察宿主支持的创建接口及不继承历史语义；使用真实新 Agent／会话，不用同一主上下文换角色。仅传明确任务材料和公共规则，不导入父／兄弟完整历史。

派发前先集中登记并取得本任务记录区／控制区的实际写权；创建结果未知继续保留占用，不能再建一个任务绕过。取得原生创建回执及实际身份，关联 [dispatch](record-shapes/dispatch.md)。确认子 Agent 可与用户交互、等待后继续原实例、可写自己的记录区。派发消息必须写明：**先向用户说明本任务 Plan 目标，等待阶段启动；不要直接跑完四阶段。**

没有可交互／可恢复能力，保持 blocked_unexecuted；可输出非正式分析但不能冒称节点执行。独立不要求不同模型或永久进程，要求独立会话实例及受控输入。

### 四条路径

| 路径 | 处理 |
|---|---|
| 新建获准 | 原生创建一次，固定回执、身份与输入；新 Agent 进行目标沟通 |
| 继续原任务 | 定位原实例，投递本次用户消息；核对返回身份、状态与权限连续性；当前阶段没有授权仍等待 |
| 创建结果未知 | 保留原请求与可能占用；只对账原请求，不重新创建、不分配新 attempt绕过 |
| 恢复失败／返回新实例 | 阻断；新实例不接管，停止其未获权动作并记录副作用；同 ID 丢失原状态也不算恢复 |

父 Agent 不需要保持等待循环或后台监控。子任务完成／请求确认由宿主事件或用户主动打开会话呈现；没有事件推送时明确交互限制，不伪造后台持续运行。单任务等待只暂停自己，不串行阻塞无关获准任务。

### 结果消费

只从固定交付、原生消息与事件读取结果。task_id／会话／attempt 不匹配的迟到返回不覆盖当前任务。停止和资源结清由真实拥有者处理；文字 completed 不自动释放写权。全中心records/resources统一判断跨项目实际对象冲突；账本与后端取得/撤销/结清证据都要匹配。

按需看 [原生能力说明](../concept/capability-protocol.md)，它不是运行兼容保证。环境能力证据可按适用版本复用，本次创建／继续的回执不可省略。
