# 取消、接管和依赖修复的完整返工演练

本文件是教学计划，不含真实成功记录。fixture操作仅在授权隔离对象上执行，expected在实施前固定。

## 演练A：Check替代旧尝试，不绕过授权

前置：B1实现任务T-old到Check，已发现RANGE-N03失败；B/R尚未取得新交付。固定旧suite/run/artifact及失败日志。

1. 用户只说“要修复”但尚未认可原Check时，先记录后继建议；不能自签取消。用户明确“取消旧尝试，另开修复任务”时分开记录取消来源与新任务授权范围。
2. 对T-old发stop_requested；旧Agent不再写实现/阶段，control/runtime先限制准入。查询OP-old是否仍在途；unknown保持资源retained，不能先启动T-new。
3. 对账确认没有剩余副作用，或可靠隔离旧资源且新任务完全不相交；宿主撤销旧访问/记录写权，生成termination。保留phase=check、execution_state=interrupted，四条正常边只保留实际已完成的1、2。
4. 槽释放且新派发授权明确后，T-new取得新attempt与全新Agent，导入旧失败的固定材料而非旧对话。新Plan固定原目标、缺陷复现和回归预算，取得自己的确认。
5. 先证明旧实现复现失败，再验证修复。B1最终版本重跑全必需套件和R20相关控制，完成完整PDCA；本地可交付但工作缺陷仍开放。
6. B和R各自新完整组合任务使用新B1，旧组合/审查证据stale。独立新Agent审查通过后工作缺陷才能关闭，整树发布另判。

反例：直接将T-old设archive；只撤销本地Agent不查远端OP；迟到旧Check确认授权新Plan；为复用上下文让旧Agent换名字；孩子先等祖先才交付。任一被观察到都不关闭缺陷。

## 演练B：超时与确认的两条事件次序

固定deadline=100（宿主测试计时域），响应提交99/到期100应consumed；到期100/响应101应expired。取消属于任务控制，consumed后仍可以停止；截止比较使用提交时刻严格小于，不看Agent自填sent_at。

注入LAST_EVENT_WINS错误控制：后一条事件覆盖终局，测试必须失败。修复后保留旧冲突证据，重新验证R03/R04/R05及R11/R13回执恢复。时钟域中断用blocked_clock，不能猜“迟到也算批准”。工作级tree_confirmation到期只保持未冻结，不取消已完成节点。

## 演练C：依赖图联合环与版本竞争

目标树仍是child属于parent，projection导出child→parent。注入显式输入parent→child产生混合环；两个子图各自无环不能通过。建模任务负责修改真正接口/输入边界，不靠宿主删除义务。

固定G1检查后发布候选G2：候选未授权时旧工作仍消费G1；若当前授权视图已换G2，则旧check不得派发。保存parent compare失败和完整循环路径，改正后重新检查全部场景顶点、跨场景屏障与资源获取顺序。

回归R14/R15/R16，再验证R06/R07资源与槽竞争；空本体depends_on图不能代替实例图。新冻结目标版本按既有TREE/SCENE规则逐节点覆盖，不绕开完整PDCA。

## 演练D：观测器和取消实现都有可能错

先用已知当前owner写成功与旧epoch写被拒的控制验证观测器；只看报告不看实际写入次数的观测器应被负控制识别。R13用真实临时文件保存seq2而快照seq1，对账后仅修复快照、OP计数不增长。这个局部模型实验不能被标成真实分布式撤权/断电恢复通过。

每个run保存输入、expected/actual、版本、后端事件、失败分类与清理结果。修复测试器不改变本体约束；修改判定语义需要新基线，不把旧失败重算成成功。
