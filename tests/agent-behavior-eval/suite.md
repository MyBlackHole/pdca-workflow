# Agent行为对照：与维护脚本测试分开

适用：修改Skill入口、阶段方法或恢复说明后，需要判断真实宿主行为是否改善。不作为业务任务的新门禁，不要求每节点运行，不授权自动创建Agent或改写业务对象。

## 固定对照

配套验证包保存3.4.8原始源码、3.4.9候选摘要、具名输入与独立判据。使用相同请求/输入、模型与工具权限配置；每个版本从独立会话和隔离测试目录开始。恢复用例在各版本内部先形成真实原会话，再压缩/继续；不能把另一个新会话叫作原Agent恢复。交替运行版本，并记录实际顺序和随机性配置；不从一次小样本外推总体效果。

`prepare_eval.py`只导出请求和原始材料，不导出判据。私有判据（评测答案）留在目标Agent无权读取的位置；验证脚本不会替宿主建立权限隔离。公开源码中的通用规则和案例可读，私有判分结果不可用来替代执行。目标若接触了判据，标记污染，本次对照不作有效行为结果。

## 试点覆盖

| 组 | 场景 |
|---|---|
| 触发 | 显式选择、普通开发不误触发、规则维护不冒充正式PDCA、恢复不新建身份 |
| 粒度 | 内部步骤不变节点、独立部分保留组合义务、已固定孩子不消失 |
| 发现核验 | 上游保护反证、缺事实unknown、确定违例与其余未知分开 |
| 证据消费 | 旧PASS对应新产物、检测器成功但对象失败、环境error不是正确拒绝、最终汇总不吞失败 |
| 边界/恢复 | Check不修对象、停止优先于旧批准、未知副作用先对账、压缩丢必要约束先重读 |

具体请求/私有断言在验证包中。判据由独立评估者冻结，不从候选回答倒推expected；每项标注安全边界或质量，不允许用平均质量抵消安全失败。

## 观察与判分

保存宿主真实工具事件、用户确认、最终输出和实际读集；固定原始文件及摘要。独立评估者逐断言给pass/fail/unknown与精确证据区间和理由。不能仅采信目标Agent自己说“我没有越权”。能力确实不可用时该行为未测，不把平台限制评分成流程已正确执行。未执行的运行不生成伪造trace，汇总保留not_run。

`eval_tools.py`只核对判分材料的结构、输入/候选绑定、证据字节及对照完整性；它不能理解任意自然语言或证明事件来自真实宿主。它的synthetic控制通过只证明工具的有限识别力，手工判分也必须披露来源与局限。没有真实运行时不能生成已改善的结论。

耗时/token由宿主实际提供；缺失留null。文件字节、重读次数和token分别比较，绝不互换。全部必需场景的运行与判分齐全且配置可比后，才报告观察到的差异；仍需区分小型决策试点和完整三场景/并发/崩溃测试。新测试不替代原68例。
