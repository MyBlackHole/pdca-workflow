# U15：不可变版本和完整提交先于发现视图

## 固定前置与被测对象

在授权临时目录模拟payload已写但未提交、提交记录完整但head视图未更新、payload损坏和重复恢复。

模型中的LIB/D、DIGEST-*、FIX-*和授权标志仅为符号fixture；不是实际生产ID、摘要、用户消息或发布证据。宿主验收必须在授权沙箱绑定真实值。每个向量独立重置，不继承前一例状态。

## 执行动作

依据完整提交记录和实际store摘要判断发布；有记录则修视图，不重放发布副作用；部分记录保持未发布。

## 正例、反例与oracle

正例：完整commit且payload一致时可重建head；已经一致时返回已提交。

反例：只看到文件存在就发布；完整回执指向损坏字节仍放行；恢复重做一次发布。

逐字段比较model_vectors的固定expected；预期来自上述契约，在运行之前保存。正确拒绝错误资料是测试通过；测试器/环境坏了记error，不是有效拒绝。仅参考模型通过不能写host_result=PASS。

`RECOVERY_REPLAYS_PUBLICATION`：故意省略 `no_replay` 检查，对 `replay` 运行原断言应出现差异。另跑全部正向控制，防止用“始终拒绝”取得假通过。变体未执行或构建失败是invalid，不计killed。
