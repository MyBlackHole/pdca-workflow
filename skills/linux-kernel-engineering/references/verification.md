# 验证与审查

先找项目已有构建和测试入口，只运行与改动和风险相关的检查。不能将格式检查等同于语义正确，也不能把压力测试无报告当作并发证明。

## 输出目录约束

编写或运行测试时，**不要在 `/tmp` 创建或写入测试文件、临时目录、日志、构建产物或缓存**。优先使用当前项目已有输出目录。

运行前确认构建器、编译器、测试框架、UML/QEMU、sanitizer 和子进程的临时文件行为。可配置时，将 TMPDIR/TMP/TEMP、缓存、日志和显式输出参数指向工作区的已有目录或专用验证目录。不能仅因设置 TMPDIR 就假定所有工具均遵守；已知硬编码 `/tmp` 且无法重定向的测试不运行，说明原因。不要为了验证该限制而先让测试往 `/tmp` 写一次。

## 选择验证

| 变更风险 | 用户态 | 内核态 |
| --- | --- | --- |
| 风格/编译问题 | 目标 C/C++ 模式、现有告警与静态分析；Rust fmt/clippy 按项目配置 | 目标 Kbuild、变更相关 W=1 告警、checkpatch；C=1 sparse（工具可用时） |
| 越界、释放、未定义行为 | 针对性测试及适用 ASan/UBSan/LSan | KUnit/集成场景及适用 KASAN/UBSAN/KFENCE |
| 数据竞争/锁 | 并发回归和适用 TSan；核对同步证明 | lockdep、KCSAN、相关上下文/锁调试配置 |
| 内核内部逻辑 | 可复用纯逻辑在其真实环境测 | KUnit 适合内部单元/白盒路径 |
| 系统接口与设备行为 | 客户端行为、协议和错误约定 | kselftest/既有集成测试，真实 UAPI 和设备路径 |
| 资源耗尽与回滚 | 分配/I/O 失败注入、容量和退出测试 | fault injection、probe 失败、热拔插/解绑、队列取消 |
| 性能 | 同一条件下对比代表性工作负载 | 同配置/硬件/负载下对比，按需 perf/追踪和锁竞争分析 |

这是可选工具映射，不要求每次全部启用。不同 sanitizer/config 可能需要分别构建运行；支持程度以目标工具链/架构为准，不强行组合全部开关。

## 有意义的场景

从本次改动选择适用项，不为纯格式或低风险文档改动新增业务测试：

- 正常输入与最小/最大/越界输入；长度加乘溢出、无效标志、权限和坏地址。
- 每个相关资源取得失败时的回滚；验证错误码、剩余所有权和资源平衡。每个负例只破坏它要验证的条件，避免更早的检查掩盖目标分支。
- 并发生产/消费、重复使用、关闭/取消/超时、回调与释放竞争；用明确屏障/事件控制关键交错，避免仅 sleep 后猜时序。
- 重试期间维持原截止时间；部分完成不重复提交具有副作用的操作；超时后后台访问仍受生命周期保护。
- 内核改动涉及上下文时覆盖相关 RT/非 RT、SMP、抢占及实际支持配置；不要为无关变更盲目跑完整矩阵。
- ABI 变化覆盖旧应用/新内核、相关新应用/旧内核的探测/降级、32 位 compat、布局及保留字段；架构与硬件不足以验证的项列为未验证。
- 设备相关覆盖 probe 失败、解绑/卸载、IRQ/work/timer/DMA 在途和相关 suspend/resume 生命周期。

## 性能证据与交付

记录同等条件下的基线与候选值，包括负载、并发、运行次数和波动；按目标报告吞吐、p95/p99 延迟、CPU、内存或锁竞争。诊断开关导致的开销与正式测量区分；优化收益与饥饿、复杂度、内存和尾延迟代价一起评估。

审查先关注可触发的正确性、生命周期、安全和兼容问题，再看性能与风格。每项问题附具体位置、触发条件、影响和建议；无法从证据确认的风险明确标为待验证。

交付说明包含实际命令或可定位的测试入口、结果、配置/环境及未覆盖项。失败和未运行都如实记录。提交/推送/邮件发送仍取决于用户授权，不由此技能自动触发。
