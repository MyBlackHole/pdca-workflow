# Linux 内核工程实践

以 Linux 内核的可维护性、资源纪律、并发设计、兼容性和可验证性为基础，按实际执行环境选择实现。此技能是工程实践指南，不是内核全部子系统的 API 手册。

## 适用边界

- 主语言为 C。C++ 仅作为 C 风格代码的编译环境，**不使用 C++ 库**：不引入 STL、`std::`、iostream、智能指针或基于 C++ 库的 RAII。采用 C 接口、显式所有权和成对释放；不主动引入类层次、模板、异常、RTTI 等复杂设施。
- Rust 单独沿用所有权、安全边界与同步设计；用户态遵守项目 Rust 约定，内核态使用目标树支持的 Rust 抽象。
- 遵守用户和项目既有约束。普通改动不附带全仓格式化、语言迁移或替换依赖。遇到已有 C++ 库，只在本次授权范围内应用上述约束，不自动重写整个项目。
- 本文“共同原则”是跨环境的工程提炼；内核专用规则只约束内核路径。准确 API、配置和子系统约定以**目标源码树**为准，不能将在线最新文档当作旧内核的接口保证。

## 工作入口

先从构建文件、调用者和邻近实现确认下列信息；只询问无法从项目得知且会影响正确性的条件：

| 确认项 | 需要查明的事实 |
| --- | --- |
| 环境 | 用户态/内核态/跨边界；语言与标准；内核版本、厂商补丁、架构、配置及 PREEMPT_RT |
| 契约 | 输入信任边界、返回约定、可见行为、API/ABI、数据布局、时钟与单位 |
| 执行 | 进程/线程/信号/硬中断/softirq/具体 workqueue 类型；允许阻塞吗；谁并发访问 |
| 生命周期 | 谁创建、持有、发布、取消、等待和释放对象；失败及卸载如何收敛 |
| 验证 | 现有构建和测试入口、输出目录、可用诊断工具、性能基线 |

按任务读取，避免一次加载全部参考资料：

- 任何实现或审查：读 [共同工程原则](references/engineering-principles.md)。
- 设计、实现或审查涉及分配、缓冲区、异步任务、共享状态或同步路径时：读 [内存与锁设计](references/memory-and-lock-design.md)，主动完成下面的设计要求。
- 用户态 C、C 风格 C++ 或 Rust：读 [用户态适配](references/userspace.md)。
- 内核、驱动、IRQ、DMA、workqueue、Rust for Linux：读 [内核态约束](references/kernelspace.md)。
- ioctl、共享内存、网络/磁盘格式等边界：读上述对应环境资料中的接口部分；跨用户/内核时同时读两份。
- 选择检查、构建、测试、基准或准备交付：读 [验证与审查](references/verification.md)。
- 确认依据、版本差异或进一步查 API：读 [官方资料索引](references/sources.md)。

## 核心决策

1. 复用已有子系统与项目抽象，把策略与机制分开；抽象须有具体复用或隔离理由。
2. 先确定不变量、所有权、锁保护范围及退出协议，再选择数据结构和原语。
3. 失败处理是接口的一部分：部分成功如何回滚、谁仍拥有资源、能否重试，都应明确。
4. 不把 `volatile`、引用计数或单个原子变量当成完整的并发协议；内存可见性和对象存活分别证明。
5. 保持已有外部接口的可观察语义；新增能力设计兼容路径，内部实现可以演进。
6. 性能优化依据代表性测量，记录吞吐、尾延迟、CPU/内存及代价；不凭“内核也这么写”替换锁、加入 RCU 或强行零拷贝。

## 主动设计要求

涉及上述内存或并发路径时，把设计作为任务的一部分，无需等待用户点名“优化内存/锁”。从实际调用链选出当前任务范围内更合适的所有权、存储布局和同步方案；实现时落实可证明的正确性及资源上界改进，纯性能候选给出测量方法与取舍，不虚构收益。只读审查只提出结论，不自行修改业务代码。

按本次相关性，在设计或审查结果中给出以下内容；简单场景几句话即可：

| 设计项 | 必须讲清的决定 |
| --- | --- |
| 内存 | 对象由谁拥有、何时转移/释放；分配次数和复制是否必要；容量如何计量和限制；失败、取消及在途使用如何收敛 |
| 锁 | 哪份共享状态由谁保护；锁类型/上下文、临界区及锁顺序；慢操作移出后靠什么保持存活和一致性；停止与等待如何结束 |
| 取舍与验证 | 采用或保留什么方案及原因；针对性反例/测试；需要基准才决定的优化及其测量项 |

保留现有方案也是有效设计决定，但要说明它为何满足当前生命周期、资源预算和并发需求。范围外重构作为独立建议，不把“主动设计”扩展为全仓重写。

## 容易混用的规则

| 问题 | 用户态 | 内核态 |
| --- | --- | --- |
| 错误返回 | 遵守实际 API；系统调用常为 `-1` + `errno`，pthread 常直接返回错误号 | 按回调契约，常见负 errno；指针错误仅用于支持该约定的 API |
| 同步 | pthread、C 原子；阻塞、退出、信号上下文分别处理 | 锁、waitqueue、completion、RCU 等；先核对执行上下文与 RT 语义 |
| 内存 | C 分配/释放及显式 unwind；Rust 使用项目类型 | 按睡眠、回收、连续性及设备要求选择分配器和 GFP |
| 风格 | 项目规范优先；新增独立 C 代码可采用内核风格 | 目标树编码风格及子系统惯例；checkpatch 是辅助 |
| 库 | C++ 只用 C 接口；Rust 用户态可按项目使用库 | 无 libc、C++ 标准库；Rust 内核环境无 `std` |

## 交付

按任务规模说明：行为或审查结论、适用的内存/锁设计决定、关键不变量/兼容性、实际验证和未验证项。问题给出位置、触发条件及影响。性能结论给出基线和数据。只报告实际执行的检查；未运行的配置、架构、硬件或压力场景明确标注。
