# PDCA Assist：当前项目的只读工作建议

本入口只分析并在会话中展示建议。用户显式调用才进入；加载 Skill、发现问题或用户选择候选项本身都不授予写入、阶段执行或 Git 修改权限。

## 定位与读取边界

1. 根据[项目绑定契约](../../ontology/contracts/project-workspace.md)，核对本 Skill 真实路径所在 PDCA_ROOT 与用户指定或既有会话绑定的一个 `project_id`/`workspace_id`。只读取对应集中 `project-context.md`，确认 `records_root=PDCA_ROOT/records` 与当前已绑定的 TARGET_ROOT。没有绑定、多个匹配、路径冲突或无读取权限时停止，报告缺口并建议用户通过 `pdca` 明确定位/绑定；不自动调用该入口。
2. 不扫描其他项目，不读取未关联目录或无关历史记录。只按当前绑定导航读取该项目必要的集中 records；在宿主权限允许的范围内读取当前 TARGET_ROOT 的相关源码、文档与 Git 状态。路径先规范化，符号链接或记录链接不能扩大项目读取范围；必要文件越界或无权限时停止并说明。不得因建议而执行测试、构建、安装或其他可能写文件的命令。
3. 在 PDCA_ROOT 中只读运行 `GIT_OPTIONAL_LOCKS=0 git rev-parse HEAD`、`GIT_OPTIONAL_LOCKS=0 git status --porcelain`，禁用可选索引写入，报告规则 HEAD、工作树状态以及绑定所记录的 `rules_git_head`/`rules_git_status` 的差异。TARGET_ROOT 为 Git 工作副本且读取获准时使用相同命令查询，并分别标明目标与规则 Git 状态。目标不是 Git 仓库则如实说明；集中根 Git 命令失败、无有效 HEAD 或状态无法核实时停止，不猜测或修复。
4. 工作树有未提交改动时只报告风险，提供审阅、提交、暂存或继续的选项，不执行 Git 修改。集中 records 可被 Git 跟踪不代表可以读取其他项目，也不代表已获记录写入或 Git 提交授权。

## 建议前检查

生成建议前，先做两项检查：

1. **冗余检查**：按领域概念（而非请求字面词）搜索项目中是否已有类似实现、记录或决策。已有现成方案时，建议指向已有方案而非重新创建。
2. **先前拒绝检查**：搜索 project-context.md 和 event 记录中是否有类似请求被拒绝或标记为 wontfix 的历史。有拒绝记录时，说明上次拒绝的原因并询问是否要重新考虑。

## 四个建议视角

输出项目/工作区、读取依据和限制后，展示下列四个标签。每个视角最多一个候选动作；依据不足时写“暂无建议”及缺口，不凑任务。每个候选写明事实依据、动作、影响、所需授权。

| 视角 | 候选关注点 | 影响与所需授权 |
|---|---|---|
| 任务地图 | 当前任务、最后实际阶段、待用户事项与依赖 | 说明拟影响哪个任务；创建任务或启动某阶段需用户明确操作 |
| 项目上下文 | 绑定、源码与文档中的上下文缺口 | 列出拟补充的具体集中记录；写记录须记录写入授权，业务文件另需目标写入授权 |
| 证据审阅 | 既有证据与验收标准之间的缺口 | 标明建议审阅或补验的对象；运行验证需授权，正式 Check 须用户启动，不输出正式通过结论 |
| 协作交接 | 原 Agent、待回应请求与交接材料缺口 | 标明接收对象与信息范围；发送消息/交接须明确授权，恢复任务仍回原 Agent |

然后等待用户选择、补充并授权。选择后先核对具体动作与授权范围，再由用户启动对应入口；不要将选择解释为四阶段连跑或自动串联其他 Skill。

## 停止边界

建议阶段不创建记录、不创建任务、不派发 Agent、不创建资源预约、不启动阶段、不写入 TARGET_ROOT，也不提交、拉取、切换分支、暂存、还原或覆盖 Git 工作树。不因分析写日志、context 或"待办"，不轮询原 Agent。输出建议后停止，宿主实际交互是否满足这些边界仍需[现场验收](../../tests/host-acceptance.md)，静态检查不替代验收。

用户拒绝某个建议后，本次会话不重复推荐同一建议，除非用户主动重新提及或上下文发生实质变化（如新证据出现、任务状态变更）。尊重用户决定，不反复骚扰。
