# Act：执行获准处置，保留真实结论

## 先定位，不以加载当授权

安装后的入口会给出真实 **PDCA_ROOT** 和当前发布快照。直接从源码读取时，由用户明确集中根，或核对该文件真实路径所在的根；定位不等于批准业务操作。路径冲突时停止，不在目标项目创建 `.pdca/` 或另一份 records。

先读[共同恢复入口](../../bootstrap/entry-check.md)，再读集中项目 context、自己的 task/原 Agent 绑定、最后完整事件和当前请求。已有任务采用 `protocol_baseline_ref` 所在快照；与本入口版本或摘要不同，则只作定位并读取原快照方法，不用这里的新方法推进旧任务。

当前会话不是该任务执行者时，只把真实用户操作路由回原 Agent 后停止本地执行；不可路由就阻断。**切换 Skill 不换 Agent**，不要调用新建工具、设置自动 fork 或由父 Agent 接管。加载方法、文件存在和上一阶段 PASS 都不授权本阶段。

开始前核对匹配 task/attempt/phase/run/subject 的原始用户回应、固定输入及撤权状态，并核验集中资源预约及实际写权。缺项时展示本阶段目标和缺项后等待；已有明确确认不要重复盘问。无任务时返回总入口定位，不在阶段 Skill 中新建。

## 当前 run 的动作

1. 对齐当前 Check 报告及其产物版本，明确用户批准的是接受交付、仅归档、共享发布还是采纳经验；不能从“同意”推导未展示的发布权限。
2. 按[Act 方法](../../ontology/process/flow-act.md)执行获准处置。公共本体发布、产品发布及任务私有记录各有资源/写权，不能因同在一个中心而混用。
3. 经验记录来源、版本、环境、反证、未验证范围和重评条件；没有新经验就说明没有，不把失败结论改为成功。
4. 核对在途 operation 和集中预约，保存实际归还或 retained 隔离依据。task completed、会话停止或租期到期不自动释放实际对象。
5. 固定最终交付、映射/模型版本、处置证据与实际场景覆盖；其他节点或未来场景未运行就 not_run。失败/unknown可在用户批准下诚实归档，不标可用。

## 报告与停止

保存本 Act 完成及归档事件，报告实际处置和未决资源。没有下一轮授权就停止；不自动创建孩子、启动下一场景或新 attempt。
