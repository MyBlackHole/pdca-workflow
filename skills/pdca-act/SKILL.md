# Act：执行获准处置，保留真实结论

## 先定位，不以加载当授权

核对本文件经符号链接解析后的真实路径，定位集中 Git 工作副本 **PDCA_ROOT**。既有任务绑定优先于 cwd 或环境变量；与入口所在根冲突时停止，不在目标项目创建 `.pdca/` 或另一份 records。定位不等于批准业务操作。

先读[共同恢复入口](../../ontology/contracts/entry-recovery.md)，再读当前绑定项目 context、自己的 task/原 Agent 绑定、最后完整事件和当前请求。核对记录的 `rules_git_head`/`rules_git_status`；每次获准写入记录前按共同入口重新采集当前 Git 来源。已有任务不自动改绑或升级规则，原依据缺失或规则冲突时停止；不复制规则、不自动 checkout，不以新规则改写原授权。

当前会话不是该任务执行者时，只把真实用户操作路由回原 Agent 后停止本地执行；不可路由就阻断。**切换 Skill 不换 Agent**，不要调用新建工具、设置自动 fork 或由父 Agent 接管。加载方法、文件存在和上一阶段 PASS 都不授权本阶段。

开始前核对匹配 task/attempt/phase/run/subject 的原始用户回应、固定输入及撤权状态，并核验集中资源预约及实际写权。缺项时展示本阶段目标和缺项后等待；已有明确确认不要重复盘问。无任务时返回总入口定位，不在阶段 Skill 中新建。

## 当前 run 的动作

1. 对齐当前 Check 报告及其产物版本，明确用户批准的是接受交付、仅归档、共享发布还是采纳经验；不能从“同意”推导未展示的发布权限。
2. 按[Act 方法](../../ontology/process/flow-act.md)执行获准处置。公共本体发布、产品发布及任务私有记录各有资源/写权，不能因同在一个中心而混用。
3. 经验记录来源、版本、环境、反证、未验证范围和重评条件；没有新经验就说明没有，不把失败结论改为成功。用户要求回顾时，补充结构化回顾：(a) 本次做得好的（保留），(b) 可改进的（记录到 ontology/decision/），(c) 对后续任务的建议（写入 project-context.md）。团队项目时，补充 per-person 视角：每人的贡献、赞扬点和成长机会。可选补充：**趋势观察**（连续多个任务的模式变化，如"调试时间逐任务缩短"）和**尤里卡时刻**（意外发现的关键洞察，供后续任务参考）。
4. 核对在途 operation 和集中预约，保存实际归还或 retained 隔离依据。task completed、会话停止或租期到期不自动释放实际对象。
5. 固定最终交付、映射/模型版本、处置证据与实际场景覆盖；其他节点或未来场景未运行就 not_run。失败/unknown可在用户批准下诚实归档，不标可用。

## 报告与停止

保存本 Act 完成及归档事件，报告实际处置和未决资源。每个处置选项（交付/归档/发布）需用户逐项确认，不从"同意"推断其他选项的权限。没有下一轮授权就停止；不自动创建孩子、启动下一场景或新 attempt。

**幂等性：** 重复执行不重复归还资源或重复发布。已完成的 Act 不因重跑产生副作用。
