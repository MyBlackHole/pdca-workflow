# Skill 入口，共同资源中心

总入口定位和显式绑定；辅助入口只读提出建议；阶段入口操作已有任务；场景入口提供对象与方法。各入口共享同一集中 Git 工作副本，宿主通过指向其 `skills/` 的发现路径读取正文。

| Skill | 作用 |
|---|---|
| [pdca](pdca/SKILL.md) | 用户显式选择 PDCA、绑定项目、查询状态或恢复已有任务时使用。定位集中 Git 工作副本与原会话，不自动创建任务或执行四阶段。 |
| [pdca-assist](pdca-assist/SKILL.md) | 仅在用户显式调用 pdca-assist，为当前已绑定项目选择下一步工作建议时使用。普通请求不自动启用。 |
| [pdca-plan](pdca-plan/SKILL.md) | 用户明确启动或继续现有 PDCA 任务的 Plan 阶段时使用。 |
| [pdca-do](pdca-do/SKILL.md) | 用户明确启动或继续现有 PDCA 任务的 Do 阶段时使用。不自动 Check。 |
| [pdca-check](pdca-check/SKILL.md) | 用户明确启动现有 PDCA 任务的 Check 时使用。不修改业务对象或自动返工。 |
| [pdca-act](pdca-act/SKILL.md) | 用户明确批准现有 PDCA 任务的 Act 处置时使用。不启动下一场景。 |
| [pdca-model](pdca-model/SKILL.md) | 用户明确选择本体建模场景，或已有建模任务需要场景方法时使用。不以知识地图冒充模型。 |
| [pdca-implement](pdca-implement/SKILL.md) | 用户明确选择本体投影场景，或已有投影任务需要场景方法时使用。不脱离模型。 |
| [pdca-verify](pdca-verify/SKILL.md) | 用户明确选择本体符合性验证，或该任务需要核验方法时使用。不把链接检查当语义证明。 |

四阶段每次匹配用户操作后启动，完成后停止；一个任务使用多个 Skill 但保持原 Agent。已有 task 绑定优先，读取场景方法不创建场景任务。中央项目/任务登记和资源预约对所有入口相同；业务项目不自动生成 `.pdca/`。记录写入与 Git 提交分别授权。

`catalog.json` 是入口名录，不是授权表。正文相对链接从集中工作副本解析，不生成导出副本或规则快照；更新由用户自行使用 Git 完成，并按宿主能力重启或显式重载。更新不自动改绑活动任务或授权后续阶段。宿主发现与交互以[现场验收](../tests/host-acceptance.md)为准。

## 任务分解

当任务超出单个 PDCA 周期时，支持在 Plan 阶段建议拆分，Do 阶段按薄切片执行。

### 触发条件（Plan 阶段判断）

- 预计时间 > 8 小时
- 涉及 > 3 个独立模块
- Agent 置信度 < 0.7

### 执行原则（Do 阶段遵循）

- **薄切片**：每个子任务贯穿所有相关维度的窄但完整路径
- **阻塞边**：显式声明子任务间依赖关系
- **前沿驱动**：所有阻塞项完成的子任务可立即开始
- **可验证交付**：每个子任务完成后可独立验证
- **宽幅变更例外**：机械性全局变更用扩展-收缩策略

### 约束

- 需要用户批准拆分方案
- 每个子任务对应独立 PDCA 周期
- 父节点协调子任务执行和结果聚合

详细设计见[子任务拆分详细设计](../docs/superpowers/specs/2026-09-15-subtask-splitting-design.md)。
