# 内核态约束

首先确认目标源码树、架构、配置、子系统及 PREEMPT_RT。以下为决策依据，不保证每个列出的 API 在目标内核都存在。具体函数及清理顺序核对树内声明、文档和调用者。

## 风格与执行环境

- 内核 C 采用目标树风格：tab 按 8 列显示，函数大括号换行、控制块大括号同行，命名清楚、避免深嵌套、尽量保持文件内一致。80 列为优先可读性目标，不机械拆坏字符串或更清晰的语句。
- 代码不依赖 libc、C++ 库或普通用户态运行时。内核开发以目标树支持的 C/Rust 为准，不将 C 风格 C++ 推广为内核 C++ 开发。
- 不假设每种内核执行上下文均可睡眠。硬中断、softirq、持 raw 自旋锁、禁抢占等约束与可睡眠进程上下文区分；上下文也可能受调用者持锁影响。
- **workqueue 并不一律可睡眠**：普通 threaded workqueue 与 BH workqueue 的上下文不同；核对队列标志与具体 callback。
- 尽量缩小中断/不可睡眠路径，将可延迟操作交给合适线程上下文。访问调用进程的用户指针应在有正确用户地址空间和允许 fault 的上下文处理；移到普通 worker 不会自动让原始用户指针可用。

## C 作用域清理

目标树支持、子系统接受且工具链满足时，评估 `__free()`、`guard()`/`scoped_guard()`、`return_ptr()` 等内核 C 抽象；禁止 C++ 库不限制这些机制。旧树和用户态工程沿用各自清理方式，不强行移植宏。

- 清理按声明逆序发生，在真正取得资源的位置定义并初始化变量；需要持锁的对象清理必须先于锁释放。
- guard 持锁持续到对应作用域结束；用清晰作用域控制范围，不能把最后一处显式访问当作解锁点。
- 成功返回或移交对象时使用目标树适用的所有权释放标记，避免自动清理释放已交付对象；失败路径仍须正确清理。
- 遵守该机制要求的函数内退出方式，避免跨作用域 goto 与自动清理造成重叠释放或错误顺序。
- 自动清理只处理当前作用域，不替代 [异步退出协议](../principles/memory-and-locks.md#生命周期与退出协议)。

## 锁、内存序与生命周期

- mutex 只用于允许睡眠的场合。spinlock/raw_spinlock 的选择来自上下文与共享关系；不要用关本 CPU 中断替代跨 CPU 互斥。
- PREEMPT_RT 下 `spinlock_t`、rwlock 等语义变化，不能套用非 RT 的禁抢占/IRQ 假设。确需硬中断级保护时审慎使用极短的 raw 锁区域，而不是把所有锁都替换成 raw 锁。
- 在不可睡眠上下文或持有禁止睡眠的自旋/raw 锁时，不调用可能 fault/睡眠的 uaccess、分配或阻塞等待。PREEMPT_RT 的锁约束单独核对。
- 可睡眠进程上下文中持 mutex 并不天然禁止 `GFP_KERNEL` 分配或 uaccess；核对回收、fault、回调及锁顺序是否产生同锁依赖或死锁。把慢操作移出 mutex 是需要维持生命周期和事务一致性的设计选择，不能一概当成正确性修复。
- cancel、flush 和 synchronize 等等待操作若可能等待需要当前持有锁的执行者，会形成死锁；按实际依赖安排等待点。
- mutex 及其所在对象至少存活到 `mutex_unlock()` 调用返回，并收敛其他使用者；内部发布点或其他线程观察到锁空闲均不构成回收证明。
- `READ_ONCE`/`WRITE_ONCE` 限定特定访问行为，不自动建立完整的跨 CPU 发布协议。原子 API 按具体操作/后缀核对排序，不能假定所有 `atomic_*` 都是全屏障。
- 对象引用采用适合的 `refcount_t`/kref；取得与交付引用的存活依据按 [生命周期与退出协议](../principles/memory-and-locks.md#生命周期与退出协议) 检查。
- RCU 需分别证明读侧保护、指针发布、写者同步和延迟回收；引用计数不能替代 RCU grace period。睡眠条件取决于所选 RCU 家族和读侧上下文，不能概括为所有 RCU 都一样。
- 卸载/失败回滚遵循 [异步退出协议](../principles/memory-and-locks.md#生命周期与退出协议)，按设备依赖同步 IRQ、定时器、work、DMA 等。`cancel_work_sync` 不是阻止所有未来 queue 的开关；`devm_*` 也不自动消除活动回调的竞态。

## 内存、资源与设备

| 决策 | 约束 |
| --- | --- |
| kmalloc/kzalloc、数组、flexible array | 大小受上下文和分配器限制；数组用可检查溢出的 API，结构尾数组按目标树使用 struct_size 等 helpers |
| GFP | 根据是否允许直接回收、睡眠及回收递归选取；GFP_KERNEL 可睡眠；非睡眠路径评估 NOWAIT 及失败退路，访问保留资源有理由时再用 ATOMIC，仍须处理失败；核对 NMI、RT/raw 锁及禁抢占对分配器本身的限制 |
| 大块/连续性 | 区分虚拟连续和物理连续；不将 vmalloc 内存直接作为普通 DMA 缓冲；核对设备约束 |
| 回收路径 | 文件系统/块层等按调用路径评估 NOFS/NOIO 与作用域机制，避免回收递归死锁，不只局部改一个分配标志 |
| 用户触发分配 | 核对 memcg/kmem 归属及子系统计量；按上下文选用 `__GFP_ACCOUNT`/`GFP_KERNEL_ACCOUNT` 等适用机制，不重复计量，也不能用服务字节上限替代系统资源归属 |
| devres | 只管理与 device 生命周期相符的资源，核对解绑和手动释放，先停止活动使用者 |
| 栈 | 控制局部大对象与递归；不要假定用户态栈规模，敏感或大数据按上下文另行分配 |
| MMIO | 使用适用的 ioremap/readl/writel 等平台抽象；不能用普通内存原子/volatile 指针访问替代 |
| DMA | 区分 CPU 虚拟/物理/DMA 地址；设置 mask、处理 mapping error、方向和 map/unmap/sync 配对；CPU 锁不能代替设备可见性保证 |

分配与映射均处理失败；内存压力、高阶分配失败和设备移除是正常错误分支。需要预分配、池化或保留资源时给出容量和耗尽策略。

PREEMPT_RT 下释放内存也可能涉及分配器内部锁；分配和释放均核对调用上下文，必要时将实际回收延后到允许的执行环境。

`mempool.min_nr` 是最小保留元素数，不是最大活跃分配数；常规分配先尝试底层分配器，失败再使用保留。硬上限另行计量和准入，进展还需核对资源需求、并发及等待依赖。

目标树的类型化分配 helper（如 `kmalloc_obj`、数组/柔性数组 helpers）核对实现、默认 GFP、溢出和计数字段规则；不能因省略参数而在不可睡眠路径隐含使用 GFP_KERNEL，也不要求旧树增加该 API。

回收路径依赖工作项时，结合 NOFS/NOIO 作用域核对队列进展保证和等待关系；`WQ_MEM_RECLAIM`/rescuer 与 mempool 分别解决特定问题，均不能据此假定所有依赖都会前进或资源/锁循环已消除。

## UAPI、ioctl 与不可信输入

- 不直接解引用用户指针。使用适用的 `copy_from_user`/`copy_to_user` 或目标树 helpers；这两类 copy API 返回未复制字节数，非零视为失败，不能当作负 errno 使用。部分复制不能留下未初始化字段供后续使用。
- 固定请求头复制到内核后验证；嵌套缓冲区有独立的长度/方向/算术/权限检查。需要一致快照时复制一次后使用副本，不能重复读取用户内存形成 double-fetch。
- 异步任务优先持有内核副本。若性能确需固定用户页，另行证明 pin/unpin、进程退出、取消、内存失效、DMA 及长期固定约束；仅保存指针或固定页面都不代表内容不会并发变化。
- UAPI 使用明确位宽类型，布局避免本机 `long`、`size_t`、裸指针、enum 和隐含 padding。按需要使用 `__aligned_u64`、显式保留字段及正确的用户指针转换，验证 32/64 位布局及 compat 路径。
- 新接口清零输出和 padding，校验未知 flags、保留字段及长度上界；既有 ABI 先保留已发布语义，不盲目增加会拒绝旧应用的检查。
- ioctl 使用正确方向的 `_IO/_IOR/_IOW/_IOWR` 和类型参数，**不传 `sizeof(type)` 代替类型**。未知命令按接口约定返回 `-ENOTTY` 等正确结果。
- handler 返回值依回调契约，常见为 0/负 errno；不要把所有内核函数一概改为该约定，也不混淆 ERR_PTR 与 NULL。
- 已发布命令不因版本号重新解释旧字段。语义变化使用新命令并保留旧命令；大小可扩展结构需使用子系统既有协议、能力发现和兼容规则，不能只在结构末尾随意加成员。
- 时间表示明确定义位宽、单位、时钟域和绝对/相对语义；避免直接导出本机 timespec/timeval。持续时间/截止时间通常选择单调时钟，持久日历时间按实际需求另行定义。
- 对 read/write/poll/mmap、netlink、sysfs 等也明确权限、阻塞、取消、部分成功和文件/设备关闭后的生命周期；选用已有子系统接口，避免重复造通信协议。

## 可观测性、框架与 Rust

- 驱动优先 dev_*，其他路径适用 pr_*；选择日志级别、动态调试与限速。高频诊断按需采用 tracepoint/ftrace 等，勿用 printk 刷屏影响时序。
- 普通无效输入返回错误，不用 BUG/BUG_ON 或 WARN 当验证器。WARN 用于真正预期不可达的内部违约，考虑 panic_on_warn 的影响。
- 驱动接入设备模型、probe/remove、错误回滚及相关 PM/runtime PM 生命周期；文件系统、网络、块 I/O、调度等改动先读对应子系统文档及邻近代码，不根据通用清单猜测其锁/回调契约。
- Rust for Linux 使用目标树支持的 `no_std` 环境与 `kernel` 抽象，不能直接搬用户态 std 或未经支持的 crates。核对工具链、可用 API、分配失败、锁保护、固定地址/Pin、FFI 与 unsafe 不变量。
- 模块许可证标记、导出符号和接口许可按项目与上游规则处理；外部模块没有稳定内核内部 API 保证，支持矩阵需要实际构建和行为证据。
