# 编码、注释与接口文档

普通系统代码开发使用本页，不额外加载中文补注流程。Linux 内核规范提供设计经验，目标项目、源码版本及子系统风格优先。

## 控制流与表示

- 命名表达角色、单位和状态；使用可局部理解的控制流、明确错误路径和项目已有抽象。函数长度、行宽等遵守目标规则，不为满足通用数量门槛拆出无意义包装。
- C/C++ 语言差异、错误约定与 FFI 见 [用户态适配](../environments/userspace.md)；资源清理见 [生命周期与退出协议](memory-and-locks.md#生命周期与退出协议)，目标内核的新写法按 [C 作用域清理](../environments/kernelspace.md#c-作用域清理) 核对。
- 宏仅用于必要的编译期能力，避免隐藏控制流与参数多次求值。内联、位操作和布局技巧须有具体必要性，检查对齐、端序、位宽及未定义行为。硬件/UAPI 布局与普通内部数据结构分开处理；内联和缓存行填充需要测量依据。
- 只调整当前逻辑相关的格式和组织；纯重排、语言迁移和更换容器/依赖各有自己的授权范围。格式检查只是辅助，不替代语义证明。

## 说明维护者无法直接看出的契约

根据当前对象或接口的风险选择需要说明的事实：

| 对象或接口 | 文档中的关键契约 |
| --- | --- |
| 内存、fd、请求及回调参数 | owned/borrowed/transferred；成功、失败、取消及部分完成后的责任；谁能释放 |
| 共享状态与等待 | 锁或原子协议、可调用上下文、阻塞/重入条件、锁顺序、退出谓词及存活要求 |
| 外部 API/ABI、数据格式 | 长度与单位、布局/端序、错误约定、副作用、能力探测与兼容条件 |
| 非显然的实现选择 | 当前不变量、平台/硬件限制、取舍依据，以及改变条件后需要重新评估什么 |

文档描述实际实现和被证明的契约，不代替实现检查。使用目标项目的 kernel-doc、头文件注释或其他既有格式；不强制 `// 备注:`、固定模板、每个函数列出两个替代方案或补齐 FAQ。

注释解释原因、约束和容易破坏的不变量，不重复明显代码。原注释与代码不一致时核对真实契约，按本次范围修正或明确指出；不能仅因原文是英文就永久保留错误说明。许可证、版权和签署内容遵守其专门规则。

## 图示与验证

所有权转移、状态机、锁依赖、设备停止或数据布局用文字难以审查时，可增加简短图示。标签使用真实状态、函数、字段或业务概念中最准确的一种；包含相关失败/取消/退出路径。不按步骤数强制配图，不为画图重构代码，也不假定源码中的 Mermaid 会被自动渲染。

性能结论按 [性能证据与交付](../workflows/validation.md#性能证据与交付) 区分结构变化、推导和实测；源码中不写一次性调试流水账。

检查注释是否仍准确、公开声明与实现是否一致，以及改动是否误触代码、宏续行、编译指令或文档生成格式。中文项目/专门中文补注任务另按 [可选中文约定](project-conventions.md) 采用相关部分。
