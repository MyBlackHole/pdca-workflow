# 编码、注释与接口文档

普通系统代码开发使用本页，不额外加载中文补注流程。Linux 内核规范提供设计经验，目标项目、源码版本及子系统风格优先。

## 控制流与表示

- 命名表达角色、单位和状态；使用可局部理解的控制流、明确错误路径和项目已有抽象。函数长度、行宽等遵守目标规则，不为满足通用数量门槛拆出无意义包装。
- C/C++ 语言差异、错误约定与 FFI 见 [用户态适配](../environments/userspace.md)；资源清理见 [生命周期与退出协议](memory-and-locks.md#生命周期与退出协议)，目标内核的新写法按 [C 作用域清理](../environments/kernelspace.md#c-作用域清理) 核对。
- 优先用函数表达可类型检查的逻辑；确需预处理、类型泛化等能力时使用宏，避免隐藏控制流与参数多次求值。位操作和布局技巧检查对齐、端序、位宽及未定义行为，硬件/UAPI 布局与内部结构分开处理。`static inline` 可用于头文件实现、配置桩或替代函数式宏，不以基准为先决条件；为性能加入内联或缓存行填充时才要求相应测量依据。
- 只调整当前逻辑相关的格式和组织；纯重排、语言迁移和更换容器/依赖各有自己的授权范围。格式检查只是辅助，不替代语义证明。

字符串/二进制、长度与缓冲 API、结构布局及回调接口的设计规则见 [数据结构与接口](data-and-interfaces.md)，不以替换为“安全函数”代替边界证明。

## 说明维护者无法直接看出的契约

根据当前对象或接口的风险选择需要说明的事实：

| 对象或接口 | 文档中的关键契约 |
| --- | --- |
| 内存、fd、请求及回调参数 | owned/borrowed/transferred；成功、失败、取消及部分完成后的责任；谁能释放 |
| 共享状态与等待 | 锁或原子协议、可调用上下文、阻塞/重入条件、锁顺序、退出谓词及存活要求 |
| 外部 API/ABI、数据格式 | 长度与单位、布局/端序、错误约定、副作用、能力探测与兼容条件 |
| 非显然的实现选择 | 当前不变量、平台/硬件限制、取舍依据，以及改变条件后需要重新评估什么 |

文档描述实际实现和被证明的契约，不代替实现检查。使用目标项目的 kernel-doc、头文件注释或其他既有格式；不强制 `// 备注:`、固定模板、每个函数列出两个替代方案或补齐 FAQ。

注释解释原因、约束和容易破坏的不变量，不重复明显代码。原注释与代码不一致时核对真实契约，按本次范围修正或明确指出；不能仅因原文是英文就永久保留错误说明。许可证、版权和签署内容遵守其专门规则。

## Linux 内核编码与文档

仅用于目标内核代码；完整细则核对目标树的 `process/coding-style` 和子系统要求，来源入口见 [官方覆盖映射](../sources/official-docs.md#风格文档与贡献)。用户态不因此改为内核格式。

- 内核 C 使用 8 列 tab、函数大括号换行、控制块大括号同行；80 列是优先可读性目标，保留更清楚的语句和可搜索的完整消息。遵守 case、指针及运算符的目标树排版，不借修复重排无关代码，也不在源文件加入个人编辑器 modeline。
- 内核 C 通常不为可直接访问的结构或指针创建 typedef；不透明对象、明确整数类型及其他官方例外按目标树处理。UAPI 与内部类型分开。函数原型保留参数名，属性次序、导出位置和头文件依赖核对声明与调用者，不依赖偶然的间接 include。
- 相关常量优先考虑 enum；需要多语句宏时采用正确的 `do { ... } while (0)`、括号和局部名，避免捕获调用者变量。复用目标树已有 `ARRAY_SIZE` 等 helpers；函数规模依复杂度评估，不机械套行数或局部变量数量。
- 新接口的命名和类型区分谓词、操作状态与实际结果；内核状态通常为 0/负 errno，计数、指针或“是否发生状态变化”的返回值按各自契约判断，不能一律按状态码解释或机械改造已有 API。逻辑 bool 使用 true/false，精确外部布局另选明确表示。
- 条件编译优先隔离完整函数，在头文件提供契约一致的桩；条件可用时采用 `IS_ENABLED` 仍须保证符号存在和可链接。可能不用的定义按目标树采用 `__maybe_unused`，配置与可达性规则见 [Kbuild 与 Kconfig](../workflows/build-and-dependencies.md#linux-kbuild-与-kconfig)。
- C 导出 API、供模块使用的公开头接口及全局 API 按要求写 kernel-doc，说明 `@参数`、调用上下文 `Context`、`Return` 及相关类型成员。静态函数按实际维护需要写，不生成复述签名的模板。内存屏障的注释要解释配对和成立理由。
- 新用户接口维护 `Documentation/ABI/`；新增 `/proc`、启动参数、模块参数分别补相应文档及 `MODULE_PARM_DESC()`，新增 ioctl 核对号码登记和用户文档。验证方法见 [内核构建与文档检查](../workflows/validation.md#内核构建与文档检查)。

内核 Rust 使用 rustdoc，遵守目标树 rustfmt 和导入格式；`unsafe` 块前用 `// SAFETY:` 证明调用前提，unsafe 函数/trait 的公开约束放在 `# Safety`，两者不可互代。适用的 `# Panics`、`# Examples` 及链接按目标树规范处理；工具格式化不验证这些契约。内核 Rust FFI 与资源类型见 [内核态约束](../environments/kernelspace.md#可观测性框架与-rust)。

## 图示与验证

所有权转移、状态机、锁依赖、设备停止或数据布局用文字难以审查时，可增加简短图示。标签使用真实状态、函数、字段或业务概念中最准确的一种；包含相关失败/取消/退出路径。不按步骤数强制配图，不为画图重构代码，也不假定源码中的 Mermaid 会被自动渲染。

性能结论按 [性能证据与交付](../workflows/validation.md#性能证据与交付) 区分结构变化、推导和实测；源码中不写一次性调试流水账。

检查注释是否仍准确、公开声明与实现是否一致，以及改动是否误触代码、宏续行、编译指令或文档生成格式。中文项目/专门中文补注任务另按 [可选中文约定](project-conventions.md) 采用相关部分。
