# 可选的中文项目约定与补注

仅在用户明确选择中文项目、中文文档或中文补注任务时采用对应部分。中文回复本身不代表需要翻译项目、修改源码或改变生产配置；此资料不自动应用到所有工程技能。

## 项目约定

先区分以下选择：对话语言、文档受众、注释语言、提交语言、标识符、字符编码、locale、时区。将实际采用的约定写入目标项目现有 `AGENTS.md` 或规范；本资料不自动修改任何项目或宿主配置。

- 用户要求中文说明时用中文回复；项目已有英文文档/注释继续遵守项目约定，除非翻译或补注属于当前任务。
- 中文项目可采用简体中文文档、说明和提交正文；代码标识符、外部 API、协议字段与工具关键字遵守项目和平台契约。
- 文件编码、locale 与运行时区分别配置。UTF-8 中文内容不要求将生产 UTC 改为 `Asia/Shanghai`；时间存储、计算与展示遵守接口语义。
- 项目规则只约束可见产物与行为，不把内部思考语言作为验收条件。
- 采用哪个提交格式、是否升级版本由目标项目决定，准备提交使用 [提交与变更说明](git-commit.md)。

## 中文补注任务

先确认获准的文件、只改注释还是同时修正文档，以及是否要求逐字保留原文。遵守源文件实际的注释语法、缩进、文档生成格式和许可证；不统一强加 `// 备注:`。

补充非显然的所有权、同步、状态守卫、错误及设计原因。避免逐行翻译明显操作，不为“注释数量”扩大范围。注释应描述当前真实代码；英文原文不是天然正确的 authority。发现过时说明时核对调用者与契约，在获准范围内修正；若任务要求保留原文，则独立指出矛盾并添加准确补充，不悄悄覆盖原文。

必要时使用短文字、ASCII 或 Mermaid 说明状态/交互，让每张图回答一个具体问题，并包含相关失败、取消和退出分支。源码注释中的 Mermaid 未必会被项目工具渲染；只有项目支持且确有帮助时才使用，不强制每个复杂函数配图。

例如已有英文文档约定、用户仅要求解释取消协议时，可以在中文回复或获准的补注中说明：

```text
取消请求只关闭新增提交；已开始的回调仍持有对象。
等待回调结束后，最后一个持有者释放对象，再销毁等待者依赖的锁。
```

补注后查看差异，确认代码行为、宏续行、编译指令、许可证及未授权的原文未改变。性能数字只引用实际测量；未知的取舍写为条件或待验证项。普通系统开发的注释要求以 [编码与文档](coding-and-documentation.md) 为准，不额外启动整套中文补注流程。
