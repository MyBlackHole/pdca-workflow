# 安全边界审查参考

只选择本次攻击面相关部分。具体 API、协议和安全属性以目标版本契约及部署事实为准，不把教程片段或单项检查视为通用安全证明。

## 权限与信任

明确攻击者身份、可控字段、入口权限及目标资源。校验身份不等于有权操作每个对象；权限判断应覆盖实际资源、命名空间、租户及操作，检查随后替换对象、重解析名字或权限变化是否导致 TOCTOU。

默认行为和错误路径也要受约束：初始化未完成、策略缺失、配置禁用及下游失败时不能意外放宽权限。日志、错误响应和追踪字段只暴露当前调用者应看到的信息。

## 输入与资源

- 核对长度、计数、偏移、类型、标志、保留字段、编码与规范化顺序。加乘及对齐运算在分配/访问前检查；解析成功只说明满足某种格式，不等于满足权限或业务状态。
- 检查总量、并发量、重试、解压/解析成本与失败回收，避免攻击者通过合法小请求累积无界资源。详细预算和背压设计由 [内存与锁设计](memory-and-lock-design.md) 提供。
- 指针的非空/对齐、局部变量置空、引用计数不单独证明完整访问安全。检查有效范围、初始化、别名、对象存活及并发；发布/取得引用/取消/回调/释放的真实协议见系统资料。
- 内核异步接口不能借用可随时改变或消失的用户数据。复制或固定页面的方案分别证明输入稳定性、预算、完成、取消和释放；固定页面本身不保证内容不变，依据 [内核态约束](kernelspace.md) 审查。

## 注入与解释边界

输入到达 SQL、命令执行、脚本/模板、反序列化及其他解释器时，区分数据和语法。使用目标 API 的参数化或结构化入口，并验证不能参数化的标识符、选项或表达式范围。

命令参数列表减少 shell 解释风险，但以 `-` 开头的输入、程序自己的选项解析、可执行文件选择、工作目录及环境仍可能改变语义。不能把 `shell=False` 当成完整安全证明，也不提供拼接不可信内容的 shell 命令作为验证捷径。

反序列化按真实格式和库的能力核对：不可信输入是否能构造对象、执行代码、请求外部资源或触发无界成本；不能只根据文件扩展名判断可信。

## 文件路径与网络目标

路径清理、字符串前缀判断和“在某目录下”的文本形式不足以单独证明最终文件访问范围。结合绝对路径、组件边界、符号链接、目录替换、目录权限及实际打开/使用的对象检查；需要时采用平台支持的目录锚定访问和明确的链接策略。

SSRF 独立检查 URL 协议、解析、目标地址及端口、代理、重定向、DNS 变化和最终连接行为。只检查最初的域名字符串、一次 DNS 结果或本地路径，并不能证明后续访问目标合规。对每次实际请求及跳转应用一致策略，并验证解析/连接链的假设。

## 敏感数据、密码协议与依赖

识别凭证、密钥、令牌及个人信息的产生、存储、传输、日志和销毁路径，检查权限、错误输出、转储及子进程继承。环境变量和密钥服务也有各自暴露面，不能因未硬编码就断言安全。

使用项目采用的协议和经过审查的实现；按具体方案核对随机数、nonce/IV、认证、密钥生命周期、错误处理及降级行为。未有证据时不替换算法、不自创密码协议、不宣称合规或安全强度。

依赖审查固定实际解析版本、来源、完整性、已知漏洞及使用路径。锁定版本有助于重现，但不保证无漏洞；升级、镜像和宿主包管理配置不因审计自动获得修改授权。

## 语言与环境的检查点

| 环境 | 相关检查 |
| --- | --- |
| C / C 风格 C++ | 长度与字符串语义、格式串、显式资源责任、所有别名与在途访问；不用函数替换表代替证明 |
| 允许库的 C++ | 项目实际采用的容器/迭代器、所有权、异常与同步契约，不要求为审查引入新设施 |
| Rust | `unsafe` 操作的完整 Safety 前提、FFI、运行时别名和并发；`unsafe` 不取消其他类型/借用规则；内核/no_std 使用目标接口 |
| Go | 权限及解释边界、共享状态、goroutine/取消与资源退出、错误传播；不把编译通过或 race 一次无报告当完备证明 |
| Python | URL/路径、命令参数、SQL、动态执行、反序列化、权限及敏感错误信息；不以 try/except 或禁 shell 作为全部防护 |

Rust 指针访问前提可核对 [官方指针 Safety](https://doc.rust-lang.org/std/ptr/index.html#safety) 与 [unsafe 契约](https://doc.rust-lang.org/reference/unsafe-keyword.html)。Linux 规范来源及版本处理见 [资料索引](sources.md)。

## 反例与证据

对实际怀疑的边界安排最小反例：权限不同的对象、规范化与使用对象不一致、跨阶段输入变化、接近容量上限的并发请求、失败/取消/清理交错。负例必须触达所要检查的条件，记录现有防护是否提前拒绝。

优先使用已有测试与隔离环境，保留敏感数据脱敏及输出目录约束。不能复现或缺少部署条件时标注结论前提，不把可疑模式直接写为已确认漏洞。
