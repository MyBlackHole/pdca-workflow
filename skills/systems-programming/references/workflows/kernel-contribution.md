# Linux 内核贡献流程

用于向 Linux 上游准备贡献、报告或补丁，或用户明确要求遵循上游 AI 贡献规范。普通项目本地提交采用 [Git 提交方法](git-commit.md)，不套用本流程。

## 固定对象与必读原文

确认目标维护树、完整提交、子系统、适用政策版本和授权范围。上游目标不一定是主线 master；核对 MAINTAINERS 的维护树及子系统流程。来源核验按 [源码与规范比对](../sources/mainline-reading.md)。

AI 查错/修复的贡献开始前，完整读取适用的 development-process、coding-style、submitting-patches、coding-assistants、generated-content 及用户点名的资料；在 [官方覆盖映射](../sources/official-docs.md#风格文档与贡献) 定位原文。优先同提交树内文档，并核对当前贡献政策；不能用关键词片段或本页摘要冒充完整读取。必需资料受限时说明受阻环节，只推进不依赖它的获准工作，不宣称贡献已准备就绪。

## AI 归属与人工认证

- Linux 上游 AI 规则要求：AI 不新增 `Signed-off-by`，也不运行自动加签的 `git commit -s`；DCO 由人类审阅并亲自认证。即使人类表示愿意认证，也将新增该标签的操作留给人类；已有人工标签须核对确属该贡献后保留。
- AI 参与的贡献按政策包含 `Assisted-by: LLM`；其后只列实际采用的专项分析工具，不把 git、gcc、make 等基础工具列为辅助分析工具。不编造 `Reviewed-by`、`Tested-by` 或他人的许可。
- 说明工具影响的部分、短提示或较长会话的提示摘要、人工调整与真实验证。机械格式化等政策例外按原文判断；来源和敏感输入先核实、脱敏，不隐瞒有意义的生成内容，也不输出无关私密数据。
- AI 准备可审查的报告、补丁及证据，交人类核对并发送；不自行发送邮件或问题报告。此为 Linux 贡献要求，不改写其他项目的提交约定或授权。

## 获准的查错与修复

记录症状、目标提交、影响和反证；非平凡问题尝试制作能触达故障的复现，按 [根因调查](debugging.md) 形成因果证据。问题不成立就撤回该结论。

在已授权修复范围内完成相应代码修改、复现回归及构建/分析验证；不只批量产生未经核实的报告。核对新增告警、checkpatch 和 [内核验证](validation.md#内核构建与文档检查)；检查失败时继续修正，受限时明确未执行项。只读审查仍只输出发现，不因本页扩大为修改授权。

提交内容与混合暂存保护按 [Git 提交方法](git-commit.md)。本地提交、上游准备和实际外发分别判断授权与完成状态，不把生成草稿称为已合入或已通过维护者审查。

## 补丁、标签与修订

- 每个补丁承担独立逻辑目的；系列中每步保持可构建和合理行为。标题按目标子系统的 `[PATCH vN i/n] subsystem: summary` 等惯例，永久说明写清问题、可见影响、原因、机制和验证。
- 已定位引入缺陷的提交时，`Fixes:` 包含至少十二位提交标识及原摘要；实际报告或讨论使用可访问的 `Closes:`/`Link:`。不要把未核实的 Issue、引入提交或测试结果补成事实。
- stable 候选核对主线已有等效修复等资格条件；公开补丁合适时在标签区加入 `Cc: stable@vger.kernel.org`，未公开安全问题的地址和材料按当前安全/stable 原文另行处理，不能误发公开列表。`Fixes:` 不自动替代回补资格；回补检查依赖、冲突后的语义与目标版本验证，不只证明补丁可应用。
- 使用 MAINTAINERS、历史及 `scripts/get_maintainer.pl` 定位真正相关的维护者/列表，接口变更核对用户 API 和手册维护者。格式使用原文规定的纯文本补丁；修订说明与不应进入永久提交记录的内容放在 cover letter 或 `---` 后，不混入提交正文。
- 回应审查意见，提交新版时说明相对上版的变化并保留实际获得且仍适用的标签；不可变的重发与修改后的新版分别使用 RESEND 和版本号。人类发送前复核收件人、附件/正文及系列完整性。

## 回归与安全问题

回归固定首次受影响范围、已知良好版本及必要的 bisect 证据；按目标上游流程准备修复或回退方案，不以现有测试通过否定用户回归。需要时准备 regression tracker/regzbot 的关联信息，标清报告与修复，跟踪工具不替代修复证据。

安全分类先按 [内核安全边界](security-review.md#linux-内核问题分类) 核对 threat model，再完整读取当时的 security-bugs 规则。报告列固定版本、配置、攻击者权限、触发/观察步骤及已验证的修复；AI 辅助发现问题的公开性判断、复现材料处理和分流依该原文及人工复核，不能沿用通用“全部公开/全部保密”假设。

原文来源统一见 [贡献与问题处理的覆盖映射](../sources/official-docs.md#风格文档与贡献)。
