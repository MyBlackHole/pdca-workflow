# 构建、工具链与依赖

用于构建配置、链接、依赖、运行器和交叉编译任务。先沿用现有构建系统，不根据通用偏好迁移工具、升级语言标准或安装示例依赖。

## 确认目标契约

核对实际目标、语言模式、编译器、链接器、sysroot、架构、libc/ABI、调试/发布配置及最低支持环境。先重现相关诊断或查看既有构建日志，再判断问题来自源码、目标依赖、搜索路径、工具版本还是配置传播。

配置改动尽量作用于相关目标，区分编译、链接、运行时和导出接口依赖；避免用全局开关掩盖一个目标的问题。修正告警根因，不以关闭所有告警或强制转换作为默认修复。

## 环境区别

| 环境 | 需要保持的边界 |
| --- | --- |
| 用户态 C / C 风格 C++ | 现有 Make/CMake/xmake 等入口、C 接口、线程/系统库依赖及语言标准；禁 C++ 库时不加入 fmt、STL 等示例依赖，不自动开启异常/RTTI |
| 内核模块/驱动 | 目标树 Kbuild、版本、配置、符号及工具链契约；不把用户态编译/链接模板和安全参数直接套入内核 |
| Rust 用户态 | 现有 Cargo/工作区、features、目标和依赖政策；不因速查模板加入异步运行库、错误库或全量 features |
| Rust 内核 / no_std | 目标树实际集成和可用类型；不独立替换为普通 std 应用构建 |
| Go / Python | 现有模块/环境、版本约束、原生扩展或 CGO 边界及项目采用的包管理方式；不擅自更换管理器 |

跨平台、交叉编译和静态/动态链接需要核对真实目标工具及 ABI，不能以宿主一次构建代替目标验证。混合 C/C++/Rust 边界的链接、布局和调用约定另读 [用户态适配](../environments/userspace.md)。

## Linux Kbuild 与 Kconfig

仅在目标内核的构建、配置或功能依赖发生变化时采用；语法和可用机制按 [Kbuild/Kconfig 原文](../sources/official-docs.md#构建与配置) 及目标树核对。

- 区分 `bool` 与 `tristate` 的 n/m/y；为新选项提供正确 help、层级和依赖。默认通常为 n，确属官方例外时说明理由；缩进采用 Kconfig 自身规则，不照搬 C 代码。
- `depends on` 限制可选值，`select` 可能绕过被选符号的依赖，不能用来掩盖依赖错误；只在确认其适用条件的基础设施等场景使用。`imply` 是较弱关系，不能代替必需依赖。编译器能力、架构限制及 `COMPILE_TEST` 按真实可编译/可运行条件表达。
- 可选依赖也要核对链接可达性：直接引用模块提供者的 built-in 调用者不能只靠 `IS_ENABLED` 获得定义。按目标树使用条件依赖（如支持时的 `depends on BAR if BAR`，或已有等效形式）与契约一致的桩，排除不兼容的 y/m 组合。若有意让不可达功能消失，应明确行为并论证，不默认以 `IS_REACHABLE` 静默丢弃用户启用的功能。
- `obj-$(CONFIG_X)` 与对象/目录的 built-in、module 归属对应；复合目标核对 `name-y`、条件对象、链接顺序和符号导出，防止目录按 m 进入却留下不参与链接的对象。
- 使用目标树的目录/文件编译变量，如 `ccflags-y`、`CFLAGS_name.o`，注意子目录变量的传播范围。生成文件以 `$(obj)`、源输入以 `$(src)` 等目标树接口定位，验证独立输出目录，不用全局选项掩盖局部错误。

配置组合、modpost、交叉构建和文档检查统一按 [内核构建与文档检查](validation.md#内核构建与文档检查) 取得证据。

## 依赖与可重现性

- 新依赖必须解决当前明确需求，核对已有能力、目标环境、维护/漏洞信息、许可和发布方式；不因示例中存在库就自动添加。
- 版本范围、锁文件、完整性和来源由应用/库的发布政策决定。锁文件帮助重现实际解析结果，不意味着供应链天然安全或所有项目使用同一锁定策略。
- 镜像、代理和私有源优先使用已配置入口，不修改用户级包管理、证书或系统配置来绕过失败。网络或写入权限由执行环境管理，本资料不豁免审批。
- 明确构建缓存、下载、生成文件及测试子进程的写入路径；执行前按 [输出目录约束](validation.md#输出目录约束) 预检。

## 验证与交付

使用相关目标及支持配置验证编译、链接和必要运行路径；只在环境变化、失败或新风险需要时扩大矩阵。静态配置检查、实际编译、链接成功和运行验证分别报告。

安全编译选项及 sanitizer 按目标、编译器、组合兼容性和发布政策选择，不无差别添加全部保护参数。诊断构建与正式测量的区别按 [性能证据与交付](validation.md#性能证据与交付) 处理。

说明修改的目标/配置、原因、实际命令或可定位入口、环境、结果和未覆盖项。构建修复不隐含部署、发布、系统配置修改或外部发送授权。
