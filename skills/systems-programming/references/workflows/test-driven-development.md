# 测试先行与回归循环

用于需要定义新行为或修复可复现缺陷的实现切片，不是所有文档、格式或配置改动的固定仪式。保留用户和项目既有实现，遵守本次授权与可用验证条件。

## 明确边界

从需求和现有调用者找到可观察的公共行为：输入、结果、副作用及失败契约。已有接口和已批准测试边界可以直接采用，无需逐个接缝重复审批；只有确实缺少会影响实现的契约时才请求澄清。

新增或调整断言时，按 [单项测试的质量](testing-strategy.md#单项测试的质量) 设计；需要选择真实依赖或替身时只读 [对应小节](testing-strategy.md#真实依赖与替身)，不展开整套覆盖/CI 规划。

## 一个行为的循环

1. 对新行为或已知缺陷，优先增加最小测试或复现检查。运行后确认它因目标行为而失败，而非语法、依赖、权限或更早的无关检查失败。
2. 在获准范围内实现能满足该行为的最小完整修改；同时落实必要的所有权、错误和退出协议，不能为了“最小”保留已知漏洞或泄漏。
3. 重新运行该检查及相关回归；通过后只清理与本次相关的重复和结构问题，保持契约。每个切片保留有辨别力的断言及实际结果。

## 已有实现与执行限制

已有实现时不删除业务代码来重演先后顺序。若测试已经通过，检查它是否确实覆盖目标路径；可以读取历史版本或做隔离的反例确认辨别力，不制造失败或破坏当前工作区。无法运行旧版本时如实记录缺少修复前运行证据。

检查范围、执行限制及结果报告按 [改动验证](validation.md) 处理。

完整测试体系规划使用 [测试策略](testing-strategy.md)，当前资源风险选择 [改动验证](validation.md)。
