# 源码与规范比对

用于从本地 Linux 主线/目标树提炼工程方法，或判断一个新写法能否用于当前项目。本页维护来源固定与比对方法；具体技术规则按下方主题定位，不仅凭出现次数或某个驱动的写法建立规则。

## 固定真实来源

- 记录源码根、实际远端、分支、完整提交、Makefile 版本及所读文件的本地差异。主线、稳定版和 linux-next 分开识别；发布日期、分支名或“目录叫 linux”不能证明是最新主线。
- 无 Git 的导出目录可以继续研究：记录 Makefile 版本、实际读取的文件/符号和内容哈希，将不可得的远端、提交及本地修改状态标为 unknown。文件哈希固定所读内容，不认证官方来源或整树未修改；不向父目录探测 Git 根或要求补造提交标识。
- “最新”只表示某个核验时刻的远端/本地状态。记录该时刻与实际取得的提交，不能把之后移动的 master 链接当作永久证据。
- 遵守项目允许的读取范围，先选择明确文件；不为找例子扫描无关工作区。浅克隆足以读固定快照，不能据此宣称已调查完整历史。

## 每条结论的证据链

| 证据层 | 要回答的问题 |
| --- | --- |
| 同提交 Documentation | 它是要求、推荐、历史说明，还是专为演示错误的反例？ |
| 声明与实现 | 配置、执行上下文、返回值、排序、取得/释放后的对象存活约束是什么？ |
| 具体调用者 | 为什么选该分配器、锁或清理方式？发布、失败、取消和回收是否完整？ |
| 当前任务 | 上述成立条件是否在目标版本、架构、工具链和用户态/内核态仍成立？ |

优先对比同提交树内文档，再比官方在线资料。发现差异先核对版本、实现与调用路径；不能自动以“代码存在”否定规范，也不能以最新文档要求旧树调用不存在的 API。注明差异、适用条件和未决问题，避免将历史代码的缺陷、特殊上下文或调试用法推广为最佳实践。

文档若为目录页、`toctree` 导航或仅含 `kernel-doc/include` 指令，先固定所需正文的精确路径，再在获准范围内读取对应章节、展开内容或 API 注释。要求完整读取时，覆盖该文档的全部正文；仅读入口、目录或关键词片段不能认定完成。普通按需查询只声明已核对部分；超出获准范围的正文列为未核对，不自动跟随无关链接或扩大读取。

记录“规范位置 → 源码文件/符号/提交或内容哈希 → 观察 → 可迁移原则 → 限制”。保持引用简短，不把内核源码大段复制进技能，也不让技能依赖某台机器上的绝对路径。

## 归纳到未来开发

先解释规范的目的、约束强度和实现的成立条件，再选择迁移方式：

| 结论类别 | 内核态采用方式 | 用户态采用方式 |
| --- | --- | --- |
| 共同原则：所有权、失败路径、预算、共享状态与退出 | 应用到目标子系统的资源及执行上下文 | 应用到进程、线程、fd、缓冲与现有模块；详细设计归 [内存与锁](../principles/memory-and-locks.md) |
| 依赖环境的机制：分配器、锁、原子、异步回调 | 核对目标树版本、GFP/IRQ/RT、LKMM 及具体 API | 按语言、libc/系统及调度契约重新实现；不是宏/函数名逐行替换，见 [用户态](../environments/userspace.md) |
| 内核局部约定：格式、Kbuild、上游贡献 | 仅在相应任务采用对应专题 | 不自动成为用户态项目约定；遵守已确定的项目风格与接口 |

每条新结论给出“解决的问题 → 规范与实际路径 → 内核态方案 → 用户态方案 → 适用限制与验证”。无法迁移的部分写清理由，不强行为两种环境构造相同机制。已有详细规则直接引用其维护位置，不另复制一套清单。

区分规范推荐、明确要求和树内遗留/特例。发现旧 typedef、较长函数、旧宏或一般性推荐与新 helper 共存时，核对具体契约；不能以“源码里有”推广为首选，也不借学习擅自批量改写。宽泛的生命周期表述结合目标引用/移交规范解释，不凭字面强加共享引用或豁免明确的目标要求。

学习“锁外遍历”要逐把确认实际释放与继续持有的锁，并追踪并发删除、回调新增项和重新合并协议；不能把释放队列锁概括为完全无锁。学习内存记账则追踪分配容量、在途持有和析构回收，区分流控阈值与严格配额；源码中的一次阈值检查不自动证明并发硬上限。

## 按主题核对目标契约

| 当前问题 | 技术规则的维护位置 | 源码比对的重点 |
| --- | --- | --- |
| 现代 C 清理机制 | [C 作用域清理](../environments/kernelspace.md#c-作用域清理) | helper 实现、作用域与具体移交/退出路径 |
| mutex、引用及发布 | [锁与生命周期](../environments/kernelspace.md#锁内存序与生命周期) | 内部访问结束点、调用者持有关系与回收依据 |
| GFP、memcg、mempool 与回收进展 | [内核资源](../environments/kernelspace.md#内存资源与设备) | 配置、分配/释放上下文、底层分配器及等待依赖 |
| 队列预算与锁外操作 | [内存与锁设计](../principles/memory-and-locks.md) | 设计条件在已读路径中是否全部成立 |
| 规范与 API 定位 | [官方资料索引](official-docs.md) | 树内文档与匹配版本官方资料的差异 |

主题规则只在对应资料维护，本页记录如何取得证据。源码阅读证明的是已读路径的设计与约束；需要运行结论时另按 [改动验证](../workflows/validation.md) 取得证据。
