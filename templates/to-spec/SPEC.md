## Seam 分析

### 测试接缝
- 在哪个接口/边界层编写测试？（API / 中间件 / 工具函数 / UI 组件）
- 哪些部分已有测试覆盖，哪些需要新增
- Mock/Stub 策略：外部依赖如何隔离（数据库、文件系统、网络）

### 声明的测试接缝
development/bugfix 场景必填（机器可读，供契约测试校验）。每行一个 seam：

```markdown
- seam: <测试文件路径> -> <被测模块路径>
```

契约测试断言：声明的测试文件存在，且其引用的被测模块与声明一致。

### 验收可测性
- 每个用户故事是否有明确的 pass/fail 信号？
- 边界条件和异常路径是否可以独立构造？
- 端到端 vs 单元测试的分层策略
