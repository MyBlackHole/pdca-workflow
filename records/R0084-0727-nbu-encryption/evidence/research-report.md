# NBU 数据加密与存储加密调研报告

## 调研目标
系统梳理 NetBackup 10.5 的数据加密（传输中加密）和存储加密（静态加密）的实现方式、配置入口、密钥管理机制及适用场景。

## 方法
- 阅读 NetBackup 10.5 安全和加密指南（`nbu-doc` KB）
- 阅读 NetBackup 重复数据删除指南（MSDP 加密章节）
- 阅读 NetBackup 管理指南（加密配置和命令参考）
- 阅读 NetBackup Web UI 管理指南（加密配置界面）

## 发现

### 1. 加密分类体系

NetBackup 的加密分为两大类：

```
NetBackup 加密
├── 传输中数据加密（DTE — Data Transfer Encryption）
│   └── 保护数据在网络传输中的安全性（9.1+）
└── 静态数据加密（At-Rest Encryption）
    ├── 客户端加密 — 客户端侧加密文件数据
    ├── MSDP 加密 — 重删池数据加密
    ├── 磁带驱动器加密 — 基于硬件的磁带加密
    ├── 云加密 — 上传到云存储前加密
    └── AdvancedDisk — 高级磁盘加密
```

### 2. 传输中数据加密（DTE）

**原理**：对客户端↔介质服务器、介质服务器↔介质服务器之间的数据通道（Tar 流、目录库信息）进行 TLS 加密。

**版本要求**：NetBackup 9.1+ 可用，10.0+ 默认自动启用。

**DTE 三种配置层级**：

| 层级 | 说明 | 设置方式 |
|------|------|----------|
| 全局 DTE 模式 | 域级开关 | Web UI：安全→全局安全→安全通信 |
| 客户端 DTE 模式 | 逐客户端覆盖 | 客户端属性→加密 |
| 映像 DTE 模式 | 逐备份映像覆盖 | `bpimage -update -image_dtemode` |

**全局 DTE 模式值**：

| 模式 | 行为 |
|------|------|
| `Preferred Off` | 域中禁用 DTE，客户端可覆盖 |
| `Preferred On`（默认） | 对 9.1+ 客户端启用 DTE |
| `Enforced` | 强制执行 DTE，关闭/低于 9.1 的主机作业失败 |

**客户端 DTE 模式值**：`Off` / `On` / `Automatic`（10.0+ 默认）

**加密算法**：TLS 加密通信，证书基于主机 ID，私钥以 AES-256-CBC 加密存储，密钥密码以 AES-256-GCM 加密。

**注意事项**：
- DTE 决策由 全局模式 + 客户端模式 + 映像模式 + `DTE_IGNORE_IMAGE_MODE` 共同决定
- 9.1 以下版本主机参与时 DTE 自动降级（不加密或失败，取决于配置）
- `nbseccmd` 命令可配置介质服务器级别的 DTE

### 3. 静态数据加密

#### 3.1 客户端加密（Client Encryption）

**原理**：备份数据在客户端本地加密后再发送到介质服务器，介质服务器和存储端只处理密文。

**工作方式**：
1. 客户端使用 `bpkeyutil` 创建基于密码的密钥文件
2. 策略中启用"加密"属性
3. 备份时客户端用密钥文件中的最新密钥加密每个文件的数据（不加密文件名和属性）
4. 备份映像标记加密标志

**加密算法**：

| 算法 | 说明 |
|------|------|
| AES-128-CFB | **默认**，推荐 |
| AES-256-CFB | 更高安全等级 |
| BF-CFB | 旧式 Blowfish |
| DES-EDE-CFB | 旧式 3DES |
| 40/56 位 DES | 旧式（不推荐） |

**配置入口**：
- 服务器端：主机属性→客户端→加密（Web UI 或 `bpinst_crypt`）
- 客户端：`bp.conf` 中 `CRYPT_KIND=STANDARD` + `CRYPT_CIPHER` 指定算法
- 密钥管理：`bpkeyutil` 创建密钥文件

**密钥管理**：
- 密钥文件本地存储，多密钥（最新密钥用于加密）
- 密钥变更后，旧密钥仍可用于解密已有数据
- 群集环境下所有节点须有相同密钥文件

#### 3.2 MSDP 加密（重删池加密）

**原理**：对介质服务器重复数据删除池（MSDP）中的数据进行 AES-256-CTR 加密。

**加密强度**：
- MSDP：AES-256-CTR
- 旧 Blowfish 已被 AES 替换

**密钥架构（信封加密）**：
```
数据 → 数据加密密钥（DEK）加密 → 密文
DEK → 密钥加密密钥（KEK）加密 → 加密的 DEK
KEK 由 KMS 管理
```

**配置方式**：
- Web UI：配置 MSDP 存储时启用加密
- 涉及 KMS：可用 NBKMS（内置）或外部 KMS（KMIP 协议）
- 加密爬虫（Encryption Crawler）：对已有未加密数据扫描并加密

**兼容性**：MSDP 加密不同于基于策略的客户端加密，两者可独立配置。

#### 3.3 磁带驱动器加密

**原理**：利用磁带驱动器自带的硬件加密能力，数据写入磁带前由驱动器硬件加密。

**卷池命名约定**：卷池名称必须以 `ENCR_` 为前缀（如 `ENCR_P1`），NBU 据此识别启用加密。

**密钥管理**：
- 卷池级密钥组：磁带卷池的密钥组名称必须匹配 `ENCR_` 前缀
- 外部 KMS 中创建密钥，设置 `x-keygroup` 属性匹配卷池名称
- 设置 `x-application=NetBackup` 标识密钥归属

**加密算法**：
- 磁带驱动器加密：AES-256（基于硬件）
- 基于软件的加密：AES-256-CFB（旧式云连接器和高级磁盘加密）

#### 3.4 云加密

**原理**：数据上传到云存储之前进行加密控制。

**存储服务器属性**（`_crypt` 前缀）：
| 属性 | 行为 |
|------|------|
| `_crypt` | 上传前用 AES-256 加密 |
| `_cryptc` | 压缩+加密后上传 |

**密钥管理**：依赖 KMS 服务器，存储服务器属性中配置 `CRYPT:KMS_SERVER` 指向 KMS 主机。

**配置入口**：`nbdevconfig` 命令设置存储服务器属性。

#### 3.5 AdvancedDisk 加密

**原理**：对 AdvancedDisk 存储类型的数据进行加密。

**加密方式**：
- 旧式云连接器和高级磁盘加密：AES-256-CFB
- 由 KMS 管理密钥

### 4. 密钥管理服务（KMS）

#### 4.1 NBKMS（NetBackup KMS — 内置）

**组件**：
- `KMS_DATA`：密钥存储文件（含密钥组和密钥记录）
- `KMS_KPKF`：密钥保护密钥文件（加密密钥记录的密码部分）
- `KMS_HMKF`：主密钥文件（加密密钥存储文件全部内容）

**三文件层级保护**：
```
密钥存储文件（KMS_DATA）
   ↓ 由 HMK 加密
HMK 文件（KMS_HMKF）
   ↓ 由 KPK 加密  
KPK 文件（KMS_KPKF）
```

**命令**：`nbkmscmd`、`nbkmsutil`

#### 4.2 外部 KMS（EKMS）

**协议**：KMIP（密钥管理互操作协议）

**认证方式**：证书认证，主服务器出站连接到外部 KMS 的 KMIP 端口

**密钥属性**：

| 属性 | 说明 |
|------|------|
| `x-keygroup` | 密钥组名，磁带卷池须以 `ENCR_` 开头 |
| `x-application` | 固定为 `NetBackup` |
| `x-comment` | 备注 |

**操作命令**：`nbkmiputil`（验证、列出、获取属性、设置属性）

#### 4.3 密钥轮换
- 新密钥创建后用于新备份
- 旧密钥保留用于解密已有数据
- 密钥变更后须重新加密已加密数据（解密→用新密钥重新加密）

### 5. 适用场景对比

| 加密方式 | 保护范围 | 性能影响 | 密钥管理 | 推荐场景 |
|----------|----------|----------|----------|----------|
| **DTE** | 传输链路 | 低（TLS 卸载） | 证书（自动管理） | 必须启用 |
| **客户端加密** | 数据从产生到存储全程 | 中（客户端 CPU） | 本地密钥文件 / KMS | 高安全需求 |
| **MSDP 加密** | 重删池静态数据 | 低（存储层） | NBKMS / 外部 KMS | MSDP 存储必配 |
| **磁带加密** | 磁带介质 | 无（硬件卸载） | KMS（卷池级密钥组） | 磁带场景 |
| **云加密** | 云存储 | 低 | KMS | 云存储场景 |
| **AdvancedDisk** | 高级磁盘 | 中 | KMS | 通用磁盘加密 |

### 6. 密码类型汇总

| 用途 | 算法 |
|------|------|
| DTE（传输） | TLS（证书） |
| 客户端加密（默认） | AES-128-CFB |
| 客户端加密（强） | AES-256-CFB |
| MSDP 加密 | AES-256-CTR |
| 磁带硬件加密 | AES-256 |
| 旧式云/高级磁盘 | AES-256-CFB |
| 证书私钥存储 | AES-256-CBC |
| 私钥密码存储 | AES-256-GCM |

### 7. 组合使用建议

1. **DTE 必须启用**（Preferred On 或 Enforced）— 最低安全基线
2. **敏感环境**加配客户端加密（AES-256-CFB），实现端到端加密
3. **MSDP 存储**必须启用 MSDP 加密（AES-256-CTR + 信封加密）
4. **磁带**通过 `ENCR_` 前缀卷池启用硬件加密，外部 KMS 管理密钥
5. **密钥统一管理**通过 NBKMS 或外部 KMIP KMS（如 HashiCorp Vault、Azure Key Vault）
6. **避免**旧式加密（40/56 位 DES、Blowfish）

## 结论与建议

NetBackup 10.5 提供了分层加密体系，从传输层（DTE）到存储层（客户端/MSDP/磁带/云）覆盖完整。密钥管理支持内置 NBKMS 和外部 KMIP KMS 两种方式，适用于不同安全等级需求。

- 最小安全配置：DTE Enforced + MSDP 加密
- 增强配置：+ 客户端加密 (AES-256-CFB) + 外部 KMS 管理
- 合规配置：+ 密钥轮换策略 + 加密爬虫全量扫描
