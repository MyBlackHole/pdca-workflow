    【B-T0356】libobk: 修复 mTLS 握手栈溢出与帧长度必败, 1.0.0.0 -> 1.0.0.1
    
    问题描述: 开启 SBT_MTLS_ENABLE=1 时 libobk 客户端与 FileTransferAgent 的 mTLS 握手永远失败，且存在内存安全隐患。复现步骤: 1) 服务端配置证书目录并启动 FileTransferAgent 2) 客户端设置 SBT_MTLS_ENABLE=1 发起备份 3) 握手必败断连。
    原因分析: 双端握手响应体长度契约漂移——客户端 sbt_session_client_init 校验 body 长度 sizeof(resp)-sizeof(activeioHeader)=175 字节，服务端 sbt_session_server_handshake 发送 h.bytes=4+201=205 字节，175!=205 导致校验必败；同时服务端从 resp[204] 缓冲区发送 205 字节越界读 1 字节；客户端以 body 大小(205)缓冲区承接 header+body 总长(235)读取造成栈溢出 30 字节。长度字面量双端各写一份、无真实往返测试覆盖所致。
    解决方案: protocol.h 新增 OBK_HS_RESP_BODY_SIZE 单点宏(4+OBK_HS_MAX_NAME)，双端校验/发送共用；客户端接收缓冲区扩为 sizeof(activeioHeader)+OBK_HS_RESP_BODY_SIZE 并以 _recv(expect=sizeof(resp)) 读满；body 前移改用 memmove 消除重叠拷贝 UB；ca_cn 提取改用 OBK_HS_MAX_NAME；两握手函数去 static 并在头文件声明供测试链接；删除 result 死分支三元表达式；客户端握手 6 个失败分支补分类 ErrorLog(role/stage/cert_dir/ca_cn/algorithm)；libobk_session_test 新增 socketpair 级真实 TLS 升级往返用例(fork 服务端隔离全局态，升级后互发帧验证链路)。
    影响范围: 仅 libobk 的 SBT mTLS 握手路径(libobk.c 客户端/oracleCmdTbl.c 服务端)；明文模式零握手直通不受影响；dmsbtex/rdbcomm/rpc 不涉及。风险等级低——旧代码 mTLS 本就不可用，无兼容性损失。
    性能影响: 无。仅常量替换与一次 memmove(234 字节)，握手一次性开销可忽略。
    复现步骤: 见问题描述；自动化复现: xmake build libobk_session_test && xmake run libobk_session_test。
    测试验证: 新增往返用例覆盖 mTLS 升级成功路径(tssl 断言+echo 链路)，变异测试(回退发送长度至 205)确认用例判别力；xmake run libobk_session_test/libobk_protocol_test/rdbcomm_handshake_session_test/rpc_own_handshake_test/dmsbtex_session_test 全绿；ASan 构建运行无内存错误报告。
    相关 Issue: PDCA T0355(C1/C2 发现)、T0356(修复任务)；知识库 knowledge/tls/handshake-dup-impl-length-contract.md。
    风险评估: 低。新增宏与去 static 导出不改变既有调用方 ABI 行为；往返测试防止未来契约再漂移。缓解: ASan+变异测试双重验证。
    回滚方案: revert 本次 commit 即恢复原状(恢复后 mTLS 握手回到不可用状态，明文模式不受任何影响)。
    版本变更: xmake.lua: libobk_version 1.0.0.0 -> 1.0.0.1
