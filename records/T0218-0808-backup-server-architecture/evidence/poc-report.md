## 2. 逐工具 POC 结果

### 2.1 rsync 3.4.3（同步工具）

| 指标 | 结果 |
|------|------|
| 全量备份 | 499M → 499M，耗时 1.04s |
| 增量备份 | 变更 209 文件，仅传 8.4MB（Total transferred 8,448,889B），耗时 0.10s |
| 去重 | 无（文件级，磁盘占用 = 源大小） |
| 删除同步 | **默认不删源端已删除文件**（需 `--delete`；首次验证残留 200 文件） |
| 恢复正确性 | ✓ `--delete` 后 9875 文件与源完全一致 |
| 权限保留 | ✓ 755/600 正确保留 |

**关键发现**：rsync 是文件级同步工具，无版本管理、无内容去重、不默认镜像删除。
验证了调研结论「rsync 只做同步，版本管理需上层工具配合」（`--link-dest`/快照）。

### 2.2 Borg 1.4.5（CDC 去重备份）

| 指标 | 结果 |
|------|------|
| 仓库初始化 | `--encryption=none`（明文） + repokey-blake2（加密）双测 |
| 全量备份 | 483MB 原始 → 压缩 272MB → **去重 270MB**，耗时 2.97s |
| 增量备份 | 486MB → **新增仅 8.11MB**（跨版本去重率 98.3%），耗时 2.35s |
| 快照/版本 | ✓ archive1/archive2 双快照，`borg list` 可见 |
| PITR | ✓ 恢复 archive1（10072 文件）与 archive2（9875 文件）均完整 |
| 加密 | ✓ repokey-blake2，文件无明文泄漏 |
| 恢复耗时 | 2.49s（9875 文件） |

**关键发现**：CDC（内容定义分块）+ 全局去重效果显著——增量场景仅新增 8.11MB。
对比 rsync 的 8.4MB（文件级），Borg 在**数据内容**层面去重（哪怕文件路径/结构变化）。

### 2.3 Restic 0.19.1（快照式去重备份）

| 指标 | 结果 |
|------|------|
| 仓库初始化 | 默认 AES-256 加密 |
| 全量备份 | 461MB → **260M**（加密+压缩+去重），耗时 2.24s |
| 增量备份 | 464MB → 仓库仅增 9M，耗时 1.74s |
| 快照/版本 | ✓ 双快照（090618f1 / 7e7da0ed） |
| PITR | ✓ 首快照（10072 文件）与最新（9875 文件）均完整还原 |
| 加密 | ✓ pack 文件无明文泄漏 |
| 恢复耗时 | 1.81s（9875 文件） |

**关键发现**：与 Borg 同级去重能力（461MB→260M），但**默认即加密**（无需手动配置），
后端抽象统一（支持 S3/SFTP/REST 等），恢复语法更直接。

### 2.4 Rclone 1.75.0（云端/远程同步）

| 指标 | 结果 |
|------|------|
| 全量 sync | 499M → 499M（无去重，镜像同步） |
| 增量 sync | 自动识别变更，**默认删除目标多余文件**（镜像语义） |
| 恢复（copy） | ✓ 9875 文件完全一致 |
| 加密（crypt） | ✓ 远端文件名密文化（`11n02hcn...`），解密恢复内容一致 |
| 校验 | ✓ `rclone check` 0 differences |

**关键发现**：rclone 是同步/迁移工具，非备份版本管理。但 crypt 加密层 + 后端抽象
（几十种存储）使其成为「备份产品的存储传输层」首选。

### 2.5 Duplicity 3.1.0（加密增量备份）

| 指标 | 结果 |
|------|------|
| 全量备份 | 261M（RSA-2048 gpg 加密），耗时 10.2s（gpg 加密开销） |
| 增量备份 | 需**同一源路径**（路径变化报错）；增量后仅增 5M，耗时 1.14s |
| 加密 | ✓ `PGP RSA encrypted session key`，无明文泄漏 |
| 恢复 | ✓ 9875 文件完全一致，权限保留 |
| 增量链 | 全量 + 2 个 inc 卷（manifest/vol 分离） |

**关键发现**：Duplicity 用 gpg（RSA）加密 + librsync 差分增量。增量要求源路径不变
（实用特性，但要求一致性管理）。加密强度高但 gpg 加解密性能开销大（全量 10.2s vs
Borg 2.97s）。

## 4. 对架构设计的验证与修正（回归调研结论）

| 调研结论 | POC 验证 | 结论 |
|---------|---------|------|
| D1: CDC 去重为最佳基线 | ✓ Borg/Restic 均显著去重 | **确认** — 增量 8.11M vs 文件级 8.4M 相当，但 CDC 对内容级变化更鲁棒 |
| D3: 快照=manifest 原子提交 | ✓ Borg/Restic 快照可 PITR | **确认** — 双快照回滚实测成功 |
| D2: 先压缩后加密 | ✓ Borg/Restic 加密仓库体积≈明文仓库 | **确认** — 压缩收益在加密仓库仍体现 |
| 快照式 > delta 链式 | ✓ Duplicity 增量链恢复需重放；Borg/Restic 快照直接 PITR | **确认** — 避免长 delta 链重放设计正确 |
| 默认加密应内置 | Restic 默认加密最省心；Duplicity gpg 最重 | **修正** — 建议仿 Restic 默认加密 + 内置密钥派生（非外部 gpg） |
| 服务端后端抽象 | Rclone crypt + 多后端验证可行 | **确认** — 设计 D8 的后端抽象可行 |

**新增发现（补充调研）**：
1. **加密性能差异显著**：gpg(RSA) 加密全量 10.2s vs Borg 内置 2.97s → 自研产品应内置
   AES 加密层而非依赖外部 gpg。
2. **删除语义差异**：rsync 需 `--delete`、rclone 默认删 → 产品需明确删除策略配置。
3. **源路径一致性**：Duplicity 强制增量源路径不变 → 产品需用快照式避免此限制。
4. **恢复性能**：CDC 备份恢复（Borg 2.49s/Restic 1.81s）优于增量链重放（Duplicity），
   因无需顺序重放多个 delta 卷。
