# Writing Great Skills — PDCA 版

PDCA 技能的目标是**可预测性**：AI 每次执行同一技能时遵循**同一过程**（不是输出相同结果）。

## 信息层级

一条信息的"阅读优先级"决定它的存放位置：

| 层级 | 位置 | 用途 |
|------|------|------|
| **步骤** | `SKILL.md` 顶部 | 按顺序执行的操作，每条有可检查的完成标准 |
| **引用** | `SKILL.md` 靠后 | 定义、规则、事实——按需查阅 |
| **外部引用** | 独立的 `.md` 文件 | 只有特定分支需要的细节，通过**上下文指针**加载 |

**渐进披露**：所有分支都需要的放顶层，只有部分分支需要的推到外部引用。

## 极简原则

1. **每行必须通过"必要性测试"**：去掉这行，AI 的行为会变差吗？不会 → 删掉。
2. **无操作（no-op）**：AI 默认就会做的不用写。"要全面"、"要仔细"都是 no-op。如果要约束，用更强的词（"relentless" 比 "thorough" 好）。
3. **否定不如肯定**："不要做 X" 不如 "做 Y"。否定会让模型更关注 X。
4. **单点真实（SSOT）**：同一含义只在一个地方定义。改行为只改一个文件。
5. **去沉积**：定期检查每个句子是否还相关。不相关的立即删——沉积是技能文件的默认命运。

## user-invoked vs model-invoked

| | user-invoked | model-invoked |
|--|-------------|---------------|
| **标记** | `disable-model-invocation: true` | 无此标记 |
| **谁调用** | 仅用户打字 | AI 自动 + 用户均可 |
| **上下文负载** | 零 | 描述字段常驻窗口 |
| **内容** | 薄壳：描述 + 委托调用 | 逻辑体：步骤 + 引用 |

**规则**：
- 用户手动触发的技能 → `disable-model-invocation: true`，只需描述和委托
- AI 需要自主触发的技能 → model-invoked，描述要写清楚触发条件
- user-invoked 可以调用 model-invoked，但不可调用其他 user-invoked

## 何时拆分

| 场景 | 拆法 |
|------|------|
| 有独立的触发词 | 拆为 model-invoked 技能 |
| 另一个技能需要调用它 | 拆为 model-invoked 技能 |
| 步骤太长导致 AI 想跳步 | 拆分步骤序列（避免过早完成） |
| 内容是纯参考 | 推到外部引用文件 |

## 完成标准

每个步骤必须有**可检查的完成标准**——AI 能明确判断"做完/没做完"。模糊的完成标准会导致 AI 过早收工。

好的："所有 5 条证据都在 manifest 中登记"  
不好的："完成证据登记"

## 本工作流特有规则

1. **flow 文件**（flow-plan/do/check/act）负责编排步骤顺序，细节委托给 `skills/`。flow 文件不内联技能逻辑。
2. **技能文件**（skills/）负责具体行为。model-invoked 技能可被任何 flow 或技能引用。
3. **记录文件**（records/）不可变，不在其中修改已有的证据。
4. **描述字段**：model-invoked 的描述要包含触发条件短语（"Use when..."、"Mentions..."），帮助 AI 决定何时加载。

## 失败模式

| 模式 | 症状 | 修复 |
|------|------|------|
| **过早完成** | AI 跳过步骤细节就推进 | 收紧完成标准 / 隐藏后续步骤 |
| **重复** | 同一含义出现在多处 | 合并到 SSOT，删除重复 |
| **沉积** | 新增容易、删除不敢 | 定期逐行质问必要性 |
| **膨胀** | 技能文件太长 | 将引用推到外部文件 |
| **无操作** | 写了 AI 默认已做的 | 删除或换成更强的约束 |
| **否定** | "不要 X" 反而激活 X | 改写为"做 Y"
