# MySQL 在线备份 → 恢复一致性 → 物理直读转换 — 验证记录

## 场景
- 在线备份(运行中复制 .ibd), 含活跃事务未提交行
- 恢复方式: 干净关闭(shutdown) 等价恢复完成态(检查点+回滚)

## 关键发现
1. **运行中复制 .ibd 直接转换**: 混入未提交事务数据
   - 第一次实验(poc_orders): rows=1000530 vs 基线 1000000 (+530 未提交)
   - 第二次实验(poc_bk_clean): rows=10500 vs 实际 10000 (+500 未提交)
2. **干净关闭后(恢复完成)转换**: 与 SQL 全量逐字段对照 PASS
   - poc_bk_clean: 10500 行 diff=0 PASS
3. **边界**: 干净关闭态仍可能残留回滚未 purge 的行(第一实验中 30 行 id 1000617-1000920
   已回滚事务残留, SQL 中不存在), 说明 MySQL 恢复一致性依赖:
   - redo 前滚(已提交未刷盘) + undo 回滚(未提交) + purge(已回滚行的物理清理)
   - 三者缺一不可; 自研离线重放需覆盖 trx_sys 判定

## 结论
- 借力工具(xtrabackup --prepare)可完成恢复; 自研离线 redo/undo 重放是后续工作
- mysqlbin 仅在恢复完成后(干净一致态)转换结果正确
