# MySQL 运行中复制 .ibd 直接转换 — 行数差异实证

- 场景: 运行中复制 .ibd（模拟在线备份）, 含 2 个活跃事务(1000+500 未提交行)
- mysqlbin 直接转换运行中复制的 ibd: **rows=1000530**
- 基线(正常关闭快照): **rows=1000000**
- 差异: **+530 行未提交事务数据**（活跃事务行无 delete-mark, 被当作可见行读出）
- 结论: **MySQL 运行中备份产物直接转换会混入未提交行, 必须恢复到一致态**
- 边界: 恢复一致性需 redo 前滚 + undo 回滚 + trx_sys 判定（复杂, 调研报告详述）

## 干净对照实验 (poc_bk_clean 全新表)
- 建表 10000 行 + 活跃事务 500 行(未提交) → 运行中复制 ibd
- mysqlbin 转换运行中复制 ibd: **rows=10500** (混入未提交 500 行)
- 事务提交后干净关闭(shutdown) 复制 ibd: **rows=10500** (等价恢复后一致态)
- SQL 全量逐字段对照 (10500 行): diff=0 **PASS**
- 结论: 恢复完成(干净关闭态)后 mysqlbin 转换与 SQL 一致; 运行中备份产物在恢复前会混入未提交数据
