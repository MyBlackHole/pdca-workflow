# 场景13 AEAD 认证加密

**验证**：AES-128-GCM（OpenSSL EVP）vs ChaCha20-Poly1305（libsodium）——往返还原、篡改检测、吞吐。数据 128MB。

## 原理

AEAD（Authenticated Encryption with Associated Data）在**机密性**之外同时提供**完整性认证**。对比场景07 的 XOR 加密——XOR 只有机密性，密文被改无从发现；AEAD 的密文或 tag 任何 1 字节被翻转，解密即失败。

```
                    ┌──────── 加密端 ────────┐      ┌──────── 解密端 ────────┐
明文 ──► 加密 ──► 密文 ──► 密文 + MAC tag     密文+tag ──► 认证+解密 ──► 明文
         │ 机密性              │                    │  (tag 校验)
         │                     └── 传输/存储 ──►     │
                                                    └─ 任一 bit 被改 → 认证失败, 拒绝输出
```

| 算法 | 加密引擎 | 认证 | 硬件加速 | 特性 |
|------|---------|------|---------|------|
| AES-128-GCM | OpenSSL | GMAC | AES-NI | 硬件普遍、生态成熟 |
| ChaCha20-Poly1305 | libsodium | Poly1305 | 纯软件 | 无 AES 指令的 CPU 上更稳、抗时间侧信道 |

## 实测（本机 128MB）

| 算法 | 还原 | 篡改检出 | 吞吐 |
|------|------|---------|------|
| AES-128-GCM | 一致 ✓ | 密文/tag 1 字节翻转均认证失败 ✓ | ~670 MB/s |
| ChaCha20-Poly1305 | 一致 ✓ | 密文 1 字节翻转认证失败 ✓ | ~380 MB/s |

## 结论

- **AES-128-GCM 约 1.76x 快于 ChaCha20-Poly1305**（本机有 AES-NI）。备份主力吞吐场景优先 AES-GCM。
- ChaCha20-Poly1305 是软件实现、无硬件依赖且抗时间侧信道，适合**无 AES-NI 的环境**（部分 ARM、老 x86）或**对侧信道敏感**的场景。
- 两者都做到"密文任意 1 字节翻转 → 认证 100% 失败"，补齐了场景07 XOR 加密缺认证的短板。备份数据完整性与机密性同等重要——**生产加密必须用 AEAD**。
- nonce 唯一性关键：重复 nonce 会让 GCM/ChaCha 认证失效。备份场景用单调计数器或每文件随机 nonce。

## 断言

- 两算法往返还原一致；密文/tag 翻转 1 字节 100% 认证失败；吞吐均 > 100 MB/s。
