# 场景14 高速哈希选型

**验证**：BLAKE3（libblake3）vs XXH3（libxxhash）vs SHA-256（OpenSSL）——1GB 大块吞吐 + 16KB 去重块指纹 + 官方向量正确性。

## 原理

去重/校验链路的核心是**块指纹**：对每个数据块算哈希，作为去重索引键。算法分三类：

```
        ┌─────────────── 安全哈希（防伪造） ───────────────┐
        │  BLAKE3：现代多线程树哈希，加密强度 + 极速       │
        │  SHA-256：密码学标准，慢、有 SHA-NI 硬件加速     │
        └───────────────────────────────────────────────────┘
        ┌─────────────── 非加密哈希（仅查重） ─────────────┐
        │  XXH3：极速，无加密强度，用于去重位图/布隆/临时键 │
        └───────────────────────────────────────────────────┘
```

备份链路两处用哈希：
- **去重指纹**：块内容 → 指纹 → 索引查重。要求**快**（每块都算），安全强度可放宽（防碰撞误判即可，布隆假阳率兜底）。
- **完整性校验**：备份/恢复端核对数据未被篡改。要求**安全**（防攻击者伪造匹配的块）。

## 实测（本机 1GB，SHA-NI 已启用）

| 算法 | 1GB 吞吐 | 相对 SHA-256 | 16KB 块指纹 | 用途 |
|------|---------|-------------|------------|------|
| XXH3 | ~12–13.7 GB/s | ~7.0x | — | 非安全去重索引 |
| BLAKE3 | ~3.3–3.6 GB/s | ~1.8x | ~3.0–3.6 GB/s | 安全指纹（去重+校验兼顾） |
| SHA-256 | ~1.85 GB/s | 1.0x | — | 安全标准/合规 |

（BLAKE3 空串官方向量 `af1349b9…3262` 匹配 ✓）

## 结论

- **XXH3 最快（~7x SHA-256）**，但非加密。适合**去重热路径的快速键**（布隆过滤器、哈希表探测、临时校验），配合后续强校验消除误判——与场景05 的"弱+强双校验"同构。
- **BLAKE3 兼顾安全与速度**（~1.8x SHA-256，且多线程可再放大）。做**正式指纹/完整性校验**时首选，替代 sha256 以换取吞吐。
- **SHA-256 仅保留**在需要标准合规（审计、互操作）的场景。
- 16KB 块指纹 BLAKE3 仍达 ~3 GB/s（~3.5 亿块/小时），单机去重吞吐不受哈希瓶颈限制。

## 断言

- BLAKE3 与 XXH3 大块吞吐均 > SHA-256；BLAKE3 空串输出等于官方向量 `af1349b9f5f9a1a6a0404dea36dcc9499bcb25c9adc112b7cc9a93cae41f3262`。
