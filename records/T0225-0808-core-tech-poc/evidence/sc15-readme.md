# 场景15 布隆过滤器去重索引

**验证**：自研布隆过滤器（位数组 + k 双哈希派生），100 万条指纹。验证无假阴性、假阳率≤理论上限、内存节省、吞吐。

## 原理

备份去重第一步是"这个块我见过吗？"——用指纹查索引。两条路：

```
精确哈希表（内存 O(n)）              布隆过滤器（内存固定）
┌──────────────┐                     ┌──────────────────┐
│ 指纹1 → 槽0   │   1M 条 × 64B      │ 位数组 m 个 bit    │
│ 指纹2 → 槽1   │  = 61 MB          │ 插入: k 个哈希置位  │
│ 指纹3 → 槽2   │                    │ 查询: k 位全 1 则  │
│ …            │                    │       "可能在"    │
└──────────────┘                     └──────────────────┘
  准确、可删、占内存                   不占指纹原文、可假阳
                                       假阳率 = (1-e^(-kn/m))^k
```

布隆的本质是**用假阳率换内存**：不存指纹原文，只存"位痕迹"。
- **无假阴性**：插入过的元素 100% 命中（这是布隆的关键性质）。
- **假阳率可控**：k 个位都凑巧被置 1 才误报，概率随 m/n（位/元素）指数下降。
- **最优 k = (m/n)·ln2**，此时假阳率 ≈ (0.6185)^(m/n)。

去重场景使用方式：布隆命中 → 再用哈希表/磁盘二次确认（消除假阳），相当于场景05 "弱+强双校验"的索引版。

## 实测（N=100 万，k=6，m/n=8）

| 指标 | 实测 | 理论 | 结论 |
|------|------|------|------|
| 已插入命中率 | 100% | — | 无假阴性 ✓ |
| 假阳率 | 2.16% | 2.16% | 完全吻合 ✓ |
| 内存 | 1.0 MB | — | vs 精确表 61 MB = **1/60** ✓ |
| 插入吞吐 | 75.6 M/s | — | 热路径不瓶颈 |
| 查询吞吐 | 2.4 M/s | — | 随机位访问 |

## 结论

- **内存节省 60x**：1M 条指纹，布隆 1MB vs 精确哈希表 61MB。索引放内存越快，这个差距是去重系统可扩展性的关键。
- **假阳率与 m/n 强相关**：m/n=8 → 2.16%（本场景实测吻合理论），m/n=16 → 0.05%，m/n=32 → 2×10⁻⁶。假阳率每降 2 个数量级只需翻倍位数组。
- **无假阴性是硬保证**：可安全用于"块未见过"的快速否定；命中后必须二次确认（哈希表或读磁盘指纹）来排除假阳。
- **吞吐瓶颈在查询的随机位访问**：插入受益缓存局部性达 75.6M/s，查询因位分布随机受限于内存延迟；真实去重可用 CPU 缓存友好分片（每个片独立布隆）缓解。
- 典型方案：**内存布隆做第一层否定过滤 + 磁盘/哈希表做确认**，把 60x 内存换来的空间用于缓存更多索引。

## 断言

- 已插入元素 100% 命中（假阴性=0）；实测假阳率 ≤ 理论上限 ×1.5 + 容差；布隆内存 < 精确哈希表内存。
