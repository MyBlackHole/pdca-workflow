# 场景16 帧协议多路复用

**验证**：自研帧协议（magic+len+sid+type+crc 16B 头）在单连接上多路复用 4 逻辑流——粘包/半包重组、流数据隔离与顺序、帧头篡改检出。经 socketpair 传输。

## 原理

备份引擎要在**一个 TCP 连接**上并发跑多个备份/恢复任务（多个客户端、多个文件、多任务），否则每任务一条连接 → 连接数爆炸 + 相互独立限流困难 + 头阻塞。多路复用（HTTP/2 思路）用**流 ID** 把单连接切成逻辑流：

```
单 TCP 连接
────────────────────────────────────────────────────────────
│ 流0帧 │ 流1帧 │ 流0帧 │ 流2帧 │ 流1帧 │ 流3帧 │ … │ 流0帧 │
────────────────────────────────────────────────────────────
         ▲  帧交织：同一连接上不同流的帧交叉发送

帧格式（16B 固定头）:
[magic 4B "FSR1"][len 4B][sid 2B][type 1B][flags 1B][crc 4B][payload len B]
 └ 魔数对齐 ┘ └payload长┘ └流ID┘ └0数据/1EOF┘        └帧头CRC┘
```

拆帧器用**累积缓冲 + 状态机**：
- **粘包**（一次 read 多帧）→ 循环拆出全部帧
- **半包**（帧被 TCP 切散）→ 累积到缓冲，凑齐一帧再拆
- **帧头 CRC** 覆盖 magic..flags 12B，防错位/损坏

## 实测（socketpair，4 流 × 2000 块 × 64B）

| 验证点 | 结果 |
|--------|------|
| 各流收帧数 | 4 流均 2000/2000 完整 ✓ |
| 流间数据隔离 | 无串流（内容按流校验全对）✓ |
| 流内顺序 | 无丢序 ✓ |
| 粘包/半包重组 | 模拟 1–5 字节小写全通过 ✓ |
| 帧头篡改检出 | 改 sid 1 字节 → CRC 检出 ✓ |

（吞吐刻意低：发送端按 1–5 字节小块写入模拟极端半包，验证拆帧健壮性，非协议上限。真实场景按 MTU 写帧吞吐可达 GB/s 级。）

## 结论

- **流 ID 多路复用**是单连接高并发备份的基础：一连接承载多任务，节省 fd、统一限流（配合场景10）、避免每任务建连握手开销。
- **帧头固定 16B + payload 可变**：平衡拆帧简单性与传输效率；大流量下 payload 不再加 CRC（每块已有指纹校验兜底），只在帧头做 CRC 防错位。
- **累积缓冲状态机**同时处理粘包/半包，是 TCP 流式传输的通用解法——与场景03 "残留数据+FIN" 判定的收口设计互补。
- 生产可扩展：sid 空间、type 语义（数据/EOF/控制）、帧级流量控制（按流窗口）均可在此骨架上加。

## 断言

- 各流收帧数与发送数一致、内容逐字节一致（无串流/丢序）；帧头 CRC 对篡改的 sid 检出。
