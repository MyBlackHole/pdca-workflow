# 四种复用返工演练（未运行生产任务）

## 1. 过期基准导致覆盖风险

前置：A/B从r1各生成候选。A完成独立审查并真实发布r2。B已等待取得锁。

先红：用B的base=r1提交，预期stale_base，r2字节/head和原授权不变。若系统接受，应保留错误提交与所有受影响对象，先控制采用。

修复：读取r1/r2/B做语义三方合并，冲突明确到constraint/case；形成B2新candidate、payload、manifest、新审查和授权。若原B已进入Check，新attempt/新Agent，不能偷回Do。

后绿：对r2基准提交B2成功；r1/r2均可重读；A/B原冻结树仍引用原版本。再跑全部必需协议案例和真实采用者影响；definition修好不等于global issue关闭。

## 2. 局部参数被错误写入全局

先记录共享D原摘要、A/B引用、A的用户范围。注入A把私有容量写进共享定义的变体，预期U05拒绝。

固定坏字节和传播范围；从不可变store恢复投影但不伪造“从未出错”。A改成实例参数/局部delta，B独立核对是否实际误采用；被误采用的任务按REWORK新版本/新attempt重新验证。只恢复文件不代表已消除业务影响。

## 3. 改oracle把错误实现变成PASS

原定义明确末尾等号合法。错误实现拒绝，随后有人将正例预期改为拒绝。测试必须同时保留原合法例和ALWAYS_DENY错误控制，不能按修改后的测试宣布修复。

找出是实现错、定义错还是案例误抄；固定真实来源和最小复现。实现修复按旧合同新attempt；若真需改变允许行为则定义/案例/树新版本和真实确认。旧失败不洗白，新任务完整回归与独立审查。

## 4. 共享错误的影响范围未知

可信公告命中某定义r1/C_PURE。A/B已登记，另一私有项目未授权可读。不得因为索引没返回它就宣布全部修复，也不得把其私有记录复制出来。

对已知范围停止危险继续使用，局部新Agent修复并各自回归/组合/审查。global记录coverage_incomplete与通知范围；本地合格节点可先交付，不等全世界更新。后续补齐授权范围或缩小声明，不能用版本固定来继续认可已知错误。

每次演练保存fixture版本、实际工具动作与expected/actual；本文件只给步骤，真实run保持未运行。临时文件模型输出在外部验证报告中单列。
