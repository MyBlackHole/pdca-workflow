# 三场景及组合测试样本（NOT RUN）

## 建模样本

M-P：输入用户要求“16字节块的有界覆盖；所有拒绝不改变原状态”，生成节点R及A/B种子，父要求分别分配给规范化/范围/原子应用及R组合；后续生成全部7节点。判定检查唯一父归属、全部目标分配、接口单位和错误传播、每节点三场景suite承诺。正例应允许冻结结构，语义未完成仍不可假冻结。

M-N-OMIT：故意从B定义删“范围失败时不调用B2”；即使B1/B2局部合同正常，父义务遗漏必须被识别，不能只凭7节点齐全通过。

M-N-PARENT：把B1同时挂A与B。期望拒绝第二组成父归属；知识definition_ref复用本身允许，不能把二者混为一谈。

M-N-RECURSE：R建模任务试图等所有孩子建模完成才交付seed。期望指出生成循环依赖；父只交付局部明确seed，孩子再展开。需根补工作则根新attempt，不伪称一个Agent生成整树。

## 执行与调度样本

E-P-ORDER：固定完整树，给四叶真实任务与独立工作区。A1/A2完成后只标A就绪；B1未完成时B/R不得开始。B1/B2完成后B就绪；A/B完成后R就绪。每节点各四条合法转换，7个不同Agent，不复用父上下文。

E-N-ARCHIVE：B1已archive但verdict=rejected/delivery_usable=false。期望B不ready，不能把完成状态当可用。失败可被审查并形成正确失败报告。

E-N-INTEGRATE：B1对offset=15,length=2正确拒绝，故意B忽略拒绝而调用B2。即使B1/B2局部suite通过，B组合测试必须失败，原块不得被改写。失败反例验证父任务不可省略。

E-N-VERSION：B记录孩子版本v1，测试中混入B1-v2。期望固定包不匹配、旧组合证据stale，不能以“最新都是通过”发布。

E-N-CONFLICT：A和B同时申请同一输出文件。期望宿主隔离工作区或串行预约，不得并发覆盖；Markdown文字本身不算锁。

## 审查样本

V-P-CORRECT：固定符合合同实现与完整真实证据。独立审查预期subject_conformance=pass且审查任务可confirmed；不得根据执行Agent自述补证据。

V-N-DEFECT：注入上述B忽略范围失败的实现。审查应定位B对应约束/调用/状态反例并报告subject_conformance=fail；正确发现该错误的审查任务仍可confirmed。不能将其confirmed汇总为整体实现通过。

V-N-MISSING：删除一个必须测试原始run，仅保留“39通过”摘要。预期unknown/不能发布；不得凭报告字符串重造日志。

V-N-RECURSION：审查任务在Check拟创建新的“审查审查任务”并等待。期望拒绝自动递归；本任务Check检查覆盖/证据，独立复核须另有明确需求。

## 返工联动

R-P：B1某固定案例在独立审查失败；新B1执行attempt/newAgent修复且全suite通过。标B、R旧组合包stale，按顺序新B执行/新R执行；新Agent审查B1/B/R并生成新release。A/A1/A2/B2未变包可保留，影响判定有依据。

R-N：只改B1并重写根总表为PASS，未重跑B/R组合也没有新审查。预期禁止发布，旧证据不能证明新孩子版本。
