# 3.4.7 采用与历史纠错

解压完整包到新目录，或使用独立附件中校验全树基准的补丁工具在新目录应用。不要在活动工作或历史records中原地替换；新工作显式采用3.4.7，原冻结工作保持原时点版本，必要时按ADOPT/REWORK迁移。

用户提供的records为真实运行来源。补充观察应记录本次时间、输入摘要和具体事实，不能倒填历史Agent/批准/转换。对已知26/45声明矛盾撤回相应完全一致结论；其余事实逐项核验，不否认整次运行。证据缺口先检查生成/保留/导出/读取链；实际未覆盖才补对应场景。

维护project检查新增独立版本化policy。已知3.4.6/3.4.7使用附件安装的对应策略；其他版本需调用方显式提供候选树外的策略。不会自动从候选清单生成要求。允许按策略增加可选资料，未知类型/未支持语法不默认通过。

records检查默认completed-review，只作当前采用前的有限检查；草稿使用draft。具名/跨根引用采用明确授权的外部catalog，未固定引用保持incomplete。review的辅助清单须有同run的task/attempt/run身份，旧合成夹具若缺字段不能继续充当该项合法控制。原夹具保存在旧输入中，新控制显式补全，不修改历史运行。

所有CLI结果写入新位置；存在输出时拒绝覆盖。调用方区分输入错误、业务检查失败和检查器异常，不能把非零退出一律当击杀或沿用旧JSON。
