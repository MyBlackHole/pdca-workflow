# rc.1 → rc.2：恢复集中根与拆分入口

本补丁的精确基线是本次上传的 `pdca.tar(6).gz`（根目录直接含SKILL.md，无外层pdca目录），不是之前的完整rc.1包。文件缺失/内容不同先核对，不能强行套用。

本轮恢复PDCA_ROOT/records和集中领域模型，保留用户每阶段授权、原任务Agent与完整三场景；没有恢复旧自动推进。增加八个入口及安装/登记工具。资源预约与operation重新成为当前模板，真实锁/隔离仍依赖已核验宿主或后端。

## 已有资料不自动搬迁

1. rc.1 的TARGET_ROOT/.pdca是旧运行资料，保留原字节和访问路径。安装/项目登记绝不扫描复制或删除它，不将原user消息改写成rc.2批准。
2. 用户决定暂停/结束或迁移具体任务后，先核对原Agent、请求、写权、资源与在途operation；结果未知不能由新task抢占。
3. 集中登记目标project/workspace，逐项列旧→新引用与摘要，在集中迁移记录中保留原路径和来源。移动文件不代表原生会话已迁移；原会话继续能力必须单独验证。
4. 不能安全保持原绑定和原授权语义的任务，保留旧快照完成或结束；新任务/attempt须新的用户操作。不可仅改pdca_root就宣布迁移完成。
5. 3.x旧任务继续其原协议，旧两次确认不转换为四阶段启动。新入口遇到旧版本只定位，不用当前方法推进旧任务。

## 安装与升级

首次安装与项目登记参见INSTALL.md。root存在且不是本安装器所属时，拒绝直接覆盖；可在明确的现有源码根原地注册，或保留旧根并明确迁移。不要为了通过安装删除集中records。

后续更新保留原快照、原记录及用户扩展。发布清单只覆盖软件文件，排除records和ontology/projects。集中库已有修改与新软件相撞时阻断，不能静默覆盖知识资产。

本包未加入legacy或复制数百份历史备份。未修改参考知识保持原字节；旧retired指针不是当前控制规则。源码补丁和原上传包足够用于本轮文件回溯。
