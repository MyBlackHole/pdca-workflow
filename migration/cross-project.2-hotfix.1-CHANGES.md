# cross-project.2-hotfix.1：跨项目入口交接修复

## 用户反馈与结论边界

用户反馈在其它项目测试无法正常使用，尚未提供具体宿主、报错、全局配置或失败会话。本轮检查的是此前交付的 cross-project.2 原包，修补源码中可确认的入口歧义；不能宣称已确定或修复用户实际运行故障。

原 global-entry 第7行的触发条件只明确“用户要求PDCA/已配置为默认”，未明确非空PDCA_ROOT本身触发；第12行读USE-PDCA后泛指“当前必需规则”，而USE-PDCA没有明确交接步骤。原AGENTS包含ontology入口，但位于另一个仓库，不能依赖它自动被加载。原入口测试的entry_files使用合成说明和标记，没有验证Agent实际读取正式规则。

这些是可导致误用的缺口，不是实际宿主错误轨迹。原规则已有部分正确边界：全局规则需安装、环境需实际可见、能力不可伪造。本修复将这些要求与正式读取交接连起来，而不将所有失败归咎于路径。

## 修改

1. 全局入口实际加载后，非空PDCA_ROOT明确启用。空值仅在用户选择PDCA或PDCA本地入口时回到当前根；普通项目不被强行初始化。用户明确拒绝仍不启用。
2. USE-PDCA → bootstrap/entry-check → ontology/README、权威、阶段与按需入口成为明确读链。避免相互链接导致递归加载。
3. 统一说明路径锚定：协议/模板和新records布局属于PDCA_ROOT；Markdown链接属于所在文件；源码/开发cwd属于TARGET_ROOT；已有记录ref不改变。
4. 先输出实际根、版本、读入事实与阻断层级。区分未加载、入口损坏、规则已读、能力阻断、等待确认。观察消息不是新批准门禁。
5. 增加独立标准库诊断工具，默认只读，显式选项才写一个PDCA记录区临时文件并清理。它不派发、不安装、不执行目标命令，也不声称Agent已读取规则。

workspace的v2双根/身份语义及project_workspace: cross-project.2保持；分发增加entry_bootstrap版本。没有改通用正式模板、新Agent/确认门禁、旧绑定、业务records或历史结果。主包仍纯Markdown，无adapter或执行器。

## 应用与全局入口更新

补丁基于pdca-tree-v3.4.4-cross-project.2，在PDCA仓库根执行git apply --check，再git apply。应用失败需核对本地改动和基版，不跳过补丁块。

**已复制到宿主个人/全局配置的旧入口必须另外更新为bootstrap/global-entry.md正文。** 仓库补丁不会修改仓库外配置；不覆盖其它用户指导，不向各目标项目写AGENTS/.pdca/链接。全局指令未实际加载时，export变量仍不能凭空运行流程。

现有任务按旧固定上下文和协议快照恢复，不倒填新入口状态，不重算旧确认来适配新内容。新工作采用新分发快照。

## 现场需要核验

在Agent实际命令环境而非另一个终端观察pwd和PDCA_ROOT。使用独立诊断区分路径和文件问题；入口通过后仍按原CAP/RESOURCE核实读写权限、新Agent与确认/控制机制。宿主名称、诊断输出和失败步骤足以继续定位；不需要完整环境或密钥。
