# Help 与算法常量设计

## 方案

1. 在共享配置头文件定义四个工具的 section 名、mTLS 环境变量名、算法环境变量名，以及具体算法名和默认算法宏；配置解析、握手映射、TLS 初始化、help 和测试统一引用。
2. 在 `rdbcomm`、`rdbcommd`、`aio-speed`、`aio-speedd` 的既有 help 输出中增加：独立 section、对应环境变量、配置键、`mtls_enable` 语义、算法取值、默认值、优先级和安全使用案例。四组环境变量必须逐一列出：`RDBCOMM_*`、`RDBCOMMD_*`、`AIO_SPEED_*`、`AIO_SPEEDD_*`；工具名和这些标识均从宏获取。
3. 保留现有参数解析结构和配置载体，不新增 CLI 参数；help 只负责说明已有配置入口。
4. 扩展真实工具 help 回归测试，同时增加算法宏与字符串映射一致性测试。

## 取舍

- 采用共享宏而不是各工具局部字符串，避免算法名称和默认值漂移。
- 暂不进行元数据驱动 help 重构，控制本任务范围；后续可单独演进。
- 示例只输出命令/配置文本，不启动服务、不生成证书、不覆盖用户文件。
