# rdb-config 统一管理全部 INI 参数

## 问题陈述

- **现状**：`rdb-config` 已统一 INI 文档解析，但 RPC、fs-backup、s3tools 等 app 仍分别保存 INI key、默认值、字段映射、校验和重载入口。
- **目标**：由 `libs/rdb-config.c/h` 统一维护范围内所有 INI 参数的定义、类型、默认值、环境变量优先级、校验和归一化结果。
- **差距**：当前共享模块提供的是通用键值 API，而不是完整的参数目录；app 仍可能因局部实现产生参数语义漂移。

## 解决方案

在现有 `libs/rdb-config.c/h` 内增加集中式参数目录和配置快照：每个参数由 section、key、类型、默认值、环境变量覆盖规则和校验规则描述。统一加载入口生成不可变快照，统一处理配置文件、环境变量和默认值优先级，并提供类型化读取、展示、重载和错误报告 API。

app 配置层仅负责将统一快照交给既有运行时结构或直接消费快照，不再声明 INI key、实现默认值、解析、校验或独立重载逻辑。`xbsa` 保持现状，不纳入迁移。

## Seam 分析

### 声明的测试接缝

- seam: `libs/tests/rdb_config_test.c` -> `libs/rdb-config.c`
- seam: `rpc/tests/*` -> RPC 统一配置快照
- seam: `fs-backup/fsclient` 配置测试 -> fsclient 统一配置快照
- seam: `fs-backup/fsdeamon` 配置测试 -> fsdeamon 统一配置快照
- seam: `s3tools` 配置测试 -> s3file/s3mount 统一配置快照
- seam: 工具集成测试 -> 工具启动、重载、help 和真实 RPC/rdbcomm 配置路径

## 用户故事

1. 作为维护者，我希望所有 INI 参数只在共享模块定义一次，以便修改参数时不需要同步多个 app。
2. 作为工具用户，我希望配置文件、环境变量和默认值的优先级保持一致，以便升级后行为稳定。
3. 作为测试人员，我希望能通过统一快照测试所有工具参数，以便发现参数漂移。

## 实现决策

- 只扩展现有 `libs/rdb-config.c/h`，不新增独立 INI 管理文件。
- 共享模块提供集中参数描述表和类型化配置快照；参数标识、section/key、默认值、环境变量名和校验边界均由共享模块维护。
- app 不再实现 `*_init_config`、`*_parse_config`、`*_check_config` 等 INI 生命周期 API；保留与业务运行时相关的结构和非 INI 校验。
- 保持现有 section、key、默认值、环境变量优先级、错误语义、CLI 语义和协议行为；不兼容旧的内部配置 API。
- 配置快照采用显式生命周期和参数传递，不引入锁；重载通过新快照替换旧快照。
- `xbsa` 及其 inih 依赖不在范围内。

## 测试决策

- 增加参数目录覆盖测试：每个迁移参数至少验证默认值、配置文件值和环境变量覆盖值。
- 增加非法类型、范围和缺失必填值测试。
- 运行 `xmake build`、`xmake test -v` 及真实工具层 RPC/rdbcomm 集成测试。
- 扫描范围内 app 不得直接使用 inih、声明 INI key 常量或实现独立 INI 解析入口。

## 验收标准

- [ ] AC-1: 参数清单覆盖范围内全部 INI section/key，并记录每个参数的类型、默认值、优先级和校验边界。
- [ ] AC-2: 共享模块单元测试验证全部参数的默认值、配置文件读取、环境变量覆盖、类型转换和非法值错误。
- [ ] AC-3: 范围内 app 不再直接读取 INI、定义生产 INI key/default/校验规则，只通过统一配置快照完成参数映射；保留的 app 初始化函数不得解释 INI 语义。
- [ ] AC-4: INI 文件格式、section/key、默认值、优先级、CLI 参数和协议/业务行为与迁移前一致。
- [ ] AC-5: `xbsa` 源码和构建配置无变化，仍保持原有 inih 使用方式。
- [ ] AC-6: `xmake build` 构建所有受影响目标成功。
- [ ] AC-7: `xmake test -v` 全量测试通过，并包含真实 RPC、rdbcomm、fs-backup 和 s3tools 配置路径。
- [ ] AC-8: 静态扫描确认范围内只有 `libs/rdb-config.c/h` 管理 INI 参数元数据和 inih 依赖。

## 范围外

不修改 xbsa；不修改 INI 文件格式、已有键名、协议帧、TLS/mTLS 握手流程、证书选择、业务数据逻辑和 CLI 参数定义；不把业务运行时策略塞入配置模块。

## 备注

实施前必须先完成参数清单基线，避免迁移过程中遗漏未被当前测试直接覆盖的工具参数。
