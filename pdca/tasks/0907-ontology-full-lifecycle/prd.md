# PRD — 本体全生命周期保真：从代码生成到持续监控

> 任务：T2069 / 0907-ontology-full-lifecycle / scenario: development / phase: plan
> 前置任务：T2068（本体创建预防门禁）已完成

## 背景与问题

T2068 已建立本体**创建预防门禁**，确保新本体不被创建为空洞内容。但"本体内容不符合实际"的根因不仅是创建环节，还贯穿本体的**全生命周期**：

1. **人工编写偏差**：本体由人编写，即使有门禁，仍可能遗漏代码实际行为
2. **代码演进导致本体过时**：代码变更后本体未同步更新，本体-代码产生漂移
3. **缺乏回测闭环**：本体声明的 `testable_signal` 是否实际可执行，缺乏定期验证
4. **无版本关联**：本体不知道对应哪个代码版本，无法追溯
5. **影响分析缺失**：代码变更时，无法自动识别哪些本体节点受影响

T2068 解决了"不创建空洞本体"，本任务解决"**本体始终与代码一致**"——从生成到监控的全生命周期保真。

## 目标

建立本体全生命周期保真体系，包含 6 个方向：

### 方向 1：代码→本体自动生成
- 从代码静态分析自动提取实体、属性、关系，生成本体草案
- 减少人工编写偏差

### 方向 2：本体→代码回测验证
- 定期用本体 `testable_signal` 回测代码，验证每个信号实际可执行
- 检测本体-代码漂移

### 方向 3：持续监控与告警
- CI 中持续检测本体-代码漂移
- 本体过时自动告警

### 方向 4：本体-代码版本联动
- 追踪每个本体节点对应的代码版本（commit hash / tag）
- 本体知道"这对应代码的哪个版本"

### 方向 5：影响分析
- 代码变更时自动识别影响的本体节点
- 变更影响图谱

### 方向 6：本体覆盖率度量
- 统计代码到本体的覆盖比率
- 识别未覆盖的代码区域

## 非目标

- 不重写 T2068 的门禁机制（T2068 已覆盖创建预防）
- 不修改本体格式/结构定义

## 验收标准

- [ ] AC-1：`scripts/ontology-generate.py` 可执行，从代码静态分析生成本体草案，生成的本体通过 `ontology-validate.py --check all`
- [ ] AC-2：`scripts/ontology-backtest.py` 可执行，定期用本体 `testable_signal` 回测代码，检测到不可执行时输出报告
- [ ] AC-3：`scripts/ontology-drift-monitor.py` 可执行，检测本体-代码漂移，CI 中漂移时非0退出
- [ ] AC-4：本体节点 frontmatter 新增 `code_version` 字段（commit hash），`scripts/ontology-version-link.py` 可执行，同步版本信息
- [ ] AC-5：`scripts/ontology-impact.py` 可执行，代码变更时识别影响的本体节点，输出影响图谱
- [ ] AC-6：`scripts/ontology-coverage.py` 可执行，统计代码到本体覆盖比率，输出覆盖率报告
- [ ] AC-7：6 个方向全部通过 `validate-convergence`

## 约束

- 所有脚本输出必须通过 `ontology-validate.py --check all`
- 新增本体节点字段须有 `rule_spec` 本体锚定
- 不改变现有本体格式（向后兼容）
