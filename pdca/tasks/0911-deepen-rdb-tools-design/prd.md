# 深化 rdb-tools-design 代码级知识

## 背景与问题

现有 `rdb-tools-design` 已具备总路由、五个版本化分册和 23 个可交付工具的独立入口清单，但多数工具只有单行链路与一个代码/构建锚点，缺少参数分发、关键函数、数据结构、状态转换、数据流、错误处理、资源释放、跨模块契约和扩展边界。用户据此判定该 skill“不够详细”。

本任务在 T2154/T2155/T2157 基线上继续深化，不以简单扩充篇幅作为完成标准，而以另一名 agent 能否沿文档完成代码级定位、影响分析和方案设计作为标准。

## 目标

1. 为现有清单中的全部 23 个工具建立独立、版本化、可按需加载的代码级详解。
2. 对核心运行链深入到函数、数据结构、状态/线程/进程、协议、错误和资源生命周期；对外部或运维工具至少说明入口、参数分发、核心模块、数据流、输出副作用和生命周期。
3. 所有关键事实可通过 `6200/release` 的真实 `file:line` 回查；跨模块契约同时给出生产端与消费端锚点。
4. 将 skill 组织为“短入口 → 总路由 → 五个子系统索引 → 每工具独立详解”的渐进披露结构。
5. 为复杂工具提供与机制相匹配的 Mermaid 调用时序图、数据流图或状态转换图。

## 范围

### 全量工具清单（23 项）

- fs-backup：`fs-cli`、`fsdeamon`、`fsbackup_tools`、`fsbackup.ko`、`makeFsbackup`
- rpc/rdbcomm：`aio-speed`、`aio-speedd`、`rpc-keygen`、`rdbcomm`、`rdbcommd`
- S3：`s3-tool`、`s3file`、`s3mount`、`afsd`、`afs-cli`
- XBSA/SBT：`xbsa64`、`rch-tools`、`sbt`、`FileTransferAgent`、`dmsbtex`、`dm-ftp`
- 公共工具：`bwlimit_tools`、`tls-keygen`

构建与发布不是单独工具页，但每个工具页必须包含其真实 target、链接依赖、安装/交付落点和运行装配方式；五号分册继续提供横向构建索引。

### 深度分级

#### A 级：复杂运行链

适用于 `fs-cli`、`fsdeamon`、`fsbackup.ko`、`makeFsbackup`、`aio-speed`、`aio-speedd`、`rdbcomm`、`rdbcommd`、`s3file`、`s3mount`、`afsd`、`afs-cli`。

每页至少覆盖：工具职责与消费者；构建 target、入口与参数；参数到分发函数映射；主成功路径；关键结构体和字段所有权；线程/进程/socket/端口或内核边界；数据流和副作用；协议生产端与消费端；错误、重试、超时和部分完成；资源获取与释放；孤岛/废弃/条件编译；复用点、扩展点和影响面；至少一幅有源码映射的 Mermaid 图。

#### B 级：外部、运维或辅助工具

适用于 `fsbackup_tools`、`rpc-keygen`、`s3-tool`、`xbsa64`、`rch-tools`、`sbt`、`FileTransferAgent`、`dmsbtex`、`dm-ftp`、`bwlimit_tools`、`tls-keygen`。

每页至少覆盖：职责与状态、构建和入口、参数/导出接口、分发路径、核心实现、关键数据结构、数据流、输出/副作用、错误及清理、消费者边界、扩展影响面和源码锚点。存在非平凡状态或跨进程交互时升级补图，不为简单线性 CLI 机械配图。

## 信息架构

1. `SKILL.md` 保留触发条件、事实源原则、路由步骤、关键禁区和参考文件加载条件，不承载 23 个工具正文。
2. `references/00-index.md` 作为版本选择与跨子系统总路由，列出 23 项工具的稳定链接、深度等级、状态和分册归属。
3. 现有 01–05 分册保留为子系统概览、共享协议/机制和工具索引，重复的工具正文改为链接。
4. 每个工具在所属分册目录下建立 `tools/6.2.0.0/<tool>.md`；文件名采用稳定 kebab-case，页面标题保留真实产物名。
5. 任一工具须能从 `SKILL.md` 经 `00-index.md` 或所属分册在不超过三次跳转内到达详解页；详解页反向链接版本分册和总索引。
6. 不依赖易漂移的固定行号作为唯一导航；优先使用稳定标题、表格键和路径，行号只作为当前基线的源码证据。

## 事实与证据规则

- 代码事实源固定为 `/home/black/Public/aio/aio-tools/6200/release`；版本标识为 `6.2.0.0`。
- 每条主调用链的入口、分发、核心实现和输出/清理阶段分别具有源码锚点；不得用单个入口锚点代表整条链。
- 跨模块 method、FS_*、MT_*、ioctl、端口、帧字段或导出 ABI 必须同时定位生产端与消费端；只有单端时标记“未闭合”。
- “存在”“被构建”“仓内现行调用”“外部消费者”“operator”“build-only”分开表达，不以仓内无调用者推导模块无用。
- 文档与源码不一致时以源码为准并记录差异；无法实证的结论标记“无法确认”。
- 代码片段仅在能解释非显然机制时少量引用，避免复制源码形成难维护的第二事实源。

## 图示要求

- A 级工具每页至少一幅 Mermaid 图，按机制选择 sequence、flowchart 或 state diagram。
- 图中节点名称必须能映射到正文中的函数、结构体、进程或协议字段，图后列出关键源码锚点。
- 图示必须表达正文难以一眼看清的时序、数据方向或状态变化，禁止装饰性流程。

## 非目标

- 不修改 aio-tools 的 C、C++、Go、xmake 或运行时行为。
- 不为 6.2.0.0 之外的版本编造知识。
- 不以静态代码阅读替代部署、内核装载、真实备份恢复或第三方产品联调。
- 不将 23 个工具合并为少数大类，也不删除外部/孤岛交付模块的独立入口。
- 不新增与任务无关的 README、安装说明或重复索引。

## 实施任务拆解

1. **W1 盘点与缺口矩阵**：逐工具确认 target、入口、源码边界、现有覆盖和待补机制。
2. **W2 信息架构落地**：收紧 `SKILL.md`，建立总路由、五分册索引和 23 个工具页路径。
3. **W3 A 级深化**：补齐 12 个复杂运行工具的代码级正文、契约闭合和图示。
4. **W4 B 级深化**：补齐 11 个外部、运维或辅助工具的代码级正文，按复杂度补图。
5. **W5 横向一致性**：统一构建、端口、协议、状态、孤岛和影响面表述，消除重复事实。
6. **W6 验证与证据**：运行结构、链接、清单、源码锚点和 skill 校验，形成 evidence。

这些工作单元共同修改同一 skill 的路由和共享事实，单独交付会产生断链或部分迁移状态，不拆成独立 PDCA 子票；在本任务内按 W1→W2→(W3/W4)→W5→W6 推进。
