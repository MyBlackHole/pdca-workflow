# 备份工具与服务端程序架构调研 → 完整备份产品架构设计 — 规格文档

## 问题陈述

- **现状**: 当前 RPC 项目只具备基础流式文件传输能力（`rpc-server` + PAR/RANGE 并发下载），
  无备份产品的完整视角。用户需要一份基于行业调研的完整备份产品架构设计，作为后续
  实现的顶层设计依据。
- **目标**: 产出一份「全量备份生态架构调研报告」+ 一份「完整备份产品架构设计文档」，
  覆盖客户端、服务端、存储、调度、恢复五大子系统的架构设计。
- **差距**: 缺少对现有备份工具（rsync/Borg/Restic/Rclone/ZFS send/LVM 等）和服务端
  程序（高性能网络服务端/存储服务端）架构模式的系统调研，也缺少将这些模式转化为
  自身产品设计的分析。

## 解决方案

通过系统化网络调研（官方文档、源码、权威文章），横向对比主流备份工具与服务端程序的
架构模式，提炼可复用的设计决策；然后基于调研结论 + 当前 RPC 项目的既有能力，产出
完整备份产品架构设计。产出为两份独立 Markdown 文档。

1. 作为架构师，我想要了解主流备份工具（rsync/Borg/Restic/Rclone/ZFS/LVM/Bacula/
   Amanda 等）的架构模式与取舍，以便为我们的产品选择正确架构。

3. 作为实现者，我想要一份完整的备份产品架构设计（客户端/服务端/存储/调度/恢复），
   以便后续按图实施。
4. 作为评审者，我想要每个设计决策都能回溯到调研证据或项目既有能力，以便审查。

## 实现决策

**不包含具体代码。**

### 产出物（两份独立文档）
1. `research-report.md` — 全量备份生态 + 服务端程序架构调研报告
   - 备份工具架构对比：本地/网络/云备份、增量、去重（dedup）、加密、快照、
     压缩、校验、恢复
   - 服务端程序架构对比：事件循环/线程模型、IO 模型（阻塞/非阻塞/epoll/io_uring）、
     内存管理、持久化、调度、高可用
   - 每个工具/框架：核心架构 + 关键设计决策 + 适用场景 + 引用来源
2. `design.md` — 完整备份产品架构设计
   - 系统总体架构（组件图/数据流）
   - 客户端：文件扫描、分块、去重、加密、压缩、上传调度
   - 服务端：接收、去重、存储布局、索引、并发控制
   - 存储：块存储/对象存储/文件系统选择、快照、版本管理、校验
   - 调度：备份策略、增量/全量、节流、断点续传
   - 恢复：点时间恢复（PITR）、文件级/块级恢复、验证
   - 与当前 RPC 项目既有能力（PAR/RANGE 并发传输、epoll 服务端）的衔接
