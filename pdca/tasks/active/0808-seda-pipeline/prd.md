# PRD：备份流管道 + SEDA 分阶段事件驱动实证

任务 ID：T0228
日期：2026-08-08

## 问题

POC 场景 01–10 已覆盖备份链路的单点技术（网络连接/CDC 分块/加密压缩/限流/事件模型），
但**数据在多个异构处理段间流动时的架构编排**（调度、背压、多核利用）尚未实证。
产品 fs-backup 的备份数据流（分块→压缩→传输→落盘）采用同步阻塞模型，
缺乏阶段解耦与背压控制的手段。

## 目标

在 POC 仓库实证 **SEDA（Staged Event-Driven Architecture）**：
4 级备份流管道（reader→chunker→compressor→writer），
每级独立有界队列 + worker 线程池，验证相比同步流水线的吞吐收益、
背压自稳定特性与多核利用率。

## 方案

4 级 SEDA 管道：

```
[源文件] → reader → (Q1) → chunker → (Q2) → compressor → (Q3) → writer → [目标文件]
```

- **reader**（IO 密集）：分块读源，投递 Q1
- **chunker**（计算轻）：CDC/定长边界切子块，投递 Q2
- **compressor**（CPU 密集）：zlib 压缩，投递 Q3
- **writer**（IO 密集）：顺序写目标

背压：有界队列，队满生产者阻塞（pthread_cond），全链路 drain 传播关闭。

## 用户故事

- 作为备份引擎开发者，我希望数据流在多级管道中并行流动，
  使 CPU 密集（压缩）与 IO 密集（读写）阶段重叠执行。
- 我希望慢阶段自动限速上游（背压），不丢数据、不内存膨胀。
- 我希望知道不同线程数/队列深度下的吞吐表现，以确定生产配置。

## 实现决策

- C + pthread + 有界队列（pthread_mutex + cond）
- 压缩用 zlib（场景07 已引入依赖）
- 数据完整性：源 hash == 解压后 hash 断言
- 同步单线程基线作为对照下限

## 测试决策

实验矩阵 E1–E5（见设计文档）：
- E1 同步基线；E2 SEDA 全配置吞吐；E3 参数扫描（线程/队列深度网格）
- E4 背压分析（队列水位 + 耗时分位数）；E5 多核加速比

## 验收标准

- [ ] AC-1: 同步 vs SEDA 输出一致（源 hash == 解压 hash），数据完整性
- [ ] AC-2: SEDA 吞吐 ≥ 同步基线
- [ ] AC-3: 背压下无数据丢失，无内存无限增长
- [ ] AC-4: 压缩后大小 < 源（压缩率 > 0）
- [ ] AC-5: 参数扫描产出线程数/队列深度 → 吞吐曲面数据
- [ ] AC-6: 多核扩展性数据（核数 vs 吞吐加速比）
- [ ] AC-7: make test 全量回归 PASS（含新增场景 11）

## 范围外

- 不做分布式/跨机管道
- 不引入第三方队列库
