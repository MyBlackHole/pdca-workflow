# 容量模型与验收压测基线 — 规格文档

## 问题陈述

报表中心一期容量与性能边界需实测验证：100 域登记上限、单域正常数据档、任务事实年增长、物理存储/IOPS 与扩展拐点；压测结果将回填性能验收指标（主方案明确"压测后补充"）。

## 解决方案

按主方案 §6.1.1 执行：100 域登记上限（第 101 个 `BACKUP_DOMAIN_LIMIT_REACHED`）；单域正常档基线（200 数据源/600 主机/1000 实例/1000 保护对象/150 策略/80 Worker）；任务事实 14,457/天/域估算校验；以 **20 域、6,000 万任务事实** 做生产安全参数压测；在第 80 域接入前复核 100 域 IOPS/磁盘水位；记录采集延迟/线程池排队/CDM 查询耗时/Report DB 写入延迟/磁盘与备份窗口，评估扩展拐点。

## Seam 分析

- 测试接缝：压测脚本（批量造数 → 触发采集 → 度量指标）；`rpt_collection_task` 与事实表水位采样；容量登记上限拒绝路径。
- Mock/Stub：CDM 侧用受控 CLI 测试桩；PG17 用目标硬件规格实例。

## 用户故事

1. 作为部署负责人，我想要 100 域容量模型实测，以便决定纳管节奏与扩容时机。
2. 作为压测工程师，我想要扩展拐点指标，以便在拐点前停止纳管并扩容。

## 实现决策

- 落地仓库：**aio-cdm 本仓（CLI/JSONL 侧）+ report-center（Report DB/collection-service 侧）**，压测脚本与记录随本任务归档。
- 依赖：T0215~T0221 全部。
- 关键口径：物理容量须实测（表/索引/WAL/聚合/20% 余量），不得逻辑行数直接换算；IOPS 不预设固定值；拐点只能目标环境实测（§6.1.1）。

## 测试决策

- 压测采集延迟/排队时长/源端查询耗时/写入延迟/磁盘水位/备份窗口；任一指标达阈值即判定拐点；压测记录留存。

## 验收标准

- [ ] AC-1: 第 101 个备份域登记被拒，返回 `BACKUP_DOMAIN_LIMIT_REACHED`（§6.1.1）。
- [ ] AC-2: 20 域、6,000 万任务事实压测完成，记录六类指标（采集延迟/线程池排队/CDM 查询耗时/Report DB 写入延迟/磁盘容量/备份窗口）（§6.1.1）。
- [ ] AC-3: 100 域正常档物理存储/IOPS 在目标 PG17 + 硬件下实测，含表/索引/WAL/聚合/20% 余量口径（§6.1.1）。
- [ ] AC-4: 第 80 域接入前完成 100 域 IOPS 复核；不足则停止纳管先扩容或下调档位（§6.1.1）。
- [ ] AC-5: 扩展拐点由实测得出并记录，不替代为模型推定值；≥1,000 域扩展不在本期承诺（§6.1.1）。

## 范围外

- 不做 1,000 域扩展设计与分片/多实例。
- 不产出新的架构方案。

## 备注

- 依赖：T0215~T0221；压测结论回填主方案性能验收指标。
- 任务事实 90 天约 1.301 亿行、一年约 5.277 亿行为登记测算窗口，非保留期限（§6.1.1）。
