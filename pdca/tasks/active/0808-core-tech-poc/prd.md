# 备份网络核心技术栈实证 — 规格文档

## 问题陈述

- **现状**: POC 场景01–10 覆盖连接语义、CDC、并行分块、限流等，但加密/校验/传输仍用自研代理原语（XOR 加密、FNV 校验、RLE 压缩），无生产级技术对比数据。
- **目标**: 对备份网络数据通路的 6 项核心原语做实测对比与机制验证，产出选型结论。
- **差距**: 缺少零拷贝传输、AEAD 认证加密、高速哈希、布隆去重、帧复用、纠删码的实测证据。

## 解决方案

在 POC 仓库新增 6 个独立场景（12–17），每场景独立可执行二进制 + 断言 + README，接入顶层 Makefile 聚合回归。复用系统库：OpenSSL（AES-GCM/SHA）、libsodium（ChaCha20-Poly1305）、libblake3、libxxhash、libzstd。

## Seam 分析

### 测试接缝
- 场景主程序 `main.c` 自行断言（`PASS/FAIL` + 退出码），与现有 01–10 模式一致。
- 系统库经 pkg-config 探测（openssl 已确认可用；blake3/xxhash/sodium 均已确认头文件+so 存在）。
- Makefile 增 `LDLIBS += -lssl -lcrypto -lsodium -lblake3 -lxxhash -lzstd`，TARGETS 追加 12–17。

### 验收可测性
- 每场景有明确 PASS/FAIL 断言（吞吐阈值、还原一致性、容错恢复完备性、假阳率上限）。
- `make test` 全量回归 PASS:N 递增到 16。

## 用户故事

1. 作为备份引擎开发者，我想要实测 sendfile/splice vs 用户态副本，以便决定大流量传输路径是否用零拷贝。
2. 作为安全工程师，我想要对比 AES-128-GCM vs ChaCha20-Poly1305 吞吐并验证篡改检测，以便选型 AEAD。
3. 作为去重模块维护者，我想要 blake3/xxhash/sha256 吞吐数据，以便选型指纹算法。
4. 作为索引设计者，我想要布隆过滤器空间/假阳率/吞吐权衡，以便评估去重位图方案。
5. 作为传输层开发者，我想要自研帧协议多路复用的吞吐与交织验证，以便支撑单连接高并发备份。
6. 作为可靠性工程师，我想要 RS 纠删码编解码与任意 ≤n-k 块丢失恢复验证，以便设计冗余策略。

## 实现决策

- 每场景独立 main.c，避免共享代码耦合；通用辅助（GF(2^8) 域、帧缓冲）可入 lib/。
- 吞吐基准：本地回环 socket 或内存数据 + clock_gettime，多次取稳定值。
- 断言阈值相对保守（如零拷贝 ≥2x 用户态、AEAD 篡改 100% 检出、RS 恢复 100% 完备），避免环境抖动误判。

## 范围外

- 不做完整传输协议、不做持久化索引、不做跨进程/跨机真实网络（本地回环即可）。
- 布隆不做分片/序列化到磁盘；RS 不做 Cauchy/Vandermonde 优化对比。

## 验收标准

- [ ] AC-1: 场景12 零拷贝 — sendfile 与 splice 吞吐均 ≥ 用户态 read+write 副本 1.5 倍（回环近内存带宽，拷贝开销占比有限），结果打印并断言。
- [ ] AC-2: 场景13 AEAD — AES-128-GCM 与 ChaCha20-Poly1305 均完成加解密还原一致；篡改密文任意 1 字节认证 100% 失败；打印两者吞吐。
- [ ] AC-3: 场景14 哈希 — blake3/xxhash 吞吐均 > sha256（SHA-256 经 OpenSSL），打印三者吞吐；blake3 64B 短输入正确性对照断言。
- [ ] AC-4: 场景15 布隆 — 实测假阳率 ≤ 理论上限（n/m 比值下），与精确哈希表内存对比；插入/查询正确性断言。
- [ ] AC-5: 场景16 帧复用 — 帧协议粘包/拆包正确（长度前缀+校验），单连接多流交织响应归属正确，吞吐打印。
- [ ] AC-6: 场景17 纠删码 — RS(5,3) 编解码还原一致；任意 2 块丢失可完整恢复；打印冗余开销。
- [ ] AC-7: 顶层 `make test` 全量 PASS: 16，FAIL: 0。
