# PRD — T0229 备份引擎核心原语实证（第二批）

## 问题陈述

备份引擎除传输层（第一批已覆盖）外，存储层与恢复层的核心原语尚未实证：
去重块如何组织存储、加密如何支持随机访问、压缩如何选型、去重块如何回收、
数据完整性如何校验、崩溃后如何恢复。本任务以 6 个独立 C 场景实证并给出
可量化结论，供备份引擎设计直接复用。

## 目标

- 6 个独立可执行场景（18-23），每个含断言 + 自测 + README（含原理图）。
- 顶层 `make test` 全量回归 PASS，不破坏既有 16 场景。
- 结论沉淀到 `knowledge/core-tech-poc/`（第二批）。

## 用户故事

作为备份引擎设计者，我希望拿到去重存储、加密分块、压缩选型、引用计数 GC、
完整性校验、崩溃恢复的实测数据与实现要点，用于产品架构决策。

## 方案

### 场景18 dedup-chunk-store（去重块存储引擎）
- 块写入：指纹（BLAKE3）→ bloom 前置过滤（沿用场景15 结论）→ 命中则引用计数++，
  未命中则写块存储（追加日志式）+ 建索引。
- 断言：重复写入不产生新块；非重复写入产生新块；块可完整读取还原。
- 存储：单文件追加 + 块头（长度+指纹+crc32），元数据与数据分离。

### 场景19 streaming-crypto-chunk（流式分块 AEAD 加密）
- 大文件分块（64KB）流式加密，每块独立 AEAD 标签，支持随机访问解密（只解某块）。
- CEK 由主密钥 HKDF 派生（OpenSSL EVP_KDF）；每块 nonce 从块索引派生，无复用。
- 断言：全量往返一致；随机访问解密正确；篡改任一块 100% 检出；非目标块不解密。

### 场景20 compress-codec-bench（压缩选型）
- 同数据（可压缩文本 + 随机二进制混合）对比 zstd（多级别）/lz4/gzip：
  压缩比、压缩/解压吞吐。
- 断言：zstd 解压吞吐 > gzip；lz4 压缩吞吐最高；三种解压还原一致。
- 数据用 BLAKE3 指纹比对还原正确性。

### 场景21 dedup-refcount-gc（去重块引用计数 + GC）
- 块引用计数：写入 +1，删除引用 -1；计数归零进入可回收候选。
- GC：扫描回收计数为 0 的块（标记-清扫式），空闲表维护，块 ID 复用。
- 断言：无泄漏（所有释放块可回收）；被引用块不被回收；GC 后空间单调下降。

### 场景22 integrity-verify（全量完整性校验）
- 备份时记录每块 BLAKE3 指纹清单；校验时回读逐块比对。
- 损坏模拟：随机翻转 N 字节 → 校验检出并定位到块。
- 断言：无损坏时全通过；损坏块 100% 检出且定位正确；增量校验只重读变更块。

### 场景23 wal-crash-recovery（预写日志 + 崩溃恢复）
- 自研 WAL：记录格式（len+type+crc32），事务写 WAL→apply→commit 标记。
- 崩溃模拟：截断 WAL（尾部半写/缺失 commit）→ 重放恢复，半写块丢弃，已 commit 保留。
- 断言：完整 WAL 重放幂等；半写块被检出丢弃；commit 前崩溃不产生部分应用。

## 实现/测试决策

- 语言 C（gnu99），-Wall -Wextra 零警告。
- 库：OpenSSL（加密/HKDF）、libzstd、liblz4、zlib、libblake3、libxxhash。
- Makefile TARGETS 追加 18-23，LDLIBS 追加 -lzstd -llz4 -lz。
- 每个场景 `make run/<id>` 可独立执行，断言失败返回非 0。

## 范围外

- 不做多节点/分布式存储。
- 不做实际文件系统级快照。
- 19 不覆盖非 AEAD 模式；23 不覆盖多线程并发事务。
