# 工具 help 覆盖设计

## 目标

统一用户可见 CLI 工具的 help 信息质量，不改变既有参数和业务行为。

## 初始纳入范围

- `aio-speedd`
- `rdbcomm`
- `rdbcommd`
- `tls-keygen` 及其 `create`、`ca`、`sign`、`inspect`、`mtls` 子命令
- `fsdeamon`

## 设计原则

1. help 内容以实际参数注册表和默认初始化逻辑为准，避免文档漂移。
2. 每个参数说明包含作用、是否需要值、默认值或取值约束、与其他参数的关系。
3. 案例按“查看/生成配置/启动服务/执行操作”分层，默认使用安全的帮助或检查动作；需要真实文件或服务的案例明确前置条件。
4. 测试直接执行已构建工具的 help，断言参数名、关键说明、案例标题和子命令入口存在。

## 备选方案

- 仅补文字：改动小，但后续容易再次漂移。
- 生成式 help：一致性更好，但需要重构各工具参数元数据，超出本轮必要范围。
- 本轮建议：保留现有参数解析结构，集中整理 help 文本并增加回归测试；后续再评估元数据驱动。
