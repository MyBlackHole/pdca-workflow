# 外部 Agent 工作流与本地 PDCA 对比调研

## 问题陈述

本地 PDCA 已具备严格阶段门禁、证据登记、能力降级和确定性夹具，但尚未与当前主流 Agent 编排项目采用同一维度进行证据化对比，无法判断哪些机制真正值得借鉴。

## 已知目标

- 使用当前官方文档和官方仓库，不依赖营销文章或二手排行榜。
- 比较 AI 准确度、执行效率、上下文/模型调用成本、故障恢复、人类门禁、安全边界和可审计性。
- 区分“框架运行时能力”与“本地治理流程能力”，避免直接以功能数量排名。
- 给出本地 PDCA 的优势、短板、适用边界和按收益/成本排序的优化建议。
- 没有可验证 AI 提升的建议直接淘汰。

## 候选对照组

1. LangGraph：显式状态图、checkpoint、interrupt、持久化。
2. Microsoft AutoGen：多 Agent 团队、终止条件、暂停/恢复。
3. CrewAI：Crew/Flow 双层编排、结构化状态、guardrail 与可观测性。
4. OpenAI Agents SDK：轻量 agent loop、handoff、guardrail、session 与 tracing。
5. GitHub Agentic Workflows：Markdown 编译、只读默认、safe outputs、仓库级审计。

## 拟用方法

- GQM：每项指标必须回答一个决策问题。
- 特征证据矩阵：只登记官方文档可核验的能力与限制。
- 本地静态/动态审计：使用现有 doctor、schema、fixtures 和内容审查器。
- 同构场景分析：对规划、执行、失败恢复、人类确认和归档分别比较。
- 证据分级：已执行实测、官方声明、合理推断分开标注。

## 解决方案

建立“项目事实表→同构能力矩阵→本地差距→建议淘汰门槛”的证据链：

1. 每个外部项目只采集官方文档、官方仓库和官方发布说明。
2. 能力值使用 `native/configurable/external/not-found`，其中 `not-found` 只表示本轮官方资料未发现，不推断项目绝对没有。
3. 每条事实标注 `official-claim/local-measurement/inference`；推断必须同时给出依据和反证条件。
4. 不计算综合总分，分别比较准确度、效率、恢复、安全、人类门禁、可审计性和采用成本。
5. 结合本地脚本实测形成改进候选；只有预期 AI 收益、消费者、验证方法和删除条件完整的候选才进入建议。

## 用户故事

1. 作为 PDCA 维护者，我希望看到同构能力矩阵，以便识别本地真正缺失的机制。
2. 作为 AI 执行者，我希望建议明确减少哪类误判、上下文或恢复成本，以便不加载无价值规则。
3. 作为审查者，我希望官方声明、实测和推断分离，以便判断结论强度。

## 交付物

- `research-report.md`：来源、逐项目分析、本地优劣、适用边界和建议。
- `evidence/source-inventory.jsonl`：来源 URL、项目、主题、访问日期和证据等级。
- `evidence/comparison-matrix.json`：机器可读能力矩阵及每个单元格的来源 ID。

## 比较维度与判定问题

| 维度 | 判定问题 |
|------|----------|
| 准确度 | 是否有结构化输出、输入/输出/工具 guardrail、显式终止和可执行验收？ |
| 效率 | 是否支持上下文隔离、单 Agent 优先、并行、调用/轮次预算及失败后避免重算？ |
| 恢复 | 是否有持久状态、checkpoint、暂停/恢复、幂等和回放语义？ |
| 人类门禁 | 是否能在副作用前暂停、展示状态并取得明确批准？ |
| 安全 | 是否默认最小权限、隔离工具、限制写输出并保护关键文件？ |
| 可审计性 | 是否记录模型调用、工具、handoff、状态变化、证据摘要和版本？ |
| 采用成本 | 是否需要运行时、数据库、云服务、模型绑定或大量框架代码？ |

## 验收标准

- [ ] 五个项目均至少引用两个官方一手来源，并记录访问日期。
- [ ] 每个比较结论标注为本地实测、官方声明或推断。
- [ ] 至少覆盖准确度、效率、恢复、安全、人类门禁、可审计性六个维度。
- [ ] 每个项目同时列出相对本地 PDCA 的优势与劣势，不做单向宣传。
- [ ] 优化建议包含预期 AI 收益、实施成本、验证方法和淘汰条件。
- [ ] 不把确定性流程测试冒充真实 LLM 成功率或跨框架性能基准。
- [ ] comparison matrix 每个非空能力结论均引用 source ID，且报告能回链到 URL。
- [ ] 推荐项按“立即采用/条件采用/不采用”分类；不采用项说明为何不能提高当前 AI。

## 范围外

- 付费云控制台的实际部署测试。
- 无统一模型、数据集和预算条件下的性能排行榜。
- 直接把外部框架引入本地仓库。
- 实施报告中的优化建议。

## 测试决策

- JSON/JSONL 结构和 source ID 引用可执行校验。
- 官方来源域名与每项目最少来源数自动检查。
- 本地能力使用当前 doctor、严格 schema、fixture 和归档审计重新实测。
- 手工复核推断是否披露反证条件，不与自动指标合成总分。

## 备注

该研究比较“机制是否存在及其工程权衡”，不声称测量不同模型的智能水平。访问日期统一记录为 2026-07-28。
