# T0140 调研设计

## 比较对象

将五个项目视为不同范式，而不是同类产品排行榜：

- LangGraph：状态图运行时。
- AutoGen：会话式多 Agent 运行时。
- CrewAI：角色团队与事件 Flow 的混合编排。
- OpenAI Agents SDK：轻量 agent loop 与可观测性 SDK。
- GitHub Agentic Workflows：仓库原生、编译式 Agent 自动化。
- 本地 PDCA：文件协议、人工阶段门禁和不可变证据治理层。

## 证据模型

每条 source 有稳定 ID、URL、项目、主题、访问时间。矩阵单元格只能引用 source ID 或本地命令证据；没有来源时为 `not-found`。官方自述不能直接转化为“更快/更准”，只能证明机制或接口存在。

## 分析顺序

1. 冻结来源清单。
2. 提取能力与明确限制。
3. 运行本地 doctor、状态测试、六场景 fixture 和内容审查。
4. 填写不带综合分的矩阵。
5. 对每个差距做收益—成本—验证—删除条件分析。
6. 用反例审查最终结论，披露不可比项。

## 科学性控制

- 固定样本与访问日期，降低选择性引用。
- 至少两个官方来源交叉验证每个项目。
- 区分事实、测量和推断。
- 不以 GitHub star、营销性能声明或功能数量替代任务效果。
- 不把“未发现”写成“项目不支持”。

## 风险

- 外部文档持续更新：记录访问日期和具体 URL。
- 项目目标不同：按机制与采用成本比较，不给总排名。
- 本地偏见：每个项目必须同时写相对优势和劣势。
- 缺少真实模型实验：建议仅限架构机制，行为收益标为待验证。
