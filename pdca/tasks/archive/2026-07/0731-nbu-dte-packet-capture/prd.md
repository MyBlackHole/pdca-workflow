# PRD: 抓包验证 NBU DTE 单端口 TLS/明文协商机制

> 任务: T0162 | 类型: research | 创建: 2026-07-31

## 问题陈述

T0148（NBU DTE 调研）已通过符号分析确认 NBU 使用 IN-APP-TLS 路径加密数据通道，并推断"单端口（13782/13724）通过连接内协商（VNET 协议头 + TSS）同时支持 TLS 与明文，类似 STARTTLS 机制"。但该推断**未经抓包验证**（T0148 conclusion.md 明确列为待办项）。

本任务通过实测抓包，验证或推翻以下假设：
1. 同一端口上存在明文 VNET 协议头（非 TLS 开头）
2. 加密连接在明文头之后紧跟 TLS ClientHello（同连接升级）
3. 明文连接（DTE=Off 作业）只有协议头 + 业务数据，无 TLS 握手
4. DTE 配置动态生效：修改配置后新连接立即改变加密状态

## 验收标准

- AC-1: 捕获至少 1 个 DTE=On 作业的数据连接包，证明 13782/13724 端口上 TLS 握手前存在非 TLS 明文协议字节
- AC-2: 捕获至少 1 个 DTE=Off（或降级）连接包，证明同一端口上明文连接无 TLS 握手
- AC-3: 对比两条路径的 TCP 会话首字节，输出 VNET 协议头魔数/长度（若可见）
- AC-4: 验证动态生效：分析现有作业记录（DTE=Off 与 DTE=On 作业的时序），佐证配置变更后新连接立即反映状态、无需重启（**不做配置变更实验，零风险**）
- AC-5: 结论写入知识库 `knowledge/nbu/nbu-dte-architecture.md`（更新或新增协商机制章节）

## 范围

**目标环境**: nbusvr103 (10.6.67.187) + nbumed103 (10.6.67.251)，作业 file-test-msdp
**不做**: 不修改 NBU 配置之外的任何系统行为；不做协议逆向（仅抓包分析首字节/握手序列）

## 方法

1. 在 10.6.67.187 上 `tcpdump -i any -s 0 -w dte.pcap 'port 13782 or port 13724'`
2. 触发一个 DTE=On 备份作业（现有 file-test-msdp 策略）
3. 同一 pcap 中天然包含控制面明文 VNET 流量（vnetd 代理 CORBA 连接），作为明文对比样本
4. tshark 分析: 首字节序列、TLS ClientHello 位置、vnet 头（AC-1/2/3）
5. 动态生效佐证（AC-4）: 查 `bpdbjobs -L` 历史记录中 DTE=Off/On 作业的完成时间序列 + 对应的配置变更时间点（无需现场改配置）

## 备注

- 风险: 生产环境抓包需注意流量规模（仅过滤端口 + 小文件备份作业）
- 依赖: SSH 访问 10.6.67.187（root 或可 sudo tcpdump）
