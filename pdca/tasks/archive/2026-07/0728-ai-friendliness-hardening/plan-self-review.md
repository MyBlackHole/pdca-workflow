# T0135 Plan 自我审查

## 结论

当前方向合理，但 PRD 尚不能直接进入 Do。存在 2 个阻塞性可执行性缺口、4 个主要方法缺口。此前提出的“当前 Agent 重复运行”和“token 降幅 15%”都隐含了当前仓库并不具备的能力，必须先修正实验定义。

## Blocking

### S1. Token 指标没有可用实现和固定口径

- 当前 Python 环境没有 `tiktoken`。
- PRD 未指定 tokenizer、版本和编码；不同模型 tokenizer 的结果不可直接比较。
- 因此“单项 token 至少下降 15%”目前不可复现。

建议：固定一个版本化参考 tokenizer 作为审查口径，同时保留 bytes/chars 作为模型无关指标；报告必须注明参考 tokenizer 不等于所有目标模型的实际计费 token。

### S2. “当前 Agent 重复运行”无法由仓库自动执行

- 仓库没有可调用当前 Agent 的 runner、固定随机种子或独立会话接口。
- 在同一会话里重复自评不构成独立试验。
- 因此首版只能自动验证确定性夹具；Agent 行为试验应定义为外部实验协议，在具备 runner 后执行。

建议：首版交付确定性 harness + 标准化 trial manifest；不把未执行的 Agent 重复试验写成已完成证据。

## Major

### S3. 删除判定与新 schema 存在循环依赖

只有先定义并批准 schema，才能知道哪些历史任务“不符合”。若 schema 与删除同时实施，存在为满足删除目标而改变 schema 的风险。

建议顺序：冻结 schema → dry-run 审计 → 输出精确清单和原因 → 核验 records/knowledge/journal 不在清单 → 执行 Git 可恢复删除。

### S4. “零回归”适用边界表述过强

有限测试只能证明在既定夹具上无回归，不能证明所有真实任务零回归。

建议改为：“所有既定确定性夹具零回归；未覆盖场景作为结论适用边界披露。”

### S5. 信息密度和语义重复尚未操作化

- “可执行内容比例”如果依赖模型主观分类，会重新落入单模型自评。
- 当前没有 embedding 模型，无法稳定测量语义重复。

建议：自动指标限定为可复现的结构指标、规范化文本重复和引用图；信息密度与渐进披露采用带判定规则的人工/AI 审查项，和自动指标分开报告。

### S6. 单任务跨越四个独立交付面

状态机、能力适配、内容量审查、评测基准可以独立失败和验证。全部塞进一个 Do 会放大回滚和证据归因困难。

建议在终审前拆成四个子任务，父任务只负责统一 schema、基准口径和最终综合验证：

1. 状态机 schema、门禁和历史 dry-run 清单。
2. 环境 doctor、能力协议和索引生成。
3. skill 内容量审查及候选精简。
4. 六场景确定性 harness 和实验协议。

## Minor

### S7. “重复审查产物”的边界仍需机器化

不得按标题或目录名模糊删除。删除项必须满足明确规则，例如同一目标的 superseded task、无独立 evidence、且不属于保留目录；每项记录路径、理由和 Git 恢复方式。

### S8. 旧审查数据只能作为历史对照

T0130 的行数下降和 T0131 的 3.9/5 不能作为任务效果基线。可保留作历史说明，但新的 baseline 必须从确定性 harness 重新测量。

## 自我修正后的方法边界

- 后续执行修正：tokenizer 与 bytes 的 Pareto 候选一致，按用户“删除不能提高 AI 效率的依赖”要求移除 tokenizer，15% 门槛改用 UTF-8 bytes。
- 自动、可复现：schema、引用完整性、状态不变量、能力检测、bytes、结构与规范化重复、确定性故障夹具。
- 需外部 runner：Agent 重复试验、模型间差异、实际 token/延迟/成本。
- 定性但有 rubric：信息密度、渐进披露、角色表达、认知维度。
- 不再声称：单模型自评分数等同于科学基线；有限夹具可以证明全局零回归。
