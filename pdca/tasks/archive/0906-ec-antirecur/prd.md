# EC算法问题驱动防复发补救

## 背景
用户批评本体不符合实际问题与修复方案，要求问题驱动、防复发闭环。

## 目标
5 个 EC 算法节点补充"实际问题→修复方案→防复发"三段，每问题关联真实提交。

## 功能需求
1. 从 git log 提取 EC 真实问题与修复提交
2. 每节点增补问题驱动节：现象/根因/修复提交/回归保障
3. 三查 + validate 全绿

## 非功能需求
- 真实时间戳；只增修 .md；不编造提交

## 验收标准
- [ ] AC-1 5节点均补问题驱动三段，每问题有提交哈希
- [ ] AC-2 三查 0 issues，validate 全绿
- [ ] AC-3 证据登记进Check归档

### 声明的测试接缝
- seam: scripts/ontology-validate.py -> ontology/domain/core-ec-*.md（增补节点）

## 风险与对策
- 风险：提交解读错误。对策：show 核实提交内容后再写
