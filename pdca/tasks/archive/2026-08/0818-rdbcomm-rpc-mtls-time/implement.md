# 实现拆解 — T0302

1. 共享第一阶段协议：实现固定头编解码、operation、能力/算法交集判定、错误码和半包/超时处理。
2. RPC 接入：在客户端和服务端连接路径接入第一阶段；保留原有 RPC APP 帧与 `rpc_get_time` API，通过适配层使用新时间协议。
3. rdbcomm 接入：在客户端和服务端连接路径接入同一第一阶段；默认明文进入原业务帧，mTLS 成功后透明切换数据面；增加时间 API 和服务端处理。
4. 配置接线：实现默认明文、客户端请求/服务端允许和算法能力的配置判定，避免配置不足时降级。
5. 验证：先运行共享协议单测，再运行 rpc/rdbcomm 明文、mTLS、时间、未知帧、坏包、半包、超时和既有回归测试。

## 依赖与风险

- 依赖现有 tls_cert mTLS 后端，不在本任务重写证书或 TLS 算法实现。
- TLS 升级后的 SSL/TLS 对象必须绑定握手运行时结构体生命周期；通过结构体上的 `read`/`write` 函数指针切换数据面，避免继续使用已 detach 的明文 fd。
- rdbcomm 既有 `RDBCOMM_ENCRYPT`/直接 TLS 路径需保留兼容 API，但连接协议必须先经过第一阶段。
