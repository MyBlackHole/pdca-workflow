# 审查项目是否还有旧架构的引用

## 问题陈述

- **现状**: 项目历经多轮架构演进（ADR 机制退役、本体归并、旧 API 清理），但全仓仍可能存在旧架构引用残留。
- **目标**: 全面扫描全仓旧架构引用，区分有意保留的历史注记与需清理的残留引用，登记证据并输出清理建议。
- **差距**: 尚无系统性的旧架构引用审查结论。

## 范围

- 扫描 `pdca/`、`ontology/`、`scripts/`、`templates/`、`tests/`、`README.md`、`AGENTS.md` 等活动文件。
- 排除 `.git/`、`records/`（历史记录）、`pdca/journal/`（日志）的扫描结果仅作参考。
- 旧架构引用包括但不限于：已退役的 ADR 机制引用、旧 API 变体、死代码文件、旧任务格式、已废弃的测试接缝声明等。

## 验收标准

- [ ] AC-1: 全仓活动文件扫描覆盖，识别所有旧架构引用类别
- [ ] AC-2: 区分有意保留的历史注记与需清理的残留引用
- [ ] AC-3: 残留引用已登记证据，每个引用有明确的清理建议
- [ ] AC-4: 审查结论写入 records/<record-id>/conclusion.md，经确认后归档

## 方案

1. **全仓扫描**：grep 搜索已退役术语（已退役、历史决策、legacy、deprecated、docs/adr/ 等），结合目录存在性检查。
2. **人工复核**：逐条确认引用性质（有意保留 vs 需清理）。
3. **证据登记**：通过 register-evidence 登记扫描结果。
4. **结论输出**：写入 conclusion.md，明确清理建议。

## 术语

| 术语 | 定义 |
|------|------|
| 旧架构引用 | 项目中引用已退役架构决策、旧 API、旧模式的文本或文件 |
| 有意保留 | 以"历史决策，已退役删除"或"原 ADR-XXXX"形式有意保留的注记 |
| 残留引用 | 指向已删除目录/文件或仍使用旧模式的引用，需清理 |
