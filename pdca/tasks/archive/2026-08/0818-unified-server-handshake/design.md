# 设计：统一服务端首阶段握手与 mTLS 升级

## 公共入口

在 `rpc-handshake.c/.h` 增加服务端首阶段入口，使用配置结构体传参，不使用回调。入口负责：读取首帧、处理 TIME 并标记终止、发送非法帧/协商错误、执行算法和 mTLS 策略判断，以及在协商 mTLS 成功后调用 TLS 握手并把 `SSL *` 绑定到 session。

## 服务端策略

- `mtls_required = 1`：客户端必须请求 mTLS，且算法必须匹配；有效算法对应的证书链不存在时服务启动失败。
- `mtls_required = 0`：客户端未请求 mTLS 时进入明文；如果服务端证书链可用，客户端主动请求且算法匹配时允许升级到 TLS；证书链不可用时仍允许明文启动，但 mTLS 请求明确失败，不降级。
- 有效算法：显式配置算法时使用显式值；未配置时使用 `RPC_HS_ALG_CLASSIC`（AES/普通证书路径）。
- `TIME`：只返回时间，不进入第二阶段，调用方关闭连接。
- 协商成功：返回可继续状态，调用方进入原始业务数据帧逻辑；mTLS 场景使用 TLS session 的读写函数。

## 分层取舍

协议帧解析、协商和公共 TLS session 编排集中到握手模块；证书加载、算法证书链校验、CN/CA 匹配和 OpenSSL 细节继续由 `tls_cert` 模块提供。RPC/rdbcomm 仅准备配置并调用统一入口。不得新增 CLI 参数，使用现有 `RPC_TLS_ENABLE` 和 `RPC_TLS_CIPHERSUITES` 配置。
## 参数接口补充

客户端与服务端均通过显式配置结构进入公共握手入口：客户端传递 mTLS 开关和算法，服务端传递 mTLS 强制开关、算法及 `ca_cn`。RPC/rdbcomm 工具保留各自配置入口，由调用层完成配置转换；握手模块不直接读取全局配置，也不增加命令行参数。
