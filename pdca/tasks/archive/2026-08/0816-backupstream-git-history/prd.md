# backupstream v65-v101 提交演进学习 — 规格文档

## 问题陈述

- **现状**: backupstream `main` 分支共 36 个提交（v65→v101，缺 v91），提交信息仅含版本号，无修改说明。用户想系统学习每个提交改了什么、为什么改、带来了哪些架构变化。项目 `docs/ROUND*_REVIEW.md` 记录了各版本演化，但无一份从 git 提交本体出发、逐提交对齐的演进学习报告。
- **目标**: 产出逐提交学习报告，覆盖每个提交的修改文件、核心变更、修改作用、架构影响，并归纳 v65→v101 的架构演进主线。
- **差距**: 既有知识资产 T0287 只覆盖 80.0.0 单版本架构；本任务需要覆盖完整 36 提交演进视角。

## 解决方案

在 PDCA 记录目录产出 `git-history-learning.md` 学习报告，以 git diff 为事实来源，docs/ROUND*_REVIEW.md 为背景补充。报告结构：

1. **概述**: 仓库提交概况、编号与版本对应关系、v91 缺失说明。
2. **逐提交分析**（36 节，每节三要素）：
   - 修改内容：`git show --stat` 改动文件清单 + 关键代码变更
   - 修改作用：该版本要解决什么问题 / 新增什么能力
   - 架构变更：对系统架构（协议/线程/事件/存储/观测）的影响
3. **演进主线汇总**: v65→v101 的主要架构演进脉络（目录队列→dirty journal→Reactor 迁移→observability）与关键分水岭版本。
4. **学习结论**: 关键设计模式、取舍与可复用经验。
