# PRD 骨架 — 默认算法由 ed25519 改为国密

> 本文件为 Plan 阶段骨架，完整规格在 P2 Grill 决策后于 P3 合成。

## 问题陈述

当前代码库中多处"默认密钥/证书算法"硬编码为 `ed25519`（证书/签名层的默认算法与文件名前缀约定）。需求方要求将默认算法改为国密。

## 已知信息（已核实）

- 证书/签名层存在两套并列算法：`ed25519` 与 `sm2`（国密）。`sm2` 在 C 侧（OpenSSL）已支持，是 `ed25519` 的直接国密替代。
- 握手/传输层存在两套并列套件：`TLS_AES_256_GCM_SHA384`（AES）与 `TLS_SM4_GCM_SM3`（国密 SM4-GCM-SM3）。其"默认"枚举 `HS_ALG_DEFAULT` 为兜底值，字符串 `ed25519`/`sm2` 在握手层均落入该兜底，并非合法套件名。
- 默认 ed25519 的锚点分布在：证书生成工具、证书路径选择、Go OSS HTTPS 配置、证书文件名前缀常量、以及若干测试断言。
- 风险点：Go 标准库 `crypto/tls`/`crypto/x509` 不支持 SM2 证书加载；若 Go 侧默认改 sm2，当前 `buildTLSConfig` 会因 `LoadX509KeyPair` 失败而 fail-closed（HTTPS 无法启动）。

## 信息缺口（待 Grill 澄清）

1. 改动范围：仅证书生成工具，还是同时覆盖证书路径选择 / Go OSS HTTPS / 握手默认套件等？
2. "国密"具体指代：证书签名用 `sm2`，还是也包括握手套件 `TLS_SM4_GCM_SM3`？
3. Go OSS 侧 sm2 证书加载不支持问题如何处理（引入国密库 / 保持 fail-closed / 仅 C 侧改默认）？
4. 证书默认文件名前缀是否由 `ed25519_*` 改为 `sm2_*`，以及对下游依赖与既有部署的影响。

## 范围外（暂定）

- 不改 `HS_ALG_DEFAULT` 运行时枚举值（需保持二进制兼容，值为 0 不变）。
- 不改 SM2 算法的密码学实现本身。
