# PRD — 门禁合理性审视：关键字脚本门禁对AI工作流的适用性与方法论依据

> 任务：T0535 / 0902-gate-keyword-rationality / scenario: research / phase: plan

## 背景与问题

T0534 刚落地“关键字门禁零容忍”（`ATTR_GENERIC` 泛化短语检测、`grep -q` 动词检查、`mermaid`/`Source` 计数等），通过 `ontology-validate.py` + `audit-ontology-fidelity.py` 硬阻断空洞本体。开发者质疑：**大量Python脚本做关键字门禁，对AI工作流是否合理？是否过度？是否误伤？** 需以方法论与实证回答。

## 目标

回答“关键字门禁在AI工作流中何时合理、何时过度”，并对存量门禁给出“保留/降级/替换”清单，使门禁“既防空洞，又不成为AI的过度税”。

## 非目标

- 不立即删除存量门禁；本任务先给“依据+清单+决策树”，改动按建议分批实施。
- 不引入大模型语义门禁的落地方案（仅评估可行性与成本）。

## 术语

- **关键字门禁**：以正则/字符串匹配（如 `检查本文件`、`grep -q`）为判据的脚本门禁。
- **语义门禁**：以模型/嵌入/AST理解内容语义的门禁。
- **AI工作流**：本仓库PDCA中AI读写 `ontology/`/`pdca/tasks/` 的高频路径。

## 方案方向（待Grill确认）

拟采用“网络方法论 + 存量实证”双轨：

1. **网络调研**：搜 `AI workflow gate`/`lint over-enforcement`/`semantic validation`/`AI-friendly guardrail` 等，提炼“何时用关键字、何时用语义、何时不用”的理论依据。
2. **存量审计**：盘点当前全部关键字门禁（`ontology-validate` 6类 + `fidelity` 3类 + `audit`/`gate` 等），量化触发率、误伤率、维护成本。
3. **决策树**：产出“关键字 vs 语义 vs 抽样 vs 无门禁”适用边界。
4. **建议清单**：每条存量门禁给“保留/降级为警告/替换为语义/删除”意见与成本。

备选：仅做网络调研不碰存量；或仅审存量不搜网络。

## 验收标准

### 验收标准
- [ ] AC-1 方法论依据：调研报告含≥5篇高信源（学术/工业/开源）文献综述，覆盖“门禁过度”“AI友好校验”“语义vs关键字”三主题，且每篇有Source行号与对本任务的启示
- [ ] AC-2 存量量化：产出 `gate-inventory.md` 含当前全部关键字门禁清单（≥8条），每条含触发率（全量413节点中命中数）、误伤案例（≥1例“合理内容被误拒”或“空洞未被拒”）、维护成本（行数/误报处理时长）
- [ ] AC-3 适用边界：产出决策树（mermaid）明确“关键字/语义/抽样/无门禁”四象限适用条件，且与 `ontology-fidelity-criterion` 七项清单可映射
- [ ] AC-4 改进建议：对每条存量门禁给出“保留/降级/替换/删除”处置意见与实现成本（人日），且首批“降级”建议可在1人日内落地验证
- [ ] AC-5 收敛可验证：调研报告+清单+决策树已登记（`evidence/manifest.jsonl` ≥3条）且 `convergence map` 逐条回链AC-1..4，`validate-convergence valid:true`

## 约束

- 网络调研须用 `web-research` 技能结构化产出（问题拆解→搜索策略→信息整理→结论），非简单堆链接。
- 存量审计须基于真实 `ontology/` 413节点跑数，非拍脑袋。
- 建议须可执行：每条有“处置+成本+验证”三要素。

## 风险

- 网络资料噪音大，方法论与本仓库PDCA场景不匹配 → 通过“存量实证”对齐缓解。
- 结论若为“门禁过度”，可能动摇T0534刚立的零容忍 → 通过“降级为警告而非删除”缓冲。
