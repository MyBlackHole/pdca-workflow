## 从实现提炼到两种环境

| 问题及静态证据 | 内核态规则 | 用户态规则与限制 |
| --- | --- | --- |
| **存活与移交**：kref.h:62 的最后引用释放；kref.rst:153 的直接移交；kobject.c:663/709/730 的清理链 | 采用目标 kref/refcount/RCU 等时履行各自规则；查找到取引用期间要有存活依据 | 唯一消费者可显式移交，统一 owner 可等待全部使用者结束；确需共享才增加合适引用机制。没有共同生命周期证明时不能借“省引用”逃避存活责任 |
| **锁对象存活**：mutex-design.rst:104 起；mutex.c:569 和 1021 后的 wait_lock/等待者处理 | 保持 mutex 及宿主到 unlock 返回，不能把内部 release 发布点当销毁许可 | 从目标线程 API 核对 destroy/use 的契约，所有锁使用者均收敛；不凭观察到“锁空闲”释放宿主，不复制某种内核实现假设 |
| **锁范围与回调**：process_one_work 在 3362 释放 pool 锁，3396 调 callback，3431 重取锁；3297/3398 说明 work 可由 callback 释放 | 缩短队列锁持有时间同时维护 worker/pwq 等独立存活和状态；回调上下文由队列类型决定 | 锁内领取/提交、锁外慢操作可作为候选，但须补齐引用/独占与状态复核；不能概括为“回调无锁/可自由释放一切” |
| **停止与重新入队**：workqueue.c:4585 的 cancel 条件；4650 的 disable 计数 | cancel_work_sync 对 racing enqueue 有前提；目标支持时 disable_work_sync 有额外禁入语义，仍需维护句柄及其他来源 | 关闭入口、收敛生产者/回调后再销毁；用户线程取消/join 与内核 API 不能逐名替换 |
| **保留量与硬上限**：mempool.c:547/572 首选底层分配，失败用保留；mempool.h:20 的 min_nr | mempool 的进展保留不是最大活跃数；还要证明等待依赖和回收上下文 | 有严格预算时分配前原子预留，覆盖构造、排队、在途、外借和缓存；不因“用池”就声称峰值受控 |
| **流控与记账**：sock.c:3010 先查阈值、3022 分配、3025 记 owner；2743 以 truesize 计量；skbuff.h:273 包括对象元数据 | 理解该子系统的流控和释放记账，不能仅凭这段阈值检查证明全子系统严格配额 | 当前占用小于阈值，不证明加本次分配后仍在预算内；未读完整调用链不评判其并发保证。按项目实际容量和析构退账设计，逻辑计量不等于精确 RSS |
| **安全大小计算**：overflow.h:330/349 溢出返回 SIZE_MAX；434 的结构大小组合；kfifo.c:44 采用数组分配 | 复用目标 API，保留类型/位宽及失败语义，再分配和访问 | 先查失败/范围再窄化；用项目适用的安全算术和 C 分配接口。C++ 仍处理 void* 转换和对象生命周期，不套用 C 的隐式转换 |
| **上下文与进展**：workqueue.rst:175/214；locktypes.rst:229/491 | threaded/BH、RT/raw、GFP 与 reclaim 依赖分别核对；WQ_MEM_RECLAIM 不自动打破任意循环等待 | 普通工作线程不套 IRQ/GFP 规则；仍核对持锁、信号、fork 等实际限制，考虑阻塞与退出。禁止 C++ 库不禁止允许的 C/pthread 接口 |
| **发布与复用**：kfifo.c:105/111/124 及 144/150/184 的复制与索引发布 | 依目标 FIFO 调用约束及 LKMM 证明；本轮未读公开 FIFO 头/全部调用者，不认证其任意并发使用 | 重新证明生产/消费、复用及停止；使用语言/项目支持的同步，不能把 smp_wmb 改名或加 volatile 当作 C/C++ 算法 |
| **部分成功与外部契约**：libfs.c:1143/1178；同树 ioctl 指南 | 短读/写返回实际进度；固定 ioctl 请求完整复制、验证，UAPI 布局及 compat 单独处理 | 核对系统调用/库的返回约定，保持部分成功及总截止时间；持久化、权限、文件/线程生命周期不从内核 helper 自动继承 |

本轮已有的内存预算、mempool、RT、typed allocation、uaccess、所有权与停止规则经上述本地路径再次核对。新增或明确：
