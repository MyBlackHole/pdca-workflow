# ADR-0019: 客户端小文件 writer pool 的首错停止与顺序屏障

- 日期: 2026-08-13
- 状态: Accepted

## 背景

客户端 TREE GET 的 `SmallLocalWriterPool` 允许接收线程把小文件 blob 交给多个
落盘 worker。当前池在 worker 失败后会清空待执行队列并锁存错误，但接收循环的
`enqueue()`、硬链接和 TREE_END `drain()` 调用点没有统一检查失败结果，可能继续消费
或执行依赖完整树状态的后续动作。

## 决策

采用首错 fail-fast 边界：首次 writer 失败锁存错误并停止新任务；接收循环在
`enqueue` 或顺序屏障失败后停止后续树动作；已运行 worker 完成清理，pool 析构前
join 全部线程，最终向调用层恢复首个错误。

队列继续使用固定 `max(8, workers * 8)` 上限，默认 `workers=0` 不变。运行状态只
通过已有 `--progress` 输出诊断计数，不扩展协议或引入独立控制通道。

## 备选方案与取舍

- **继续消费并在 TREE_END 统一报错**：实现改动小，但可能在小文件失败后创建硬链接、
  应用目录元数据或发送成功提交，错误边界不清晰，拒绝。
- **排空所有已接收任务后再报错**：可能保留更多部分结果，也会延长失败响应并增加
  目标树不完整的可见窗口，拒绝。
- **首错停止并回收活动 worker**：错误响应快、顺序语义明确，代价是已排队任务被
  丢弃；采用该方案。

## 影响

- 失败路径可确定地停止后续树结构动作，并保留首个诊断原因。
- 正常路径保留现有原子发布、目录 metadata、hard-link 和 durability 语义。
- 指标和 benchmark 解释了队列上界与并行度，但不承诺所有文件系统上的绝对收益。
