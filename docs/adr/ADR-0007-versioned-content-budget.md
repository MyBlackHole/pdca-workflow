# ADR-0007: 以逐资产版本化 baseline 治理 AI 上下文内容成本

日期: 2026-07-30
状态: Accepted

## 背景

当前内容审计能够稳定报告 flow/skill 的 UTF-8 bytes、重复率和断链，但只证明当前结果可重复，不能阻止后续变更悄然增加 Agent 需要阅读的上下文。

全局百分比阈值没有基于当前消费者或任务类型的实证依据：小资产的固定增量和大资产的相同比例并不具有同等认知影响。需要在防止成本回弹与保留必要说明之间建立可审计边界。

## 候选方案

### A. 仅报告当前 bytes

- 优点：实现最简单。
- 缺点：没有回归判定，报告不能阻止成本增长。

### B. 使用统一的全局百分比或绝对 bytes 阈值

- 优点：规则直观。
- 缺点：阈值缺乏当前实证基础，容易对小资产过严、对大资产过松。

### C. 逐资产版本化 baseline，默认拒绝增长并允许有证据的豁免

- 优点：将成本判断绑定到实际改动资产；baseline 变更、必要性与非退化验证可审计。
- 缺点：需要维护受版本控制的 baseline 资产和明确的更新记录。

## 决策

选择 C：每个纳入审计的 flow/skill 记录版本化 UTF-8 bytes baseline。默认规则为 bytes 不得增长；增长必须同时提供必要性说明、通过引用完整性和相关确定性夹具，并以显式变更更新 baseline。任务特定的精简目标可以另行声明，不能被当作全局常量。

该预算是跨环境的内容成本代理，不是 token、延迟或真实模型成功率指标。

## 影响

- 内容审计需要读取、校验并输出 baseline、delta 和稳定错误码。
- 测试需要覆盖初始建立、未变、无豁免增长拒绝、有豁免增长通过、遗漏资产和陈旧 baseline。
- baseline 更新是受审计的治理动作，不能由自动修复静默完成。
- T0160 已于 2026-07-30 完成 P6 终审，本 ADR 自该确认起生效。
