# ADR-0827-logger-instance

## 状态
已采纳（Plan 阶段，待 P6 终审）

## 背景
`libs/logger.c` 以全局单例 `g_logger` + 全局互斥量提供日志，导致运行期反复 `init_logger` 与并发写日志产生数据竞争。用户要求彻底去全局。

## 决策

### ADR-1 实例式 vs 线程局部默认 logger
**决定**：实例式（显式句柄）。
**理由**：用户明确要求"彻底去全局"；线程局部仍是"线程级全局"，未消除隐式来源。
**权衡**：调用点改动大（661 处宏 + 7 处 init_logger），但结构正确。

### ADR-2 atfork/atexit 用内部实例注册表
**决定**：保留一个仅用于生命周期登记的受保护链表（注册表），`atexit` 关闭所有未关实例，`pthread_atfork` prepare 锁全部实例互斥量、child 重新初始化。
**理由**：实例需进程退出/ fork 时自动清理，否则泄漏或 fork 后崩溃。
**权衡**：注册表是"全局结构"，但它只管生命周期，不持有任何共享日志状态，不构成用户反对的"全局日志器"。

### ADR-3 宏命名保持 InfoLog(lg,...) 首参句柄
**决定**：保留现有宏名，仅新增首参 `lg`。
**理由**：降低审阅时"旧宏→新宏"的映射成本；编译失败即迁移信号。
**权衡**：若未来需同时支持新旧 API 会有歧义，但本次一次性迁移无此问题。

### ADR-4 simulator 实例 API 收敛
**决定**：`libobk/simulator/main.c` 的 `init_logger(&__logger__, dir, file)` 收敛到统一 `logger_open`。
**理由**：消除与 `libs/logger.c` 的 API 分裂，统一为唯一实例接口。

### ADR-5 句柄通过既有上下文结构体传递
**决定**：`logger_t *` 挂到 `sbt`/`server`/`io`/`data` 等既有上下文，深层级函数从中取句柄；无上下文的函数新增 `logger_t *log` 形参。
**理由**：最小化函数签名改动面，避免每层新增参数透传。

## 影响
所有依赖全局 logger 的模块须在 T0262–T0268 中迁移。
