# ADR-0006: 将 AI 友好评测路由建模为可执行合约

日期: 2026-07-30
状态: Accepted

## 背景

当前 AI 友好度 harness 以 `flow-do/SKILL.md` 是否包含路径标题作为正常场景的通过条件。该检查不能证明给定 `scenario_type` 实际选择了预期路径，因而会产生标题仍在但映射已错误的假阳性。

T0160 需要在不引入真实 LLM runner 的条件下，加固导航评测的 test oracle。结构化合约可提高格式和比较过程的确定性，但不能单独证明模型对任务语义的理解或真实成功率。

## 候选方案

### A. 继续以 Markdown 路径标题为正常路径 oracle

- 优点：零新增资产。
- 缺点：只能验证文档包含标题，不能验证 scenario 到路径的行为映射。

### B. 在每个 fixture 内重复维护 scenario→路径预期

- 优点：实现简单。
- 缺点：fixture 与文档/实现之间没有唯一事实源，容易产生同步漂移。

### C. 严格机器可读路由合约作为唯一事实源

- 优点：可由 resolver 和 fixture 共同消费，支持正常路径、非法输入和文档一致性的独立断言。
- 缺点：增加一个受 schema 约束的维护资产；仍需端到端测试证明语义行为。

## 决策

选择 C：建立严格、机器可读的 scenario→路径路由合约。正常夹具必须调用实际 resolver，`flow-do` 保留面向人的路径说明，并通过独立测试验证其锚点/引用与合约一致。

该决策只提高评测 oracle 的可证伪性和 Agent 导航的确定性；不得据此声称提高真实模型成功率。真实模型表现只有在固定 runner、保留任务集和独立指标存在时才可评估。

## 影响

- 需要新增路由合约 schema、resolver 和正常/非法场景夹具。
- 测试可对同一 scenario 的映射漂移给出稳定错误，而不是依赖 Markdown 标题搜索。
- 需要保留文档与合约的一致性检查，避免机器资产和人类说明分叉。
