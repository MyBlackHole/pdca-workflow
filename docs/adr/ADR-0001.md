# ADR-0001 — PDCA 工作流架构决策记录机制

- **日期**: 2026-07-27
- **状态**: 已接受

## 背景

PDCA 工作流的 flow-plan/do 多处引用 `docs/adr/` 作为架构决策记录的位置，但从未产出过实际文件。需明确 ADR 记录什么、谁维护、何时写。

## 决策

1. **ADR 只记录跨任务/跨周期的架构决策**。单任务内的决策写入 `prd.md` 或 `design.md`，不作为 ADR。ADR 的典型场景：语言/框架选择、数据模型约定、模块边界、集成协议。
2. **ADR 由 domain-modeling 技能在 flow-plan 2a 阶段或 flow-do Path E 创建**。写 ADR 时同时更新 `pdca/CONTEXT.md` 中的相关术语。
3. **ADR 编号格式**: `ADR-NNNN`，4 位数字前缀（如 ADR-0001）。
4. **ADR 内容**: 背景 / 决策 / 理由 / 影响。不包含具体代码片段。

## 理由

- "什么决策写 ADR"的模糊是导致 ADR 从未产出的根因
- 单任务决策写任务内文档，跨任务决策写 ADR，职责清晰
- domain-modeling 技能已有管理 CONTEXT.md 的职责，ADR 是其自然延伸

## 影响

- `docs/adr/` 目录现有空文件不再警告
- flow-plan 和 flow-do 中 ADR 引用指向此标准
- domain-modeling 技能需了解此 ADR 作为自身职责之一
