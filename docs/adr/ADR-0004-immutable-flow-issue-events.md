# ADR-0004: Flow Issue 使用独立不可变事件文件

日期: 2026-07-30
状态: Accepted

## 背景

T0159 需要将 PDCA 使用过程中发现的机制问题作为后续聚合、诊断、改进和效果验证的事实输入。现有 `flow-audit.json` 会整体更新 `latest` 和 `attempts`，不满足严格的单事件不可变性，也会使整文件摘要在每次追加后变化。

事实存储需要符合 `records/` 的不可变约束，为 AI 提供严格 schema、稳定 ID、明确来源和可操作错误，同时允许聚合视图随算法升级而重建。

## 候选方案

### A. 每个 record 使用一个 append-only JSONL

- 优点：文件数量少，顺序扫描简单。
- 缺点：并发追加需要锁；进程异常可能留下部分行；追加会改变整文件摘要；单事件不能独立登记和校验。

### B. 每个 occurrence 使用独立 JSON 文件

- 优点：可用独占创建保证幂等和不可覆盖；并发事件互不修改；单事件有稳定路径与摘要；损坏隔离；适合按需读取。
- 缺点：会产生较多小文件；全局统计需要确定性扫描和投影视图。

### C. 继续扩展可变的 `flow-audit.json`

- 优点：改动最少。
- 缺点：事实和最新视图混合；整文件反复覆盖；难以提供真正不可变、可独立寻址的 occurrence。

## 决策

选择 B：

1. 每次 Flow Issue Occurrence 写入
   `records/<record-id>/flow-events/<event-id>.json`。
2. 事件只能通过规范 CLI 独占创建；AI 不直接编辑事件文件。
3. 每个事件满足严格 schema，包含稳定 ID、schema/rule version、来源、执行关联、问题分类和证据引用。
4. Flow Issue backlog 是由事件确定性生成的可重建投影，不作为事实源。
5. `flow-audit/v1` 冻结为历史格式；新模型从明确 cutover 开始，不回写既有记录。

## 影响

- 需要新增事件 schema、上报 CLI、聚合器、稳定错误码和故障注入测试。
- 需要提供紧凑查询接口，避免 AI 直接加载大量小文件。
- 需要定义投影版本和 fingerprint 版本，防止规则升级后错误合并。
- 文件数量会增加，但每个事实可以单独校验、引用和恢复。
