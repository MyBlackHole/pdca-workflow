# ADR-0028: RPC 使用 session-only mTLS transport
日期: 2026-08-18
状态: Accepted

## 背景

首阶段协商后，mTLS 连接必须保留 SSL 对象并通过密文读写。现有 RPC 同时存在裸 fd 连接接口和 session I/O；裸 fd 无法表达 SSL 所有权，导致 mTLS 业务路径失败或存在误用风险。

## 决策

RPC 内部连接和业务数据面统一使用 session transport。修改连接对象、业务函数接口及同仓调用点，移除 fd-only 业务数据面，不保留兼容包装。既有配置参数、首阶段协议和“默认明文/服务端启用即强制 mTLS”语义保持不变。

可维护性优先：不以宏、双轨状态、隐式适配层或特殊分支迁就旧调用方式；让接口类型直接表达 transport 和 SSL 所有权。

## 影响

- 优点：SSL 所有权、读写分派和 cleanup 有单一模型，mTLS 与明文共享业务路径。
- 代价：同仓 RPC 接口需要系统性调整，可能影响测试和调用方编译。
- 边界：不兼容旧协议；本 ADR 不扩展 SBT/UI/存储加密范围。
