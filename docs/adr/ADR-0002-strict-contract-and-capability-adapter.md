# ADR-0002: 严格任务合约与能力适配边界

日期: 2026-07-28
状态: Accepted

## 背景

PDCA 流程当前同时依赖自然语言门禁、松散 task.json 字段和具体 Agent 平台工具名。历史任务存在 phase、status、active、states 相互矛盾仍被校验通过的情况；`task()`、`pdca context` 等硬编码接口在当前环境不一定存在。继续兼容所有旧格式会扩大状态空间，也会掩盖数据错误。

## 候选方案

### A. 保留旧格式并逐步增加兼容分支

- 优点：历史任务无需清理。
- 缺点：验证器和每个调用方长期承担多版本分支；错误状态可能被兼容逻辑接受。

### B. 冻结严格新 schema，清理不合规历史任务

- 优点：单一状态模型、fail-closed、测试和推理成本更低。
- 缺点：需要清理历史任务目录；旧任务不能直接继续执行。

### C. 在流程正文中分别适配每个 Agent 平台

- 优点：短期接入直接。
- 缺点：核心流程累积平台条件分支，工具变化会扩散到所有 flow/skill。

### D. 核心只声明通用能力，由适配层解析

- 优点：流程与平台解耦；缺失可选能力时可统一降级。
- 缺点：需要能力描述、doctor 和适配接口。

## 决策

采用 B + D：

1. T0135 起冻结严格任务 schema，不为旧任务格式增加兼容分支。
2. 先验证 schema，再 dry-run 生成删除清单；保留 records、knowledge、journal，通过 Git 执行可恢复删除。
3. flow/skill 只声明通用能力及 fallback；当前任务只实现当前环境映射，不扩展为多平台 SDK。
4. 缺失必需能力时 fail-closed；缺失可选能力时执行显式降级，不得调用未定义工具。

## 影响

- 历史任务目录可能被清理，恢复依赖 Git。
- 状态转换、门禁和归档必须统一遵守 schema 与跨文件不变量。
- Agent 平台接入必须通过能力适配层，不得向核心流程新增平台专用分支。
- records、knowledge 和 journal 保持为受保护资产，不纳入历史任务清理。
