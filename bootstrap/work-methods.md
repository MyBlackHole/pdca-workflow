# 当前任务的专业方法导航

适用：Plan选择工作方法，或按已冻结方法在Do执行、Check核验、Act交付。不是新增权威、默认必读集或宿主工具配置；只展开CONTRACT/TEST/REVIEW/LEARN的当前动作。每个方向是同一任务内部的方法，不创建角色Agent、额外节点、确认或第四场景。按本次固定快照读取所选行及其引用，不通读无关领域。

## 先确定要证明什么

先按 [CONTRACT](../ontology/concept/pdca-execution-contract.md#contract-professional-plan)固定问题、事实/假设、目标/非目标与取舍，再按 [TEST](../ontology/concept/task-unit-test.md#test-professional-paths)把风险落到原AC/case。关键事实已经提供就直接引用；范围、安全或验收所需事实缺失时精确指出缺项，不反复追问、不编造事实。

下表是方法选择提示，不是完整领域标准。依据当前要求确定适用项；小变更也可能有高风险。不能因为未列某领域、历史无发现、没有专项Agent而跳过固定义务；超出已冻结范围按REWORK记录后继，不在Check暗加必需项。其他领域用同样的“路径—不变量—反例—观察”结构补足当前任务方法。

## 只展开适用的路径

| 触发事实 | 实际检查动作 | 能支持结论的观察与常见误判 |
|---|---|---|
| 新增状态、字段、接口或格式 | 从定义/生产者追到读写、允许列表、switch默认、序列化、持久化、恢复和展示等适用消费者；阅读授权范围内diff之外的调用代码，核对新旧版本组合 | 各消费者的位置与合法/非法/兼容案例；搜不到名字时查生成器/schema/宏，不把grep未命中当不存在 |
| 异步、共享可变状态、取消/重试 | 标出参与者、状态所有者、原子边界与完成点；列读—判—写、重复完成、取消与完成竞态、结果未知、重试去重、资源交回交错 | 固定调度/屏障、事件序列及最终状态/副作用次数；串行通过或“有锁”不证明保护了该路径，未知不等于失败可重试 |
| 存储、备份、提交或数据迁移 | 明确承诺的持久化边界；追踪数据/元数据/日志的实际顺序，核对局部写入、崩溃点、回放幂等、格式版本与回退前提 | 授权隔离环境的故障前后数据/状态与恢复结果；仅重启进程不等于模拟断电，校验和存在不证明事务或持久化正确；不在生产破坏性注入 |
| 外部输入、权限或不可信内容 | 固定实际攻击者/调用者权限和信任边界，追输入到使用点；核对上游约束、规范化、授权、输出和失败路径 | 可达触发及已查保护；危险语句不自动是漏洞，非恶意测试数据不验证攻击面；不扩大现有授权 |
| 性能、容量或资源成本目标 | 先固定操作/负载、指标与单位、环境、基线、重复测量策略和可接受误差；定位热点/等待/分配，再比较候选与正确性回归 | 同条件原始样本、波动及约束影响；没有基线只能报告当前测量，不宣称提升；代码更少或一次更快不等于有效优化 |
| 跨组件或用户端到端流程 | 从真实入口追到外部效果、错误可见性、重复提交、离开/超时、空/边界状态及清理；核对mock隐藏的边界和真实组合 | 同路径前后重现、返回值/状态/副作用和适用界面证据；只截图或仅组件存在不证明端到端结果，测试失败与被测正确拒绝分开 |
| 文档、源码研究或技术方案 | 固定来源/版本及问题，区分直接观察、推断和未验证建议；核对同一主体/前提在正文、图示、表格和案例中的含义；对替代方案说明取舍 | 逐主张位置、反证与缺口；不同版本不直接拼成矛盾，计划风险不写成已发生事故；纯研究不顺便修改源码或索取商业付费证据 |
| 重构、可维护性或简化 | 定位无独立价值的包装、重复平台能力、单实现抽象与死配置；给出替代并核对兼容性、观测能力和失败语义 | 等价范围及原回归；按 [REVIEW](../ontology/process/independent-work-review.md#review-professional-findings)将建议与违约分开，不为减行删测试、安全校验、错误/恢复义务 |

## 同一条结果链

Plan把选定风险及oracle放入原基线；Do保留复现—假设—区分实验—修复—原路径复验及全必需回归，仍受预算；Check按 [EVIDENCE](../ontology/concept/pdca-evidence.md#evidence-consumption)消费原始结果，按 [REVIEW](../ontology/process/independent-work-review.md#review-counterevidence)核验反证，不在冻结对象上自动修复；Act按 [LEARN](../ontology/concept/pdca-continuous-improvement.md#learn-bounded-experience)交付有适用条件的经验。所有阶段仍使用原任务绑定及两次真实确认。

最小书写例（示意，不是实测）：将“取消接口不抛异常”替换为对已确认取消语义的验证：若取消赢得终态，后到完成回调不得再次发布结果；若完成先发生，后续取消如何回应按原合同判断。用固定交错观察终态和副作用次数，而不是假设取消永远胜出。仍须运行本节点其他全部必需案例。
